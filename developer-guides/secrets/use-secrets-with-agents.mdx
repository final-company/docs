---
title: "Use secrets with agents"
description: "Give trusted agent automation access to credentials without exposing values in prompts or logs."
---

Agents often need credentials for provider APIs, deploy systems, internal services, or artifact stores. Store those values in Secrets, then inject them through trusted tooling or runtime configuration.

Do not paste secret values into agent prompts. Prompts, transcripts, logs, and tool output are the wrong place for long-lived credentials.

## Recommended pattern

1. Store the credential in Secrets.
2. Give the server or worker `secrets:read` access.
3. Read the value only when the runtime needs it.
4. Pass the value to the process as an environment variable or scoped tool configuration.
5. Avoid printing the value in logs, command output, or agent-visible messages.
6. Rotate the secret when the provider credential changes.

## Read a value at runtime

```bash
curl "https://api.final.ai/v1/secrets/github_token/value" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

The value read endpoint returns the current value. Use it as late as possible and keep it in memory only as long as the task needs it.

See [read a secret value](/api-references/secrets/read-value).

## Separate readers and writers

| Role | Permission |
| --- | --- |
| Runtime that injects credentials | `secrets:read` |
| Rotation job | `secrets:write` |
| Admin tooling that manages names and tags | `secrets:read` and `secrets:write` |

Use separate API keys for readers and writers when your automation can support it.

## Agent workflow examples

| Workflow | Secret use |
| --- | --- |
| GitHub automation | Inject `github_token` into a trusted tool that creates issues or reads metadata. |
| Deploy preview | Read `deploy.production.token` only inside the deploy worker. |
| Webhook processing | Use `webhook.signing_secret` to validate inbound events before creating agent work. |
| Agent Disk data source | Store object storage credentials outside the prompt and pass them through server-side setup. |

## Security guidance

Keep descriptions and tags useful, but never put the secret value in metadata.

If an agent can run shell commands, treat command output as potentially visible to the session. Mask or avoid commands that echo environment variables.
