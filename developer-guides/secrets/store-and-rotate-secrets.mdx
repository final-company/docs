---
title: "Store and rotate secrets"
description: "Create, read, rotate, tag, and delete secrets through the public API."
---

Store a secret when automation needs a sensitive value. Rotate the value when the credential changes but the logical purpose stays the same.

## Create a secret

```bash
curl -X POST "https://api.final.ai/v1/secrets" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "github_token",
    "value": "ghp_example",
    "description": "GitHub token for deploy automation",
    "tags": {
      "service": "deploy",
      "environment": "production"
    }
  }'
```

The response includes metadata, not the secret value.

See [create a secret](/api-references/secrets/create).

## Read metadata

```bash
curl "https://api.final.ai/v1/secrets" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Read one secret by UUID or name:

```bash
curl "https://api.final.ai/v1/secrets/github_token" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Metadata is safe to display in admin surfaces, audit views, or configuration screens when your own access rules allow it. It does not contain the secret value.

## Rotate a value

```bash
curl -X PUT "https://api.final.ai/v1/secrets/github_token/value" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "value": "ghp_rotated"
  }'
```

Prefer rotation over creating a new name when the consuming automation should keep using the same logical credential.

## Update tags and descriptions

```bash
curl -X PATCH "https://api.final.ai/v1/secrets/github_token" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "description": "Rotated GitHub token for deploy automation",
    "tags": {
      "service": "deploy",
      "environment": "production",
      "rotation": "manual"
    }
  }'
```

Common tags include `service`, `environment`, `owner`, `source`, and `rotation`.

## Delete a secret

```bash
curl -X DELETE "https://api.final.ai/v1/secrets/github_token" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Delete a secret only after every consumer has moved to another credential or no longer needs access.

## Naming guidance

Choose names that identify the consumer and purpose. Good names include `github_token`, `deploy.production.token`, and `slack.alerts.bot_token`.

Avoid names that expose the value or describe temporary implementation details.
