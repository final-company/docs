Final Computers run container images as persistent or ephemeral cloud machines. Use them for agent runtimes, sandboxes, build jobs, preview services, and workloads that need command execution, files, SSH, and HTTP access.

You can manage Computers with the public REST API, the `final-computer` CLI, or the TypeScript SDK.

## Core concepts

| Concept | Description |
| --- | --- |
| Computer | A cloud machine created from a container image. Each Computer has a name, region, resources, HTTP settings, and lifecycle state. |
| Private Computer | A Computer owned by one user. Create a private Computer by using a user-owned API key and omitting `teamId`. |
| Team-owned Computer | A Computer owned by a team. Create one by passing `teamId` as a `team_` ID when you create the Computer. |
| Image | The container image used to boot the Computer, such as `docker.io/library/ubuntu:24.04` or a private image. |
| Ephemeral Computer | A Computer that is deleted when it becomes idle instead of being paused. Use this for short-lived jobs and sandboxes. |
| Auto resume | A setting that lets retained Computers wake when accessed after being paused or shelved. |
| computer token | A scoped Computer credential you can create, list, and revoke from the public API. |
| SSH key | An OpenSSH public key registered to your user for SSH access to Computers in your organization. |

For raw API details, start with [create a Computer](/api-references/computers/computers/create) and [list Computers](/api-references/computers/computers/list).
