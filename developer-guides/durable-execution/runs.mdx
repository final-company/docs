---
title: "Runs and signals"
description: "Inspect, cancel, retry, and signal durable execution runs."
---

A run is one execution of a durable workflow. Runs move through these statuses:

| Status | Meaning |
| --- | --- |
| `queued` | The run is waiting for a worker lease. |
| `running` | A worker is executing the run. |
| `waiting` | The run is suspended on a sleep, event wait, or signal. |
| `completed` | The workflow returned a result. |
| `failed` | The workflow failed and has no retry remaining. |
| `cancelled` | The run was cancelled. |

## Trigger a workflow directly

Use direct triggers when you want to start one workflow without sending a normal event through the app trigger matcher:

```bash
curl -X POST "${FINAL_API_URL}/v1/durable-execution/apps/${FINAL_DURABLE_APP_ID}/workflows/send-receipt/runs" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "idempotencyKey": "manual-run-123",
    "event": {
      "name": "workflow.triggered",
      "data": {
        "invoiceId": "inv_123"
      }
    },
    "metadata": {
      "source": "manual"
    }
  }'
```

See [trigger a workflow run](/api-references/durable-execution/runs/trigger).

## Inspect a run

Use [get a run](/api-references/durable-execution/runs/get) to read the current status, result, error, attempt count, trigger event, and timestamps.

Use [list run history](/api-references/durable-execution/runs/history) to read ordered history events such as `queued`, `leased`, `step_completed`, `waiting`, `resumed`, `retry_scheduled`, `completed`, `failed`, and `cancelled`.

## Signal a waiting run

Signal a waiting run when an external system or human action has the data needed to continue:

```bash
curl -X POST "${FINAL_API_URL}/v1/durable-execution/apps/${FINAL_DURABLE_APP_ID}/runs/<run-id>/signals" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "stepId": "approval",
    "payload": {
      "approved": true,
      "approvedBy": "person@example.com"
    }
  }'
```

`stepId` is optional. Include it when the run has more than one waiting step.

See [signal a run](/api-references/durable-execution/runs/signal).

## Cancel or retry

Cancel a run that should not continue:

```bash
curl -X POST "${FINAL_API_URL}/v1/durable-execution/apps/${FINAL_DURABLE_APP_ID}/runs/<run-id>/cancel" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Retry a terminal run:

```bash
curl -X POST "${FINAL_API_URL}/v1/durable-execution/apps/${FINAL_DURABLE_APP_ID}/runs/<run-id>/retry" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

See [cancel a run](/api-references/durable-execution/runs/cancel) and [retry a run](/api-references/durable-execution/runs/retry).
