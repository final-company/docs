Final uses Git as its default version control system for agent and automation workflows. Use Git-compatible HTTPS remotes with short-lived scoped credentials, then manage pull requests, stacked changes, reviews, checks, and merge queues through Final.

Use this workflow when your product needs version-controlled code changes without asking every agent, job, or user to hold a long-lived provider credential. A repository can be cloned by standard Git clients, updated by automation, reviewed in Final, synchronized with GitHub, and protected by a merge queue.

## What you can build

| Use case | How version control helps |
| --- | --- |
| Agent-authored code changes | Let an agent clone a repository, push a branch, and open a pull request with a short-lived credential. |
| Small-review workflows | Split large changes into stacked pull requests that reviewers can inspect one step at a time. |
| Protected branch landing | Queue approved work and test the exact candidate SHA before it lands on `main`. |
| GitHub-connected workflows | Sync selected branches between Final Git and GitHub while keeping Final as the agent-facing control plane. |
| Version-controlled code storage | Create repositories and perform normal clone, fetch, push, and pull request operations from your own product. |

## Core concepts

| Concept | Description |
| --- | --- |
| Repository | A Git-backed repository with a `gsr_` ID and a default branch. |
| Git credential | A short-lived HTTPS username and password for clone, fetch, or push. |
| Pull request | A review object for one source branch targeting one branch. |
| Stack | A dependency chain of pull requests in the same repository and target branch. |
| Merge queue | A branch protection system that creates candidate commits and waits for required checks before landing work. |
| Check | A commit status or check run reported against a SHA. Merge queues require checks on the candidate SHA. |
| GitHub sync | A branch reconciliation process between selected Final Git branches and GitHub branches. |

## Typical agent flow

1. Create or select a Git-backed repository.
2. Mint a short-lived Git credential for the job.
3. Clone the repository with normal Git commands.
4. Make a branch and push changes.
5. Create a pull request, or create a stack when the work is easier to review in smaller pieces.
6. Report checks on the pull request or merge queue candidate SHA.
7. Land approved work through the merge queue when the target branch is protected.

For a first hands-on flow, start with [clone and work with a repository](/developer-guides/git/clone).
