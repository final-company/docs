Final Virtual Machines run container images as persistent or ephemeral cloud machines. Use them for agent runtimes, sandboxes, build jobs, preview services, and workloads that need command execution, files, SSH, and HTTP access.

You can manage VMs with the public REST API, the `final-vm` CLI, or the TypeScript SDK.

## Core concepts

| Concept | Description |
| --- | --- |
| VM | A cloud machine created from a container image. Each VM has a name, region, resources, HTTP settings, and lifecycle state. |
| Private VM | A VM owned by one user. Create a private VM by using a user-owned API key and omitting `teamId`. |
| Team-owned VM | A VM owned by a team. Create one by passing `teamId` when you create the VM. |
| Image | The container image used to boot the VM, such as `docker.io/library/ubuntu:24.04` or a private image. |
| Ephemeral VM | A VM that is deleted when it becomes idle instead of being paused. Use this for short-lived jobs and sandboxes. |
| Auto resume | A setting that lets retained VMs wake when accessed after being paused or shelved. |
| VM token | A scoped VM credential you can create, list, and revoke from the public API. |
| SSH key | An OpenSSH public key registered to your user for SSH access to VMs in your organization. |

For raw API details, start with [create a VM](/api-references/virtual-machines/vms/create) and [list VMs](/api-references/virtual-machines/vms/list).
