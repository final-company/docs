---
title: "Session lifecycle"
description: "Create Agent Workspaces, send messages, poll session state, and archive completed work."
---

A workspace is the durable container for agent work. A session is one agent conversation or run inside that workspace. Most integrations create a workspace, keep the returned IDs, and then drive the session with messages and state polling.

## Lifecycle

1. Create a workspace with a title, execution mode, and optional first message.
2. Store `workspace.id` and `session.id` with your product task.
3. Poll session state for progress and message cursors.
4. Fetch messages after the cursor changes.
5. Send follow-up messages when a user or automation needs to steer the work.
6. Stop the session if it should not continue.
7. Archive completed workspaces when they leave your active view.

## Create a workspace

```bash
curl -X POST "https://api.final.ai/v1/agent-workspaces" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: workspace-001" \
  -d '{
    "agentProfileId": "prof_123",
    "title": "Investigate failing tests",
    "repositoryId": "gsr_123",
    "executionMode": "cloud",
    "message": "Find the failing tests and propose a fix."
  }'
```

Use an `Idempotency-Key` when the request comes from a button click, webhook, or retrying job.

See [create an agent workspace](/api-references/agent-workspaces/workspaces/create).

## Send a follow-up message

```bash
curl -X POST "https://api.final.ai/v1/agent-workspaces/${WORKSPACE_ID}/sessions/${SESSION_ID}/messages" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "message": "Focus on the API client tests first."
  }'
```

Follow-up messages should be specific and observable. Ask the agent to inspect a file, answer a question, apply a bounded change, or summarize findings before continuing.

See [send a session message](/api-references/agent-workspaces/messages/send).

## Poll state and read messages

```bash
curl "https://api.final.ai/v1/agent-workspaces/${WORKSPACE_ID}/sessions/${SESSION_ID}/state" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Use `latestMessageCursor` from the state response to fetch new messages:

```bash
curl "https://api.final.ai/v1/agent-workspaces/${WORKSPACE_ID}/sessions/${SESSION_ID}/messages?cursor=${CURSOR}" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Store the last cursor you processed so your UI or background worker can fetch only new messages.

## Stop or archive work

```bash
curl -X POST "https://api.final.ai/v1/agent-workspaces/${WORKSPACE_ID}/sessions/${SESSION_ID}/stop" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Stop a session when a user cancels the task, the task is no longer valid, or your automation has found a blocking condition. Archive workspaces after the result is recorded elsewhere.
