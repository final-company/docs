---
title: "Delegated credentials"
description: "Mint, refresh, and revoke short-lived credentials for product protocols."
---

Delegated credentials are short-lived Final credentials for product-specific protocols. Use them when a client or worker needs Git, WebSockets, or Durable Execution worker access, but should not receive a long-lived Final API key.

Use a Final API key for REST API calls. Use a delegated credential only for the protocol it was minted for.

## Credential kinds

| Kind | Returned secret material | Use it for |
| --- | --- | --- |
| `git` | Git `username` and `password` | Clone, fetch, and push for one repository. |
| `websockets` | WebSockets `token`, `url`, and `jti` | Browser clients, service clients, and connected workers that use WebSockets. |
| `durable_worker` | Worker WebSocket token, queue metadata, and session metadata | Durable Execution SDK workers. The SDK mints and refreshes this credential for you. |

Delegated credentials include lifecycle fields:

| Field | Meaning |
| --- | --- |
| `id` | Credential ID with a `dc_` prefix. |
| `status` | `active`, `refreshing`, `revoked`, or `expired`. |
| `expiresAt` | Time when the credential stops working. |
| `refreshAfter` | Earliest time a refresh request can rotate it. |
| `refreshBefore` | Latest time a refresh request can rotate it. |

## Mint a Git credential

Use a user-owned API key with `repositories:read` for read access or `repositories:write` for write access.

```bash
repository_id="gsr_123"

curl -X POST "https://api.final.ai/v1/delegated-credentials" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "kind": "git",
  "grants": {
    "repositoryId": "${repository_id}",
    "access": "write"
  }
}
EOF
```

Use the returned `username` and `password` with the repository HTTPS remote. Do not use them as REST API bearer tokens.

## Mint a WebSockets credential

Use a user-owned or team-owned API key with `websockets:connect` and the permissions required by the requested grants.

```bash
CHANNEL_NAME="chat"

curl -X POST "https://api.final.ai/v1/delegated-credentials" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d @- <<EOF
{
  "kind": "websockets",
  "grants": {
    "clientId": "browser_1",
    "ttlMs": 600000,
    "channels": [
      {
        "name": "${CHANNEL_NAME}",
        "access": ["subscribe", "publish"]
      }
    ],
    "metadata": {
      "app": "customer-portal"
    }
  }
}
EOF
```

Channel, RPC, bridge, and work queue names are owner-local. Send names such as `chat` or `customer-jobs`. Do not prefix resource names with `user:` or `team:`.

## Refresh a credential

Refresh only during the window between `refreshAfter` and `refreshBefore`.

```bash
credential_id="dc_..."

curl -X POST "https://api.final.ai/v1/delegated-credentials/${credential_id}/refresh" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Refresh requests must use the same API key that created the credential. If you pass replacement `grants`, they must be narrower than or equivalent to the current grants.

## Revoke a credential

Revoke credentials when a client disconnects permanently, a worker shuts down, or you need to invalidate leaked secret material.

```bash
credential_id="dc_..."

curl -X POST "https://api.final.ai/v1/delegated-credentials/${credential_id}/revoke" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

For `websockets` and `durable_worker` credentials, revoke also invalidates the recorded session token.

## Restrict what keys can mint

API keys can include `kind` and `resourceRestrictions` so a key can mint only a specific class of delegated credentials.

| Restriction | Applies to | Example |
| --- | --- | --- |
| `audiences` | All delegated credentials | `["git"]`, `["websockets"]`, `["durable-execution"]` |
| `repositories` | `git` credentials | `["gsr_123"]` |
| `namespaces` | `durable_worker` credentials | `["billing"]` |
| `websocketsResources` | `websockets` credentials | `["channel:chat", "work:customer-jobs"]` |

Use `*` in a restriction list to allow every value for that restriction. An empty list denies every value.
