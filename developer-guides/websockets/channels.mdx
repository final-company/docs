---
title: "Channels"
description: "Use WebSockets channels to publish owner-scoped realtime events."
---

Channels are owner-local pub/sub streams for application events. Use them to push agent progress, task updates, chat messages, build logs, or product notifications to connected clients.

## Name channels after product objects

Good channel names map to objects your product already understands:

| Channel | Use |
| --- | --- |
| `agent-chat:chat_123` | Agent chat progress. |
| `run:run_123` | Durable workflow run updates. |
| `room:billing` | Shared product room or team space. |
| `repository:gsr_123` | Repository activity. |

Do not prefix resource names with `user:` or `team:`. Final derives the owner scope from the API key that minted the token.

## Subscribe from a client

After the socket opens, send an `auth` frame. After auth succeeds, subscribe to the channel:

```js
socket.send(JSON.stringify({
  type: "channel.subscribe",
  channel: "agent-chat:chat_123",
}));
```

Your token must include a `channels` grant for that channel with `subscribe` access.

## Publish from your server

```bash
curl -X POST "https://api.final.ai/v1/websockets/channels/agent-chat:chat_123/events" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "agent.status",
    "data": {
      "state": "running",
      "message": "Running tests"
    },
    "idempotencyKey": "status-001"
  }'
```

Use `idempotencyKey` when the publish is tied to a retried job, webhook, or database transaction.

See [publish a channel event](/api-references/websockets/channels/publish).

## Design guidance

Keep event names stable, such as `agent.status`, `message.created`, or `artifact.ready`. Put changing details in `data`.

Publish from your server when the event comes from trusted backend state. Let clients publish only when the client is the source of the event and the token has a narrow `publish` grant.
