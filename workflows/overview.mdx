An AI workflow is a TypeScript module that Final runs step by step. An agent writes it from your description, you review and edit it as a canvas (or as code), and Final runs it whenever its triggers fire: on a schedule, from a webhook, when an integration reports an event, or when an agent calls it as a tool.

```ts
import { defineWorkflow, onIntegrationEvent, z } from '@finalai/workflows';

export default defineWorkflow({
  name: 'Triage support email',
  input: z.object({ messageId: z.string() }),
  require: {
    integrations: {
      inbox: { description: 'Support inbox', tools: { allow: ['messages.get'] } },
      tracker: { description: 'Issue tracker', tools: { allow: ['issues.create'] } },
    },
  },
  triggers: [onIntegrationEvent('inbox', 'message.received')],
  async run({ input, step, integrations }) {
    const email = await step.call('read-email', integrations.inbox, 'messages.get', {
      id: input.messageId,
    });
    const triage = await step.ai('classify', {
      prompt: `Classify this support email:\n${JSON.stringify(email)}`,
      output: z.object({ severity: z.enum(['low', 'high']), summary: z.string() }),
    });
    if (triage.severity === 'high') {
      const decision = await step.approval('page-on-call', {
        title: `Page on-call: ${triage.summary}`,
      });
      if (decision?.approved !== true) return { paged: false };
    }
    return step.call('file-issue', integrations.tracker, 'issues.create', {
      title: triage.summary,
    });
  },
});
```

## Why code

- **One source of truth.** The canvas is generated from the code, and every canvas edit is a small code edit. Nothing on the canvas can drift from what runs.
- **Agents are good at it.** Any coding agent can write and change a workflow with Final's workflow tools, and the type checker and validator tell it what is wrong before you publish.
- **Durable by default.** Every step's result is recorded. A finished step never runs again, a run survives restarts and redeploys, and waits can last days.

## How it fits together

<Steps>
  <Step title="Describe it">
    Create a workflow in **Workflows** and ask your project's agent what it should do, or edit the code yourself. See [Build with agents](/workflows/build-with-agents).
  </Step>
  <Step title="Choose its integrations">
    In the workflow's **Settings**, pick which of your project's integrations fills each integration the workflow requires.
  </Step>
  <Step title="Test and publish">
    Test-run the draft, then publish it. Each publish is an immutable version; promote an older one to roll back. See [Runs and versions](/workflows/runs-and-versions).
  </Step>
  <Step title="Watch it run">
    Every run lists each step's input, output and attempts, and the transcript of any agent it ran. A run waiting on you shows the approval right there.
  </Step>
</Steps>
