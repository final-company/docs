Keep your current tracing backend and send to Final as well.

## You already run an OpenTelemetry SDK

Add `finalSpanProcessor` next to your existing span processors. It exports to Final in batches, and it makes this package's helpers (`setSession`, `tag`, `inject` and the rest) work with your provider.

```ts
import { NodeSDK } from '@opentelemetry/sdk-node';
import { finalSpanProcessor } from '@finalai/observability/node';

const sdk = new NodeSDK({
  spanProcessors: [
    ...yourSpanProcessors, // your existing backend, unchanged
    finalSpanProcessor({ apiKey: process.env.FINAL_INGEST_KEY! }),
  ],
});
sdk.start();
```

Set `deployment.environment.name` in your resource; `finalSpanProcessor` doesn't add one. `createFinalExporter({ apiKey, baseUrl })` gives you the exporter alone, for pipelines that build their own processors.

## You start with Final

Pass your other exporters to `init`. Every span goes to Final and to each of them:

```ts
import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-proto';
import { init } from '@finalai/observability/node';

init({
  environment: 'production',
  additionalExporters: [new OTLPTraceExporter({ url: 'https://otel.example.com/v1/traces' })],
});
```

`redact` applies to every exporter. A batch counts as failed if any exporter fails it. `combineExporters` and `redactingExporter` are exported for building the same behavior yourself.

## You run a Collector

Add Final as a second `otlphttp` exporter in the traces pipeline. See [the Collector config](/observability/quickstart-otlp#opentelemetry-collector).
