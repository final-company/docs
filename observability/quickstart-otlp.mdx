Final accepts standard OTLP/HTTP, so any OpenTelemetry SDK, the OpenTelemetry Collector, or a plain HTTP client can send traces without a Final package. Use this for Python, Go, Java and every other language.

| | |
| --- | --- |
| Endpoint | `https://api.final.ai/v1/observability/otlp` (exporters append `/v1/traces`) |
| Traces URL | `https://api.final.ai/v1/observability/otlp/v1/traces` |
| Auth | `Authorization: Bearer <ingest key>` |
| Encoding | Protobuf (`application/x-protobuf`) or JSON (`application/json`), optionally gzip |

Create an ingest key in your project's **Observability** settings first. The key decides the project; nothing in the payload can change it. See the [ingest contract](/observability/reference/ingest) for limits and status codes.

## Send one span with curl

```bash
NOW=$(date +%s)
curl -sS https://api.final.ai/v1/observability/otlp/v1/traces \
  -H "Authorization: Bearer $FINAL_INGEST_KEY" \
  -H 'content-type: application/json' \
  -d '{
  "resourceSpans": [{
    "resource": { "attributes": [
      { "key": "service.name", "value": { "stringValue": "support-bot" } },
      { "key": "deployment.environment.name", "value": { "stringValue": "development" } }
    ]},
    "scopeSpans": [{
      "scope": { "name": "curl" },
      "spans": [{
        "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
        "spanId": "00f067aa0ba902b7",
        "name": "answer",
        "kind": 1,
        "startTimeUnixNano": "'"${NOW}"'000000000",
        "endTimeUnixNano": "'"$((NOW + 2))"'000000000",
        "attributes": [
          { "key": "final.span_kind", "value": { "stringValue": "agent" } },
          { "key": "final.session_id", "value": { "stringValue": "conv_1" } },
          { "key": "final.input", "value": { "stringValue": "What is OpenTelemetry?" } },
          { "key": "final.output", "value": { "stringValue": "An open standard for telemetry." } }
        ],
        "status": { "code": 1 }
      }]
    }]
  }]
}'
```

A `200` response (`{}`, or a `partialSuccess` object when some spans were rejected) means Final stored the batch durably. See [partial success](/observability/reference/ingest#partial-success).

## Python and other OpenTelemetry SDKs

Point the SDK's OTLP/HTTP exporter at Final with the standard environment variables. Values in `OTEL_EXPORTER_OTLP_HEADERS` are URL-encoded, so the space after `Bearer` is `%20`.

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=https://api.final.ai/v1/observability/otlp
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer%20${FINAL_INGEST_KEY}"
export OTEL_RESOURCE_ATTRIBUTES="service.name=support-bot,deployment.environment.name=production"
```

In Python, install the SDK and the HTTP exporter, then create a tracer provider. The exporter reads the variables above.

```bash
pip install opentelemetry-sdk opentelemetry-exporter-otlp-proto-http
```

```python
from opentelemetry import trace
from opentelemetry.exporter.otlp.proto.http.trace_exporter import OTLPSpanExporter
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor

provider = TracerProvider()
provider.add_span_processor(BatchSpanProcessor(OTLPSpanExporter()))
trace.set_tracer_provider(provider)

tracer = trace.get_tracer("support-bot")

with tracer.start_as_current_span("answer") as span:
    span.set_attribute("final.span_kind", "agent")
    span.set_attribute("final.session_id", "conv_1")
    span.set_attribute("final.input", "What is OpenTelemetry?")
    span.set_attribute("final.output", "An open standard for telemetry.")

provider.shutdown()  # flush before the process exits
```

Final also reads OpenTelemetry GenAI semantic conventions and OpenInference, so instrumentation libraries that emit those (for OpenAI, Anthropic, LangChain and others) work without `final.*` attributes. Add `final.*` attributes for what they don't cover, such as the session or customer. See [attribute keys](/observability/reference/attributes).

To set only the traces URL, use `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT=https://api.final.ai/v1/observability/otlp/v1/traces` and `OTEL_EXPORTER_OTLP_TRACES_HEADERS` instead. Signal-specific endpoints are used as given; nothing is appended.

## OpenTelemetry Collector

Add an `otlphttp` exporter for Final to your traces pipeline. Keep your existing exporters to send to both.

```yaml otel-collector.yaml
receivers:
  otlp:
    protocols:
      grpc:
      http:

processors:
  batch:

exporters:
  otlphttp/final:
    endpoint: https://api.final.ai/v1/observability/otlp
    headers:
      authorization: "Bearer ${env:FINAL_INGEST_KEY}"
    compression: gzip

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [otlphttp/final]
```

Set `deployment.environment.name` in your apps, or add it in the Collector with a `resource` processor.

## What Final needs from your spans

- **One root per trace**, ended. Evaluation starts when the root ends; see [root finalization](/observability/reference/ingest#root-finalization).
- **`final.session_id` on the root span** to group traces into sessions. Final reads it from the root only.
- **Input and output** on the root (`final.input`, `final.output`, or GenAI and OpenInference equivalents).
- **Model, usage and cost** on model calls. Leave cost out when you don't know it; never send `0`.

[Trace health](/observability/reference/trace-health) checks each of these and tells you what to fix.
