---
title: "Error codes"
description: "API error codes, SDK client error codes and final-obs exit codes."
---

Failed API requests return a JSON body with a code and a message:

```json
{ "error": { "code": "forbidden", "message": "missing observability:write permission" } }
```

API responses also carry `details`: extra information such as validation issues, or `null`. The SDK client throws `ObservabilityApiError` (check with `isObservabilityApiError`) with `status`, `code`, `message`, `details`, `operation` and `requestId`. Include the request ID when you contact Final.

## Server codes

| Code | Status | Meaning |
| --- | --- | --- |
| `invalid_request` | 400 | The input failed validation, or the SQL isn't a single read-only statement over the [catalog](/observability/reference/sql#queries). |
| `unauthorized` | 401 | Missing, invalid or expired credentials. |
| `forbidden` | 403 | The key lacks the operation's scope, or your role doesn't allow it. Ingest keys get this for everything but ingest. |
| `not_found` | 404 | No such object in this project. |
| `conflict` | 409 | A stale `revision` (dashboards), or a name already taken. Re-read and retry. |
| `spend_cap_reached` | 402 | The project reached its monthly cap. Ingest is refused and evaluations are skipped. |
| `payload_too_large` | 413 | Over an [ingest limit](/observability/reference/ingest#limits). |
| `rate_limited` | 429 | Too many requests. Retry with backoff. |
| `query_rate_limited` | 429 | Too many SQL queries. See [SQL limits](/observability/reference/sql#limits). |
| `query_memory_limit` | 422 | The SQL query used too much memory. |
| `query_timeout` | 504 | The SQL query ran too long. |
| `unavailable` | 503 | A dependency is temporarily unavailable. Retry with backoff. |

Invalid input is rejected before anything runs: requests are strict, so unknown fields and wrong types are errors rather than being ignored. Other codes may appear; treat unknown codes by their HTTP status.

## Client codes

The SDK client raises these itself:

| Code | Status | Meaning |
| --- | --- | --- |
| `invalid_request` | 0 | The input failed the operation's schema; nothing was sent. |
| `network_error` | 0 | No response arrived. |
| `invalid_response` | | The response didn't match the expected shape. |
| `request_failed` | The HTTP status | A failed response without a JSON error body, such as one from a proxy. The message includes the start of the body. |

## Evaluation statuses

Evaluations don't fail requests; their outcome is a status on the result. See [results](/observability/judges#results).

## CLI exit codes

`final-obs` exits `0` on success, `1` when tests fail or regress (or, for other commands, when a request fails), and `2` when it couldn't complete. See [tests in CI](/observability/tests-in-ci#exit-codes).
