`sql_query` runs ClickHouse SQL over a versioned catalog of views scoped to your project. `discover_schema` returns the catalog's version, its tables and every column with a description.

## Catalog

| Area | Tables |
| --- | --- |
| Telemetry | `traces`, `spans`, `observations`, `conversation_items`, `trace_tags`, `trace_health`, `model_usage` |
| Evaluation | `scores`, `judge_reviews`, `judges`, `labels` |
| Product objects | `issues`, `issue_evidence`, `datasets`, `examples`, `test_runs`, `test_results` |

Judges, labels, issues, datasets and test runs are configured in Final's control plane and copied into the catalog, so SQL can join them with telemetry. Use `discover_schema` for exact column names rather than guessing.

You only see your project's rows. Isolation is enforced by the database, not by rewriting your query: joins, subqueries and unions can't reach other projects. Deleted traces disappear from every table as soon as deletion is requested.

## Queries

- One statement: `SELECT` or `WITH`. Anything else is rejected before it runs.
- `{start_time}` and `{end_time}` are replaced with the request's `from` and `to`; dashboards fill them from their time range.
- `environment` limits the query to one environment.

The result has the columns with their types, the rows, `truncated` (true when a row or byte cap was hit), `elapsedMs` and `bytesRead`.

## Limits

| Limit | Value |
| --- | --- |
| Time | 30 seconds |
| Memory | 2 GiB |
| Result | 10,000 rows or 25 MiB |
| Rate | Burst of 40, then 4 queries per second per project |

| Error | Cause |
| --- | --- |
| `query_rate_limited` | Over the rate. Retry after a pause. |
| `query_memory_limit` | The query needed more than 2 GiB. Aggregate earlier or narrow the time range. |
| `query_timeout` | The query ran past 30 seconds. Narrow the time range or filter on indexed columns such as time and environment. |
