Observability publishes lifecycle events to a per-project feed. Read the feed, deliver it to webhooks, or start workflows from it. `LifecycleEventKind` in `@finalai/observability/contract` has every kind.

## Kinds

| Kind | When |
| --- | --- |
| `observability.judge.matched` | An online result from a judge's production version matched. Fires on every match, whether or not an action group fires. |
| `observability.judge.version_promoted` | A judge version became the production version. |
| `observability.evaluation.failed` | An evaluation ended in an error or timeout. |
| `observability.issue.created` | An issue was opened. |
| `observability.issue.updated` | An issue's status, severity or content changed. |
| `observability.issue.regressed` | A monitored or inactive issue was seen again. |
| `observability.issue.resolved` | A monitored issue's label stayed at zero for the stale window. |
| `observability.test_run.completed` | A test run finished. |
| `observability.dataset.version_created` | A dataset changed. |
| `observability.usage.threshold_crossed` | A usage alert threshold was crossed. |
| `observability.ingest.rejected` | Telemetry was rejected. |
| `observability.deletion.completed` | A deletion request finished purging. |

Each event has `eventId`, `kind`, `occurredAt` and `data`.

## Read the feed

```bash
curl -sS "https://api.final.ai/v1/observability/projects/$FINAL_PROJECT_ID/events?kinds=observability.issue.created&limit=50" \
  -H "Authorization: Bearer $FINAL_API_KEY"
```

`list_events` returns events in order, filtered by `kinds` and time, with `nextCursor` for the next page. It needs `observability:read`.

## Webhooks

Create a subscription with an HTTPS URL and the kinds to deliver. The response includes a signing secret, shown once:

```ts
import { LifecycleEventKind } from '@finalai/observability/contract';

const subscription = await project.admin.createEventSubscription({
  url: 'https://hooks.example.com/final',
  kinds: [LifecycleEventKind.IssueCreated, LifecycleEventKind.IssueRegressed],
  description: 'Incident tooling',
});
// subscription.signingSecret is shown only here: store it now.
```

Deliveries are signed per [Standard Webhooks](https://www.standardwebhooks.com/), like the [agent event feed](/operate/events#receive-webhooks): verify with `verifyWebhook` from `@finalai/agents/webhooks` or any Standard Webhooks library before trusting a delivery, and pass the body exactly as received.

| Operation | What it does |
| --- | --- |
| `update_event_subscription` | Change the URL, kinds or description, or pause with `paused: true`. |
| `replay_events` | Redeliver past events in a time range to a subscription. |
| `delete_event_subscription` | Stop delivering. |
| `list_event_subscriptions` | List subscriptions with their status: `active`, `paused` or `failing`. |

## Workflows

To run a workflow when a judge matches, use a [`start_workflow` action](/observability/judge-actions#targets). Lifecycle events also reach your project's workflows as events, so a workflow with `onEvent('observability.issue.created')` starts on every new issue. See [workflow triggers](/workflows/triggers).

There is no email channel. To email someone about an event, start a workflow that sends the email.
