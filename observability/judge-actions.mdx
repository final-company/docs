When an online result matches, a judge can start a workflow, notify people, post to Slack, add the trace to a dataset, or run another judge. Actions are events: every match publishes `observability.judge.matched` to the project's [event feed](/observability/reference/events), and action groups decide what else happens. There is no email action; to send email, start a [workflow](/workflows/overview) that sends it.

Only online results from a judge's production version fire actions. Backfills, manual runs, test runs and rescoring never do.

## Action groups

Action groups belong to a judge version, like run settings. Set them on the draft, then publish and promote.

```ts
import { ActionTargetKind } from '@finalai/observability/contract';

await project.judges.setJudgeActionGroups({
  judgeId,
  actionGroups: [
    {
      name: 'Unsupported claims in production',
      labelIds: [unsupportedLabelId],
      environments: ['production'],
      frequency: { count: 5, windowSeconds: 600 },
      cooldownSeconds: 3600,
      targets: [
        { kind: ActionTargetKind.Slack, slackChannel: '#agent-quality' },
        { kind: ActionTargetKind.AddToDataset, datasetId },
        { kind: ActionTargetKind.StartWorkflow, workflowId },
      ],
    },
  ],
});
```

| Field | What it does |
| --- | --- |
| `labelIds` | Results with one of these labels fire the group. Empty matches every result. |
| `environments` | Fire only for traces from these environments. |
| `frequency` | Fire when `count` matches happen within `windowSeconds`. Default: 1 match in 1 minute. |
| `cooldownSeconds` | After firing, wait this long before firing again. Default: 0. |
| `targets` | 1 to 20 targets. A judge has up to 20 groups. |

## Targets

| Kind | What it does |
| --- | --- |
| `start_workflow` | Starts a published [AI workflow](/workflows/overview) (`workflowId`) with the event as its input. |
| `notify` | Sends a notification in Final to project `roles` or `memberIds`. |
| `slack` | Posts through the project's Slack connection, to `slackChannel` or the project's default channel. |
| `add_to_dataset` | Adds the trace to `datasetId`, with an optional `fieldMapping` from trace or session fields to dataset columns. |
| `run_judge` | Runs another judge's production version (without its run settings) on the same target. Chains reject cycles when you publish and go at most 5 deep. |

To reach other systems, subscribe a webhook to `observability.judge.matched` instead; see [lifecycle events](/observability/reference/events).

## Delivery history

`list_action_deliveries` lists each delivery with its status (`pending`, `delivered`, `failed` or `skipped`), attempts and last error. Filter by judge, status, target kind and time. Each delivery is idempotent: a retry never posts or starts twice.
