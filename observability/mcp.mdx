Every Observability operation is a Final MCP tool. Connect Claude Code, Codex, Cursor or any MCP client to Final, and your coding agent can search traces, read spans, write judges, run tests and fix issues in the same session where it edits your code.

## Connect a coding agent

Observability tools come through the same server as the rest of Final's MCP gateway:

```text
https://api.final.ai/v1/connectors/mcp
```

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http --scope user final https://api.final.ai/v1/connectors/mcp
    ```

    Start Claude Code, run `/mcp`, select **final** and sign in.
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add final --url https://api.final.ai/v1/connectors/mcp
    codex mcp login final
    ```
  </Tab>
  <Tab title="Cursor">
    ```json ~/.cursor/mcp.json
    {
      "mcpServers": {
        "final": {
          "url": "https://api.final.ai/v1/connectors/mcp"
        }
      }
    }
    ```

    Then sign in from Cursor's MCP server list.
  </Tab>
</Tabs>

You sign in with your Final account; no API key is needed. If you already added Final for the [MCP gateway](/mcp-gateway/quickstart), there is nothing more to set up. See that quickstart for other clients.

Then ask:

```text
Using Final, find yesterday's production traces in project prj_your_project where the
"Grounded answer" judge returned "Unsupported claim", and show me the span that caused it.
```

## How agents find the tools

Your client doesn't load 180 tools. It sees Final's discovery tools and searches for what it needs: `search_tools` finds a tool, `describe_tools` returns its exact input schema, and `call_tool` runs it. Observability tools have catalog paths like `final.observability.traces.search_traces`. Agents running on Final find them the same way, through tool search.

Every tool takes `projectId`. Agents running in a Final session are confined to their own project and its sub-projects.

## Tool groups

| Group | Covers |
| --- | --- |
| `final.observability.traces` | Traces, sessions, conversations, saved views, trace health, mappers and display rules. |
| `final.observability.judges` | Judges and versions, run settings, actions, labels, evaluations and external results. |
| `final.observability.alignment` | Review sessions, reviews, alignment summaries and golden datasets. |
| `final.observability.data` | Datasets, examples and prompts. |
| `final.observability.tests` | Test suites, cases, runs and comparisons. |
| `final.observability.issues` | Issues, evidence, monitoring, fix handoffs and detection. |
| `final.observability.analytics` | SQL, saved queries, dashboards and charts. |
| `final.observability.admin` | Settings, ingest keys, usage and limits, deletion, events, audit, the data plane, scheduled analysis and knowledge. |

The [tool reference](/observability/mcp-tools) lists every tool with its scope and effect.

## Permissions and approvals

Tools act with your project role. Read tools run without asking. Tools that write, execute or delete ask for approval when an agent session calls them: Final shows an approval card with the tool's title and the exact input, and runs exactly what you approved. See [accounts and approvals](/mcp-gateway/accounts-and-approvals).

## Useful prompts for coding agents

- "Run `get_trace_health_summary` for the last 24 hours and fix the instrumentation for every failing check." Each failing check includes a fix prompt written for coding agents.
- "Read the open issues with `list_issues`, pick the most severe, and fix it in this repository. Cite the traces you used."
- "Create a test suite from the failing traces of issue `iss_…` and run it against this branch."
