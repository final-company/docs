title: "Tracing patterns"
---

How to shape traces for the ways agents actually run. Every helper here is exported from both `@finalai/observability/node` and `@finalai/observability/workers`.

| Helper | What it does |
| --- | --- |
| `observe(fn, options)` | Wraps a function so every call is a span, with arguments as input and the result as output. |
| `span(name, fn, options)` | Runs `fn` in a new active span that ends when `fn` returns, settles or finishes streaming. |
| `startActiveSpan(name, fn, options)` | Like `span`, but you end it with `span.end()`. |
| `startLinkedTrace(name, fn, options)` | Runs `fn` as the root of a new trace linked to the current one. |
| `inject(carrier)` | Writes `traceparent` and `final.*` baggage into headers for an outgoing call. |
| `continueTrace(carrier, fn)` | Runs `fn` as a continuation of the trace in `carrier`. |

`observe`, `span` and `startActiveSpan` take `kind` (a `SpanKind`), `attributes`, `startTime` (epoch milliseconds, for spans recorded after the fact), `root: true` to start an unlinked trace, and `fork: true` to start a linked one. `observe` also takes `name`, `recordInput` and `recordOutput`.

## Streaming

`observe` on an async generator keeps the span open until the stream finishes, and records the chunks as output: joined into one string when every chunk is a string, otherwise as a list (up to 1,000 chunks). An error or early `return()` ends the span too.

```ts
import { SpanKind, observe } from '@finalai/observability/node';

export const streamAnswer = observe(
  async function* (question: string) {
    for await (const token of model.stream(question)) yield token;
  },
  { name: 'stream answer', kind: SpanKind.Generator },
);
```

The OpenAI, Anthropic and AI SDK integrations record streamed model calls the same way.

## Distributed services

Send the trace context with outgoing requests, and continue it on the receiving side. Trace-level attributes (session, customer, user, agent version, tags) travel with it as W3C baggage, and only `final.*` keys are read back.

```ts
import { continueTrace, inject } from '@finalai/observability/node';

// Caller
await fetch('https://tools.internal/search', { method: 'POST', headers: inject({}), body });

// Receiver
export const handle = (request: Request) => continueTrace(request.headers, () => search(request));
```

Any W3C Trace Context client works on either side.

## Queues and background workers

Store the carrier with the message, and continue the trace when a worker picks it up:

```ts
import { continueTrace, inject, span } from '@finalai/observability/node';

await queue.send({ payload, trace: inject({}) });

worker.on('message', (message) =>
  continueTrace(message.trace, () => span('process message', () => process(message.payload))),
);
```

If the job runs long after the request that queued it, start a linked trace instead so the request's trace stays short; see [long gaps](#human-approval-and-other-long-gaps).

## Workflow engines

Make the run the root span and each step a child. While the run executes in one process, nesting follows `await`:

```ts
import { SpanKind, span } from '@finalai/observability/node';

await span(
  'order workflow',
  async () => {
    const order = await span('load order', () => loadOrder(orderId));
    await span('charge card', () => charge(order), { kind: SpanKind.Tool });
    await span('send receipt', () => sendReceipt(order), { kind: SpanKind.Tool });
  },
  { kind: SpanKind.Agent },
);
```

Durable engines that pause a run for hours or days, or resume it in another process, should end the trace at the pause and start a linked trace when the run resumes, as below.

## Human approval and other long gaps

Evaluation starts when a trace's root ends, and a trace left open for days is never evaluated. When work waits for a person, end the trace at the wait and start a linked trace when it resumes:

```ts
import { TraceLinkRelation, continueTrace, inject, span, startLinkedTrace } from '@finalai/observability/node';

// Before waiting: save the context with the pending approval, then let the trace end.
await span('draft refund', async () => {
  const draft = await draftRefund();
  await approvals.save({ draft, trace: inject({}) });
});

// After approval, possibly in another process:
continueTrace(approval.trace, () =>
  startLinkedTrace('issue refund', () => issueRefund(approval.draft), {
    relation: TraceLinkRelation.Continuation,
  }),
);
```

The new trace's root carries `final.link.trace_id`, `final.link.span_id` and `final.link.relation`, and the trace view links the two. The session and other propagated attributes carry over through the saved baggage.

## Subagents and forks

Run a subagent as its own trace, linked to the span that started it. Each trace stays small enough to read and evaluate, and judges can score the subagent on its own.

```ts
import { TraceLinkRelation, observe, startLinkedTrace } from '@finalai/observability/node';

await startLinkedTrace('research subagent', () => runResearch(topic), {
  relation: TraceLinkRelation.Subagent,
});

// Or for every call of a function:
const research = observe(runResearch, { fork: true, relation: TraceLinkRelation.Subagent });
await research(topic);
```

The relation is `fork` by default; use `subagent` or `continuation` to say what the link means. The parent span records a `final.linked_trace` event pointing to the new trace.

## Serverless

Functions can be frozen as soon as they return. Use `instrumentWorker` on Cloudflare Workers, or call `await forceFlush()` before returning elsewhere. See [Workers and serverless](/observability/quickstart-workers).

## Spans recorded after the fact

When you only learn about work once it's done, such as an event from another system, pass `startTime` and end the span yourself:

```ts
import { SpanKind, startActiveSpan } from '@finalai/observability/node';

startActiveSpan('vendor call', (span) => span.end(event.finishedAt), {
  kind: SpanKind.Tool,
  startTime: event.startedAt,
});
```

To add whole conversations after the fact, without spans, use [observations](/observability/reference/observations).
