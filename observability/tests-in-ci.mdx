---
title: "Tests in CI"
description: "Run a test suite from CI with final-obs, write JUnit and Markdown reports, and fail on regressions."
---

`final-obs test run` starts a [test suite](/observability/tests) run, waits for it, writes reports and exits with a code your CI understands.

```bash
npx final-obs test run --suite ts_your_suite --candidate "$GITHUB_SHA" --fail-on regressed \
  --junit results.xml --markdown summary.md
```

It needs `FINAL_API_KEY` (an API key with `observability:read` and `observability:execute`) and `FINAL_PROJECT_ID`, or `--project`. `FINAL_API_URL` defaults to `https://api.final.ai`.

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The run passed. |
| `1` | Cases failed, or with `--fail-on regressed`, cases regressed against the baseline. |
| `2` | The run couldn't complete: bad usage, an API or runner error, a timeout, or a run that ended `failed` or `cancelled`. |

## Options

| Flag | Default | What it does |
| --- | --- | --- |
| `--suite <id>` | Required | The test suite. |
| `--version <n>` | Latest published | The suite version. |
| `--candidate <label>` | | What is under test, such as a commit SHA. |
| `--mode <mode>` | `external` with a runner command, else `stored_traces` | `external`, `stored_traces` or `native`. |
| `--agent <id>`, `--workflow <id>` | | The candidate for `native` runs. |
| `--revision <rev>` | | The agent or workflow revision for `native` runs. |
| `--repeats <n>` | 1 | Run each case `n` times, to find flaky cases. |
| `--fail-on <mode>` | `failed` | `failed` fails on any failing case; `regressed` fails only on regressions against the baseline. |
| `--baseline <run id>` | The previous completed run of the suite | The run to compare with for `--fail-on regressed`. |
| `--junit <path>` | | Write a JUnit XML report. |
| `--markdown <path>` | | Write a Markdown summary. It is also printed. |
| `--timeout <seconds>` | 1800 | How long to wait for the run. |
| `-- <command>` | | Your runner, for `external` runs. |

With `--fail-on regressed` and no earlier completed run, it fails on failures instead. Runs started in CI (when `CI` is set) are recorded with trigger `ci`.

## External runner

Put your runner after `--`. It runs with `FINAL_TEST_RUN_ID`, `FINAL_TEST_SUITE_ID` and `FINAL_PROJECT_ID` set, and links each case with [`testCase`](/observability/tests#external-runs). If it exits non-zero, the run is cancelled and the command exits `2`.

```bash
npx final-obs test run --suite ts_your_suite --candidate "$GITHUB_SHA" -- npx tsx scripts/run-cases.ts
```

## GitHub Actions

```yaml .github/workflows/agent-tests.yml
name: Agent tests
on: pull_request

jobs:
  agent-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with:
          node-version: 26
      - run: npm ci
      - name: Run the suite
        run: >
          npx final-obs test run --suite ${{ vars.FINAL_SUITE_ID }}
          --candidate ${{ github.sha }} --fail-on regressed
          --junit results.xml --markdown summary.md
          -- npx tsx scripts/run-cases.ts
        env:
          FINAL_API_KEY: ${{ secrets.FINAL_API_KEY }}
          FINAL_PROJECT_ID: ${{ vars.FINAL_PROJECT_ID }}
      - name: Summary
        if: always()
        run: cat summary.md >> "$GITHUB_STEP_SUMMARY"
```

The key needs `observability:read` and `observability:execute`. If your runner sends traces with the same key, add `observability:ingest`. For Final agents, replace the runner with `--mode native --agent <id>`.
