`@finalai/agents` contains three things: helpers for defining agents, a client for starting and talking to them, and the `final-agents` CLI. Install it with `npm install @finalai/agents zod`. It requires Node.js 26 or later for the CLI and local compute; the authoring helpers and client also run in browsers, React Native, and Workers. Full signatures are in the package's TypeScript declarations.

## Client

`createClient({ auth, localCompute?, host? })` returns a client. `auth` is `{ apiKey }`, `{ bearer }` for a signed-in person, or `{ cookies: true }` in a browser. `localCompute: false` stops the client from serving agents' files and shell from its own process; see [where code and compute run](/build/where-code-runs).

`client.project({ id })` returns a project client. Everything is created through it:

| Property | What it does |
| --- | --- |
| `sessions` | `create({ agent, provide, id?, actor?, message?, output? })` starts a session; `attach(id)` returns a handle by ID. A handle sends messages, streams events, lists and answers decisions, reads `requirements()` and `provide()`, and cancels or closes. See [sessions](/client/sessions). |
| `conversations` | `create` and `direct` take `provide`; `findDirect` looks up without creating. A handle's `addParticipant` and `participants.provide` set each agent's settings, and it has `inputs`, `context`, `labels`, and schedules. See [conversations](/client/conversations). |
| `agents` | `publish({ agent, name, visibility? })`, `get({ name } \| { id } \| { hash })`, `history({ name })`, `list()`, `store({ agent })`, and `parse(json)`. See [publishing](/operate/publishing). |
| `sandboxes` | `create(environment, { setup?, ownedBy?, idempotencyKey? })`, `get`, `list`, and `providers()`. A handle runs commands, reads its `description()`, and deletes the sandbox. |
| `sandboxSetups` | `publish({ name, setup })`, `get`, and `list`. See [sandbox setups](/build/sandbox-setups). |
| `sandboxProviders` | `register({ name, url })`, `list`, `get`, `update`, `refresh`, and `remove` for providers you run. See [run your own provider](/build/sandboxes#run-your-own-provider). |
| `integrations` | `create`, `get`, `list`, `update`, `delete`, and a person's `signIn`, `completeSignIn`, and `signOut`. `listTools` and `callTool` use an integration's tools without a session. See [integrations](/build/integrations). |
| `decisions` | `raise`, `list`, `get`, `respond`, and `cancel` for decisions outside any conversation. See [decisions](/client/decisions). |
| `harnesses` | `check({ agent, harness })`, `publish({ harness, name })`, `get`, `list`, and `allowances`. See [harness settings](/harnesses/settings). |
| `acpAdapters` | `publish({ adapter, name })`, `get`, and `list`. See [harnesses and adapters](/harnesses/overview). |
| `channels` | `publish({ name, source })`, `get`, `install({ channel, agent, app?, agents: { provide } })`, and `installs()`. See [channels](/build/channels). |
| `channelApps` | `create`, `list`, `update`, and `delete` for provider app credentials. |
| `schedules` | `list()` every schedule in the project's conversations. See [schedules](/build/schedules). |
| `events`, `eventSubscriptions` | The project's event feed and webhooks. See [events and webhooks](/operate/events). |
| `publisher`, `publicNames` | Claim a publisher handle and make names public. See [make a name public](/operate/publishing#make-a-name-public). |

The client itself also has:

| Property | What it does |
| --- | --- |
| `sessions` | `attach`, `get`, and `fork` for existing sessions by ID. |
| `conversations` | The signed-in person's conversations: `list`, `get`, `search`, and `decisions`. |
| `channelBindings`, `channelTickets` | Channel installs by ID, and the tickets an installer's link and connect pages complete. |
| `agents` | `list` the agents the caller can use, and `get({ id })` one in whichever project owns it. |
| `publishers` | `get(handle)` reads a publisher's public agents, harnesses, adapters, and channels. |
| `organization` | Model credentials and their grants, budgets, and spending restrictions. See [subscriptions and keys](/harnesses/settings#subscriptions-and-keys). |
| `inference` | `offering()` lists the models Final's metered inference serves, with prices. |
| `events` | The event feed across everything the caller can see. |
| `projects` | List and create projects. |
| `people` | List your organization's members, for adding people to conversations. |
| `close()` | End the client's open streams and local connections. |

## CLI

Run the CLI with `npx final-agents <command>`. `npx final-agents --help` lists every option.

### `print <module>`

Writes the document of the agent, harness, or ACP adapter the module exports, as JSON. Calls nothing.

```bash
npx final-agents print ./agent.ts
```

### `publish <module> --name <name>`

Stores the document and points `<name>` at it in a project: `project.agents.publish` for an agent, `project.harnesses.publish` for a harness, `project.acpAdapters.publish` for an adapter. See [publishing](/operate/publishing).

```bash
npx final-agents publish ./agent.ts --name release-assistant
```

### `conformance <module>`

Runs the harness conformance kit against a harness implementation the module exports. See [test conformance](/harnesses/overview#test-conformance).

```bash
npx final-agents conformance ./my-harness.ts --profile final-required
```

### Options

<ParamField path="--export" type="string">
  The export to use. `print` and `publish` find the agent, harness, or adapter by themselves when the module exports one; `conformance` defaults to `default`.
</ParamField>

<ParamField path="--name" type="string">
  `publish` only: the name to point at the document.
</ParamField>

<ParamField path="--project" type="string">
  `publish` only: the project. Overrides `FINAL_PROJECT_ID`.
</ParamField>

<ParamField path="--host" type="URL" default="https://agent-session.final.ai">
  The agents API to use. Overrides `FINAL_API_HOST`.
</ParamField>

<ParamField path="--profile" type="'final' | 'final-required' | 'plain-acp-v2'" default="final">
  `conformance` only: which checks to run. Use `final-required` for ACP adapters.
</ParamField>

<ParamField path="--timeout" type="number">
  `conformance` only: the per-case timeout, in milliseconds.
</ParamField>

<ParamField path="--json" type="boolean">
  `conformance` only: print the report as JSON.
</ParamField>

## Environment variables

| Variable | Used by | What it does |
| --- | --- | --- |
| `FINAL_API_KEY` | `publish` | Your [API key](/api-keys). |
| `FINAL_PROJECT_ID` | `publish` | The project to publish in. |
| `FINAL_API_HOST` | `publish` | The agents API to use, if not the default. |

`print` needs none of them. The client doesn't read environment variables; pass the key and project to `createClient` and `client.project`.
