Final Cloud endpoints are mounted under:

```text
https://api.final.ai/v1/final-cloud
```

Use a Final API key:

```bash
Authorization: Bearer <api-key>
```

Reads require `apps:read`. Mutations require `apps:write`. Deployment, redeploy, rollback, and job-run requests require a user-owned or team-owned API key.

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `GET` | `/v1/final-cloud/apps` | List apps in the organization. |
| `POST` | `/v1/final-cloud/apps` | Create or update an app record. |
| `GET` | `/v1/final-cloud/apps/{appId}` | Get app status. |
| `GET` | `/v1/final-cloud/apps/{appId}/status` | Get app status, latest deployment, services, jobs, and functions. |
| `GET` | `/v1/final-cloud/apps/{appId}/config` | Read repository-backed app config. |
| `PUT` | `/v1/final-cloud/apps/{appId}/config` | Write repository-backed app config. |
| `GET` | `/v1/final-cloud/apps/{appId}/deployments` | List app deployments. |
| `GET` | `/v1/final-cloud/apps/{appId}/deployments/{deploymentId}` | Get deployment details, events, logs, metrics, resources, hooks, and diagnostics. |
| `POST` | `/v1/final-cloud/apps/{appId}/deployments/{deploymentId}/redeploy` | Redeploy from a stored deployment manifest. |
| `POST` | `/v1/final-cloud/apps/{appId}/deployments/{deploymentId}/rollback` | Roll back to a selected healthy deployment. |
| `DELETE` | `/v1/final-cloud/apps/{appId}` | Soft-delete an app. |
| `POST` | `/v1/final-cloud/apps/{appId}/domains/verify` | Compare manifest domains with runtime state. |
| `POST` | `/v1/final-cloud/apps/{appId}/domains` | Add or remove a domain in a repository-backed manifest. |
| `GET` | `/v1/final-cloud/apps/{appId}/events` | List deployment and runtime events. |
| `GET` | `/v1/final-cloud/apps/{appId}/logs` | List unified logs with filters and cursor pagination. |
| `GET` | `/v1/final-cloud/apps/{appId}/metrics` | Read deployment, service, HTTP, job, and function metrics. |
| `POST` | `/v1/final-cloud/deployments` | Deploy one app from a manifest. |
| `POST` | `/v1/final-cloud/workspace/deployments` | Deploy multiple app manifests from one workspace. |
| `POST` | `/v1/final-cloud/jobs/{jobName}/runs` | Trigger a job immediately. |
| `POST` | `/v1/final-cloud/repository-pushes` | Process a repository push and deploy matching apps. |

## List apps

```bash
curl "https://api.final.ai/v1/final-cloud/apps" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Returns `{ "ok": true, "apps": [...] }`.

## Create an app

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/apps" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "displayName": "API",
    "manifestPath": "apps/api/final-cloud.yaml",
    "repositoryId": "repo_...",
    "branch": "main",
    "metadata": {
      "source": "ci"
    }
  }'
```

The response includes the stable `appId`:

```json
{
  "ok": true,
  "result": {
    "appId": "00000000-0000-7000-8000-000000000001"
  }
}
```

If you omit `slug`, Final derives one from `displayName` and `manifestPath`.

Pass `repositoryId`, `branch`, and `manifestPath` when Final Cloud should read and update the app manifest from a repository.

## Read and update app config

Repository-backed apps expose their manifest through the config API:

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/config" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

The response includes `manifestText`, parsed `manifest`, `normalizedManifest`, diagnostics, file locator, and `fileSha`.

Write config with either `manifestText` or `manifest`:

```bash
curl -X PUT "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/config" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "manifestText": "name: api\nimage:\n  repository: ghcr.io/acme/api\n  tag: latest\nservices:\n  - name: web\n    port: 3000\n    health:\n      path: /health\n",
    "expectedFileSha": "current-file-sha"
  }'
```

Use `expectedFileSha` or `expectedHead` to avoid overwriting newer repository changes.

## Deploy an app

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/deployments" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "appId": "00000000-0000-7000-8000-000000000001",
    "manifestText": "name: api\nbuild:\n  method: dockerfile\n  context: .\n  dockerfile: Dockerfile\nservices:\n  - name: web\n    port: 3000\n    health:\n      path: /health\n",
    "sourceArchive": {
      "format": "tar.gz",
      "url": "https://example.com/builds/api-source.tar.gz",
      "sha256": "sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
    }
  }'
```

Deployment responses use `ok` for health:

```json
{
  "ok": true,
  "result": {
    "deploymentId": "00000000-0000-7000-8000-000000000010",
    "status": "healthy",
    "rolledBack": false,
    "diagnostics": []
  }
}
```

`status` can be `healthy`, `failed`, or `rolled_back`.

You can also deploy from a repository instead of passing `manifestText`:

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/deployments" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "appId": "00000000-0000-7000-8000-000000000001",
    "repositoryId": "repo_...",
    "ref": "main",
    "manifestPath": "apps/api/final-cloud.yaml"
  }'
```

## Deploy a workspace

Use workspace deployments when one repository contains multiple `final-cloud.yaml` manifests.

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/workspace/deployments" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "failurePolicy": "stop-on-failure",
    "items": [
      {
        "appId": "00000000-0000-7000-8000-000000000001",
        "manifestPath": "apps/api/final-cloud.yaml",
        "manifestText": "name: api\nimage:\n  repository: ghcr.io/acme/api\n  tag: latest\nservices:\n  - name: web\n    port: 3000\n    health:\n      path: /health\n"
      },
      {
        "appId": "00000000-0000-7000-8000-000000000002",
        "manifestPath": "apps/jobs/final-cloud.yaml",
        "manifestText": "name: jobs\nimage:\n  repository: ghcr.io/acme/workers\n  tag: latest\njobs:\n  - name: sync\n    command: npm run sync\n"
      }
    ]
  }'
```

Set `failurePolicy` to `continue` when later items should deploy even after an earlier failure.

## Read status

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/status" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Status includes the app, latest deployment, active services, jobs, and functions.

## Deployments

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/deployments?limit=50" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Get one deployment:

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/deployments/00000000-0000-7000-8000-000000000010" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

The deployment detail response includes source metadata, events, logs, metrics, resources, lifecycle webhook deliveries, and diagnostics.

Redeploy a stored manifest:

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/deployments/00000000-0000-7000-8000-000000000010/redeploy" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Roll back to a healthy deployment:

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/deployments/00000000-0000-7000-8000-000000000010/rollback" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{}'
```

## Read events

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/events?limit=50" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Use `deploymentId` to filter events for one deployment.

## Logs and metrics

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/logs?deploymentId=00000000-0000-7000-8000-000000000010&limit=200" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Log filters include `deploymentId`, `source`, `severity`, `resource`, `query`, `startTime`, `endTime`, `cursor`, and `limit`. The response includes `nextCursor` when more logs are available.

```bash
curl "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/metrics?hours=24" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Metric filters include `deploymentId`, `resource`, `startTime`, `endTime`, and `hours`. Service CPU is reported as vCPU.

## Domains

Verify domains declared in the manifest:

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/domains/verify" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{}'
```

Add a domain to a repository-backed manifest:

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001/domains" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "kind": "service",
    "resourceName": "web",
    "hostname": "api.example.com",
    "expectedFileSha": "current-file-sha"
  }'
```

For function domains, use `"kind": "function"` and include `pathPrefix` when needed.

## Trigger a job

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/jobs/sync/runs" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "appId": "00000000-0000-7000-8000-000000000001"
  }'
```

The response includes a job run result. `ok` is `true` when the run succeeds.

## Repository push events

```bash
curl -X POST "https://api.final.ai/v1/final-cloud/repository-pushes" \
  -H "Authorization: Bearer ${FINAL_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "event": "github_push",
    "repositoryId": "repo_...",
    "branch": "main",
    "after": "abc123"
  }'
```

Final Cloud deploys matching repository-linked apps only when `final-cloud.yaml` allows the pushed branch and trigger.

## Delete an app

```bash
curl -X DELETE "https://api.final.ai/v1/final-cloud/apps/00000000-0000-7000-8000-000000000001" \
  -H "Authorization: Bearer ${FINAL_API_KEY}"
```

Delete returns `{ "ok": true, "deleted": true }`.
