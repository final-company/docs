Final doesn't replace your coding agent. It gives the agent a computer to work on. You can run the stock Claude Code or Codex CLI there yourself, or create a Final agent that anyone on your team can message and that starts on a prepared computer.

| | Claude Code or Codex on a computer | Final agent |
| --- | --- | --- |
| **You talk to it** | In the computer's terminal | In Final chats, alone or with teammates |
| **Its environment** | A computer you open and set up with your [setup script](/ai-coding/cloud-environments#write-a-setup-script) | A new computer from your [sandbox setup](/ai-coding/cloud-environments#prepare-computers-for-a-final-agent) for each chat |
| **Its settings** | Your CLI's own settings, instructions, and login | Instructions and tools in the agent's source; each person picks the model in the chat |
| **Models** | Your Claude or ChatGPT subscription, or an API key | Final-provided models, or your own subscription or API key |

## Set up your agent

<Tabs>
  <Tab title="Final agent">
    A Final agent is a coding agent that lives in your project. Create it once, and anyone with access can chat with it. Each chat gets a fresh computer prepared by your sandbox setup.

    <Steps>
      <Step title="Create the agent">
        Open **Agents** and click **New agent**. Enter a name, such as `Storefront Coder`, and choose the coding template.

        Final creates a repository for the agent with an `agent.ts` and `instructions.md`. The agent states what it requires, and names no machine or model:

        ```ts agent.ts
        import { defineAgent, markdown } from '@finalai/agents';

        export const agent = defineAgent({
          name: 'Storefront Coder',
          instructions: markdown('./instructions.md', { from: import.meta.url }),
          require: {
            harness: {
              permissionMode: 'review',
              recommended: { harness: 'nanocode-claude', model: 'claude-opus-5-5' },
            },
            compute: { files: 'write', shell: 'execute' },
          },
        });
        ```

        `recommended` is the harness and model a new chat starts with. It's a suggestion, not a rule: people can pick another one the project allows.
      </Step>
      <Step title="Point new chats at your environment">
        In the project's settings, open **Sandbox for new chats** and choose a Final computer with your image and your published [sandbox setup](/ai-coding/cloud-environments#prepare-computers-for-a-final-agent). Each new chat with the agent gets its own computer from it, with your repository checked out and your app running.
      </Step>
      <Step title="Choose Claude or Codex">
        In a chat, open the chat's info and pick the model. The list shows the harnesses and models the project allows that suit the agent, with the agent's recommendation marked. Claude models run on a Claude Code-style harness and OpenAI models on a Codex-style one. Your choice applies to that chat and is remembered for your next chat with the agent.
      </Step>
      <Step title="Connect your subscription">
        Connect your Claude or ChatGPT subscription in Final to let agents use your plan instead of Final-provided models. When a chat uses your subscription, model calls are charged to it; when you haven't connected one, the project's API key or Final's metered inference is used, as the project allows. See [inference sources](/harnesses/settings#inference-sources).
      </Step>
      <Step title="Test and publish">
        Use the agent editor's test to ask for something that proves the setup, such as `Run the test suite and tell me how many tests pass.` When the answer looks right, click **Publish**. Saving changes to the agent's repository doesn't publish them; only **Publish** does. Then start a chat with the agent, or add it to a project chat.
      </Step>
    </Steps>

    See [requirements and providing](/build/requirements) and [publishing](/operate/publishing) in the Agent SDK docs for everything else you can set.
  </Tab>
  <Tab title="Claude Code">
    Run the same Claude Code you use locally on a Final computer. Create a computer and clone your repository first, as in the [quickstart](/ai-coding/quickstart).

    In the computer's editor terminal, install Claude Code and check it:

    ```bash
    curl -fsSL https://claude.ai/install.sh | bash
    claude --version
    ```

    You should see a version number followed by `(Claude Code)`. Then start it from your repository:

    ```bash
    cd storefront
    claude
    ```

    On first run, Claude Code asks you to sign in. The computer has no browser for it to open, so copy the login URL it shows (press `c`) and open it in your own browser. After you sign in, paste the code you get back at the `Paste code here if prompted` prompt. Claude Code stores the login on the computer, so you only do this once per computer.

    **Your setup comes with the repository.** `CLAUDE.md`, `.claude/settings.json`, custom commands, and skills committed to the repository work as they do on your laptop. Settings that live only in your home directory, such as `~/.claude/CLAUDE.md` or user-scoped MCP servers, don't come along. Copy the files you rely on to the computer, or re-add servers with `claude mcp add`.

    <Accordion title="Sign in without the browser flow">
      Run `claude setup-token` on a machine with a browser. It prints a long-lived token for your Claude subscription. On the computer, set it before you start Claude Code:

      ```bash
      export CLAUDE_CODE_OAUTH_TOKEN='paste-your-token-here'
      ```

      To use a Claude Console API key instead, set `ANTHROPIC_API_KEY` and approve the key when Claude Code asks. Keep either value out of your repository and shell history files.
    </Accordion>
  </Tab>
  <Tab title="Codex">
    Run the same Codex CLI you use locally on a Final computer. Create a computer and clone your repository first, as in the [quickstart](/ai-coding/quickstart).

    In the computer's editor terminal, install Codex:

    <CodeGroup>
      ```bash Installer
      curl -fsSL https://chatgpt.com/codex/install.sh | sh
      ```

      ```bash npm
      npm install -g @openai/codex
      ```
    </CodeGroup>

    Sign in with a device code, which works without a browser on the computer. First turn on device code login in your ChatGPT security settings (workspace admins turn it on in workspace permissions), then run:

    ```bash
    codex login --device-auth
    ```

    Open the link it prints in your own browser and enter the code. To use an OpenAI API key instead, run `printenv OPENAI_API_KEY | codex login --with-api-key`.

    Start Codex from your repository:

    ```bash
    cd storefront
    codex
    ```

    **Your setup comes with the repository.** Codex reads `AGENTS.md` from the repository as it does on your laptop. Personal settings in `~/.codex/config.toml`, such as MCP servers or a default model, don't come along. Copy that file to the computer if you rely on it.
  </Tab>
</Tabs>

<Note>
On a computer you share, anyone with **Editor** access can open its editor and use the CLI login stored there. Give each person their own computer, or use a Final agent with per-person subscriptions.
</Note>

## Give the agent your tools

Coding agents do better with context: the issue they're fixing, the design doc, the error in your logs. Add the [MCP gateway](/mcp-gateway/quickstart) to Claude Code or Codex, and they can reach the tools your organization connected in Final through one server. Final agents reach the same tools through Final's gateway integration; see [integrations](/build/integrations#finals-gateway).
