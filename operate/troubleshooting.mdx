Find the symptom that matches what you're seeing. Each entry explains the cause, then the fix.

## Defining an agent

<AccordionGroup>
  <Accordion title="Making the document fails with &quot;uses X, which is defined outside it&quot;">
    A serverless tool or hook uses a variable, import, or helper defined outside its function. Move it inside the function, bundle the code and pass `source`, or make the tool in-process if it needs something only your process has. See [keep it self-contained](/build/tools#keep-it-self-contained).
  </Accordion>
  <Accordion title="final-agents print can't load the module">
    The CLI imports your module with Node. If it imports other local TypeScript files, run it through tsx: `NODE_OPTIONS='--import tsx' npx final-agents print ./agent.ts`. If the module exports more than one agent, pass `--export <name>`. See [the agent module](/build/project-structure#run-your-scripts).
  </Accordion>
  <Accordion title="A file named by markdown() or skill() isn't found">
    Paths are relative to `from`. Pass `{ from: import.meta.url }` so they resolve against the module that calls them, not your working directory.
  </Accordion>
</AccordionGroup>

## Starting work

<AccordionGroup>
  <Accordion title="The call fails with requirements_unmet">
    Something the agent requires wasn't provided or can't meet the requirement, and nothing was created. Read `cause.requirements`: each item has a `kind`, `name`, and `problem`. Provide what's missing, or mark requirements the agent can do without `optional: true`. See [requirements and providing](/build/requirements#nothing-starts-with-something-missing).
  </Accordion>
  <Accordion title="The harness is unsuitable or &quot;needs an environment&quot;">
    Final's serverless harnesses run in a Workers sandbox. When you start a session or conversation, the SDK creates one for settings that leave `environment` out. Channel installs need it named: create one with `project.sandboxes.create(workers(), { idempotencyKey: 'workers' })` and pass its `id`. Claude Code and Codex run on a machine, by default the one provided for `shell`. A harness is also unsuitable when its lowest permission level is above the agent's ceiling or it lacks a feature the agent uses. Run `project.harnesses.check({ agent, harness })` to see the problems. See [harness settings](/harnesses/settings).
  </Accordion>
  <Accordion title="files and shell are rejected as different_sandboxes">
    `files` and `shell` must be the same sandbox. Provide one sandbox for both.
  </Accordion>
  <Accordion title="A fetched agent fails with code_unavailable">
    The agent has in-process tools or hooks, and the calling process doesn't hold their code because it fetched the agent by name. Start it from the process that defines it, or make those tools serverless. See [where code and compute run](/build/where-code-runs).
  </Accordion>
  <Accordion title="The model ran commands on my server">
    The agent requires `files` or `shell`, the call didn't provide them, and the client lends its own process by default. On a server, create the client with `localCompute: false` and provide every capability. See [servers turn local compute off](/build/where-code-runs#servers-turn-local-compute-off).
  </Accordion>
</AccordionGroup>

## Running sessions

<AccordionGroup>
  <Accordion title="The session fails with a model or credentials error">
    No inference source in the harness settings produced model access. Check the `model` name and each source: a personal `subscription()` the person hasn't connected, an `apiKey('NAME')` whose secret isn't set, or a source the harness doesn't accept. Ending the list with `finalCredits()` gives it a fallback. See [inference sources](/harnesses/settings#inference-sources).
  </Accordion>
  <Accordion title="A turn seems stuck">
    The agent is most likely waiting for a person: an approval, or a sign-in to an integration. List the open decisions and answer them, or cancel the turn:

    ```ts
    const session = client.sessions.attach(sessionId);
    console.log(await session.decisions());
    ```

    See [handle approvals](/client/sessions#handle-approvals).
  </Accordion>
  <Accordion title="An in-process tool or the local shell reports itself unavailable">
    The process that created the session exited or lost its connection. The session carries on, and these come back when a process holding the agent starts it again. Use serverless tools and a provided sandbox for work that must continue without your process.
  </Accordion>
  <Accordion title="The turn finished, but the reply is empty">
    Check `stopReason` on the result. `cancelled` means someone stopped the turn, and `error` means it failed. An agent can also finish a turn with tool calls and no text.
  </Accordion>
  <Accordion title="ctx.secrets.get() returns null">
    The secret isn't set in the session's project, or it isn't listed in the agent's `secrets`. Add its name to `secrets` and create the value under **Developer** > **Secrets**. See [secrets](/operate/authentication#use-secrets-in-your-code).
  </Accordion>
  <Accordion title="An integration's tools are missing">
    Check the slot's `tools` policy: `deny` wins over `allow`, and the most specific pattern governs. A slot marked `optional` that wasn't provided has no tools at all. See [integrations](/build/integrations#choose-which-tools-the-agent-gets).
  </Accordion>
</AccordionGroup>

## Channels and schedules

<AccordionGroup>
  <Accordion title="Publishing a channel fails because the source imports something">
    A channel is published as one module that imports nothing. Bundle it with `esbuild --bundle --format=esm` and publish the output. See [publish and install](/build/channels#publish-and-install).
  </Accordion>
  <Accordion title="A channel refuses an unconnected place">
    Connect the provider place to a chat you manage: through the install's `connectUrl` page if it has one, or with `chat.channelRoutes.connect({ bindingId, place, policy })`. A shared place needs a group chat. See [link and connect](/build/channels#link-a-person-and-connect-a-place).
  </Accordion>
  <Accordion title="A channel install fails with requirements_unmet for its app">
    The channel declares provider app credentials in `require.app`, and the install's channel app doesn't fill every required slot. Create a channel app with the project secrets for each slot and pass its ID as `app`, or use the one the channel's publisher attached. See [provider app credentials](/build/channels#provider-app-credentials).
  </Accordion>
  <Accordion title="A schedule doesn't run">
    A schedule fires in its conversation, for one agent participant, with what that participant is provided there. Check `enabled` and `nextRunAt` with `chat.schedules()`, and fire it with `chat.runSchedule({ scheduleId })` to test it right away. If the run fails, check that the participant's `provide` still meets the agent's requirements without a person present: shared or secret-based integrations, a specific sandbox, and inference that ends with `finalCredits()` or a project key. See [schedules](/build/schedules).
  </Accordion>
</AccordionGroup>
