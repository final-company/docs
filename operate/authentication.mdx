---
title: "Credentials and secrets"
description: "Understand the credentials an agent touches, and keep each one out of your source."
---

An agent touches several kinds of credentials, and each is set up in a different place. Mixing them up is the most common setup mistake, so it helps to keep them apart:

| Credential | What it's for | Where it lives |
| --- | --- | --- |
| **Final API key** | Lets your code and the CLI publish agents and start work in a project. | `FINAL_API_KEY` on your machine or server. |
| **Inference** | Pays for the agent's model calls. | The `inference` sources in the [harness settings](/harnesses/settings#inference-sources) the caller provides. |
| **Integration auth** | Lets the agent's MCP servers act for a person or the project. | The [integration](/build/integrations): a person's sign-in, a shared sign-in, or a project secret. |
| **Secrets** | Let the agent's own code call other services, like your release API. | **Developer** > **Secrets** in the dashboard, read with `ctx.secrets`. |

Your API key is never used for model calls or integration calls. Model calls follow the `inference` the caller provides; integration calls follow the integration's auth.

## Authenticate your code and the CLI

[Create an API key](/api-keys) and export it with your project's ID:

```bash
export FINAL_API_KEY='paste-your-key-here'
export FINAL_PROJECT_ID='prj_your_project'
```

The `final-agents` CLI reads both automatically. The client doesn't read environment variables, so pass them when you create it:

```ts
import { createClient } from '@finalai/agents/client';

const client = createClient({ auth: { apiKey: process.env.FINAL_API_KEY! } });
const project = client.project({ id: process.env.FINAL_PROJECT_ID! });
```

Keep the key on your server. Browser apps should call your backend, which calls Final.

## Act for your app's end users

When your app starts work for one of its own users, name them as the `actor`, so their personal sign-ins and subscriptions are theirs:

```ts
await project.sessions.create({
  agent,
  provide: { harness },
  actor: { externalId: 'user_4821', displayName: 'Morgan Lee' },
  message: 'What is blocking 1.2.0?',
});
```

## Pay for model calls

Inference is part of the harness settings, so whoever starts the agent decides how it's paid for, per call. The agent's author doesn't:

```ts
serverlessFinal({ model: 'deepseek-v4.1-flash', inference: finalCredits(), environment: runtime.id });
```

This uses Final's metered inference and bills the project. To use a project API key or a person's own subscription, see [inference sources](/harnesses/settings#inference-sources).

## Use secrets in your code

A secret is a named value, like an API token, that Final stores encrypted and hands to the agent's code at run time. Your source only contains the name.

<Steps>
  <Step title="Create the secret">
    In the dashboard, go to **Developer** > **Secrets** and click **New secret**. Use a descriptive name, like `RELEASE_SERVICE_TOKEN`.
  </Step>
  <Step title="Declare it on the agent">
    List every secret the agent's tools and hooks read. Reading a secret that isn't listed fails.

    ```ts agent.ts
    secrets: ['RELEASE_SERVICE_TOKEN'],
    ```
  </Step>
  <Step title="Read it">
    `ctx.secrets.get()` returns the value, or `null` if the secret isn't set:

    ```ts
    const token = await ctx.secrets.get('RELEASE_SERVICE_TOKEN');
    if (token == null) throw new Error('The RELEASE_SERVICE_TOKEN secret is not set');
    ```
  </Step>
</Steps>

Secrets resolve in the project the session runs in, for serverless and in-process code alike. The same secrets back `apiKey('NAME')` inference sources, `secret('NAME')` integration auth, and `{ secret: 'NAME' }` [sandbox setup](/build/sandbox-setups) variables; those don't need to be listed in `secrets`.

<Warning>
Never log secret values or return them from a tool. Anything a tool returns goes to the model and can show up in the agent's replies.
</Warning>

## Connect an AI client instead

To use your connected accounts from Claude Code, Codex, or another MCP client, without building an agent, use the [MCP gateway](/mcp-gateway/overview). It signs in with your Final account instead of an API key.
