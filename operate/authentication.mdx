---
title: "Credentials and secrets"
description: "Understand the three kinds of credentials an agent uses, and keep each one out of your source."
---

An agent touches three kinds of credentials, and each is set up in a different place. Mixing them up is the most common setup mistake, so it helps to keep them apart:

| Credential | What it's for | Where it lives |
| --- | --- | --- |
| **Final API key** | Lets your code and the CLI publish agents that do not declare secrets, and start sessions. | `FINAL_API_KEY` on your machine or server. |
| **Model credentials** | Pay for the agent's model calls. | The `credentials` chain in `agent.ts`. |
| **Secrets** | Let the agent's code call other services, like your release API. | **Developer** > **Secrets** in the dashboard, read with `ctx.secrets`. |

Publishing or running an agent with your API key doesn't make it a model credential. The agent's model calls always follow the chain in `agent.ts`.

## Authenticate your code and the CLI

[Create an API key](/api-keys) and export it:

```bash
export FINAL_API_KEY='paste-your-key-here'
```

The `final-agents` CLI reads `FINAL_API_KEY` automatically. The client doesn't read environment variables, so pass the key when you create it:

```ts
import { createClient } from '@finalai/agents/client';

const client = createClient({
  host: 'https://agent-session.final.ai/api',
  auth: { apiKey: process.env.FINAL_API_KEY! },
});
```

Keep the key on your server. Browser apps should call your backend, which calls Final.

## Pay for model calls

Model credentials are part of the agent's definition, so every session uses the same rules no matter who calls the agent. Set them with `credentials.chain` on the harness:

```ts agent/agent.ts
harness: serverlessFinal({
  credentials: credentials.chain({
    payer: 'organization',
    tryInOrder: [credentials.platform()],
  }),
}),
```

This uses model access provided by Final and bills it to your organization. To use your own provider key or subscription, see [model credentials](/build/configuration#model-credentials).

## Use secrets in your code

A secret is a named value, like an API token, that Final stores encrypted and hands to the agent's code at run time. Tools, hooks, channel routes, and dynamic instructions can read secrets. Your source only contains the name, so tokens never end up in Git.

<Steps>
  <Step title="Create the secret">
    In the dashboard, go to **Developer** > **Secrets** and click **New secret**. Use a descriptive name, like `release-service-token`.
  </Step>
  <Step title="Declare it in agent.ts">
    List every secret your code reads. Reading a secret that isn't listed fails.

    ```ts agent/agent.ts
    secrets: ['release-service-token'],
    ```

    Secrets referenced by a [connection's](/build/connections) `auth`, a credential chain, or a channel's `credentials.secrets` are declared for you. For example, a channel with `credentials: { app: null, secrets: ['deploy-webhook-secret'] }` declares that secret name. Store its value in the project and your event producer, never in source.
  </Step>
  <Step title="Read it">
    `ctx.secrets.get()` returns the value, or `null` if the secret isn't set:

    ```ts
    const token = await ctx.secrets.get('release-service-token');
    if (!token) throw new Error('The release-service-token secret is not set');
    ```
  </Step>
</Steps>

Publishing code that declares secrets requires an organization admin with project edit access. A project API key can upload a new agent's initial draft and request read-only compilation, but cannot publish or create a secret-using test revision. After that revision is published, later source changes also use the admin's Final Code view. Follow [draft upload and admin publication](/operate/publishing#publish-code-that-uses-secrets).

To test channel routes locally, pass secret values to `final-agents dev` with `AGENT_LOCAL_SECRETS_JSON`; see [test it locally](/build/channels#test-it-locally).

<Warning>
Never log secret values or return them from a tool. Anything a tool returns goes to the model and can show up in the agent's replies.
</Warning>

## Connect an AI client instead

To use your connected accounts from Claude Code, Codex, or another MCP client, without building an agent, use the [MCP gateway](/mcp-gateway/overview). It signs in with your Final account instead of an API key.
