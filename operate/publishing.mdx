---
title: "Testing and publishing"
description: "Try changes by starting sessions, publish an agent by name, and roll back by pointing the name at an earlier hash."
---

An agent is a document stored by its content hash, and nothing is built or deployed. Starting a session sends the document with the call, so trying a change is just starting a session with the edited agent. **Publishing** gives a hash a name, so others in the project can fetch the agent and Final's chats, schedules, and channels can use it.

## Try a change

Edit the agent module and start a session with it, as in the [quickstart](/quickstart). The new document is stored when the session is created and the session pins its hash, so a published name and the sessions using it are unaffected.

```bash
npx tsx run.ts
```

Before you publish a change, try a normal request, a request that makes a tool fail, and a follow-up message. If the agent asks for approvals, check that your app shows them and that declining works. Tools and integrations run for real, so point them at test data.

`final-agents print` writes the document without calling anything, which is a quick way to check that serverless tools are self-contained and files named by `markdown` and `skill` exist:

```bash
npx final-agents print ./agent.ts
```

Type-check your TypeScript with `tsc` as usual; making the document doesn't.

## Publish

```bash
npx final-agents publish ./agent.ts --name release-assistant
```

```text
published release-assistant: sha256:9f3c2a1...
id: agt_7Hq2...
```

`publish` stores the document by its content hash and points the name at it. It reads `FINAL_API_KEY` and `FINAL_PROJECT_ID`; `--project` and `--host` override them. Pass `--export <name>` when the module exports more than one agent.

From code, it's one call:

```ts
const published = await project.agents.publish({ agent, name: 'release-assistant' });
console.log(published.name, published.hash);
```

Publishing does two things:

1. **Points the name at the hash.** New sessions that fetch the agent by name use it. Sessions already running keep the hash they started with, so a publish never changes an agent in the middle of a conversation.
2. **Updates the agent's schedules.** Each schedule in the document is created or updated by its key, and schedules the document no longer has are turned off. See [schedules](/build/schedules).

Names use lowercase letters, digits, `.`, `_`, and `-`, and are unique in a project.

### Publish from CI

To release every change merged to `main`, publish from your CI pipeline. In GitHub Actions, store your key as a repository secret named `FINAL_API_KEY`:

```yaml .github/workflows/publish-agent.yml
name: Publish agent
on:
  push:
    branches: [main]

jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 26
      - run: npm ci
      - run: npx final-agents publish ./agent.ts --name release-assistant
        env:
          FINAL_API_KEY: ${{ secrets.FINAL_API_KEY }}
          FINAL_PROJECT_ID: prj_your_project
```

Final doesn't watch your repository: an agent is published only when something calls `publish`.

## Fetch a published agent

```ts
const agent = await project.agents.get({ name: 'release-assistant' });
```

Fetch by `{ name }`, `{ id }`, or `{ hash }` for an exact version. A fetched agent is data: pass it to `project.sessions.create`, a conversation participant, or `publish` like the value you defined. Its serverless tools run as usual. An in-process tool can't run for a caller that doesn't hold its code, so `agent.inProcess` lists them and starting such an agent fails with `code_unavailable`. Agents meant for Final's chats, schedules, and teammates who fetch them use [serverless tools](/build/tools#in-process-or-serverless).

`project.agents.list()` lists the agents published in the project and those it inherits from parent projects.

## Review history and roll back

`history` lists every hash a name has pointed at, newest first:

```ts
const { publications } = await project.agents.history({ name: 'release-assistant' });
for (const publication of publications) console.log(publication.hash, publication.publishedAt);
```

To roll back, fetch the earlier hash and publish it under the name again:

```ts
const previous = publications[1];
if (previous != null) {
  const earlier = await project.agents.get({ hash: previous.hash });
  await project.agents.publish({ agent: earlier, name: 'release-assistant' });
}
```

The rollback is a new publication, so the history stays complete.

## Documents as files

`final-agents print ./agent.ts > agent.json` saves the document. `project.agents.parse(json)` validates a saved document and returns it as an agent, without calling Final, so a document can be reviewed, stored, or published from a system that doesn't run your TypeScript.
