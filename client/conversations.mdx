---
title: "Conversations"
description: "Use chats that Final stores, with history, read state, and several people and agents in one room, each agent with its own provide."
---

A conversation is a chat that Final stores for you. People and agents are its participants, every message is kept in order, and Final delivers each message to the right agent. Use conversations when you want a persistent chat without building your own message storage, or when several people or agents share one room.

| | [Sessions](/client/sessions) | Conversations |
| --- | --- | --- |
| What it is | A direct line to one agent | A chat room with people and agents |
| History | Kept per session | Kept as messages, with read state and threads |
| Who's in it | You and the agent | Any number of people and agents |
| What agents are provided | `provide` on the session | `provide` per agent participant, layered over the conversation's |
| Good for | Tasks, your own chat UI with your own storage | Shared, long-lived chats |

Under the hood, each agent in a conversation works in its own session. Final creates it the first time a message reaches that agent, from what that participant was provided.

Conversations belong to people: the examples here use a client signed in as a person, created with `createClient({ auth: { bearer: getToken } })` or `{ cookies: true }` in a browser. A project API key has no person inbox, so use [sessions](/client/sessions) to build your own application with an API key.

## Send a message

`project.conversations.direct` opens your one-to-one chat with an agent, creating it the first time. `provide` is stored only when the agent has no settings in that chat yet, so later calls don't overwrite choices made since:

```ts
import { createClient } from '@finalai/agents/client';
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';

const client = createClient({ auth: { bearer: getToken } });
const project = client.project({ id: 'prj_your_project' });

const agent = await project.agents.get({ name: 'release-assistant' });
const harness = serverlessFinal({ model: 'deepseek-v4.1-flash', inference: finalCredits() });

const chat = await project.conversations.direct({ agent, provide: { harness } });
const sent = await chat.send('What is blocking 1.2.0?');

for (const delivery of sent.deliveries) {
  if (delivery.sessionId == null || delivery.turnId == null) continue; // still queued
  const turn = await client.sessions.attach(delivery.sessionId).response(delivery.turnId);
  console.log((await turn.result()).text);
}
```

`send` returns the message's **deliveries**: one per agent it was routed to, with the session and turn handling it. A delivery without a `turnId` is queued, for example because the agent is still busy. Check again later with `chat.deliveries({ messageId: sent.messageId })`.

Save `chat.conversation.id` to reopen the same chat later with `client.conversations.get(conversationId)`.

### Find a chat without creating one

`findDirect` and `findHome` look up the person's existing chats and create nothing:

```ts
const existing = await project.conversations.findDirect({ agent: 'agt_your_agent' });
const home = await project.conversations.findHome();
```

`project.conversations.home({ provide })` opens the person's Home thread with the project's agent, creating it the first time.

## Show messages live

For a chat UI, subscribe to the conversation's events. The agent's reply appears as a message that updates while it's being written, so you can render every message the same way:

```ts
import { AgentRealtimeKind } from '@finalai/agents/client';

for await (const event of chat.events()) {
  if (
    event.kind === AgentRealtimeKind.MessageCreated ||
    event.kind === AgentRealtimeKind.MessageUpdated
  ) {
    const { id, author, body, streaming } = event.message;
    render({ id, author: author.displayName, text: body, typing: streaming !== null });
  }
}
```

`render` stands in for your UI. Key messages by `id`, because the same message arrives again each time it changes. `streaming` is set while the agent is still writing.

## Load history and mark it read

`messages` returns a page of history. Each message has a `seq`, its position in the conversation. Mark everything up to a message as read by passing its `seq`:

```ts
const page = await chat.messages({ limit: 50 });
for (const message of page.messages) {
  console.log(`${message.author.displayName}: ${message.body}`);
}

const last = page.messages.at(-1);
if (last != null) await chat.markRead({ throughSeq: last.seq });
```

## Create a group conversation

A group conversation can have several people and agents. Each agent participant has its own `provide`, and the conversation can carry a shared one: each top-level key comes whole from the participant if it sets it, otherwise from the conversation. This room shares one computer between its agents:

```ts
import { computer } from '@finalai/agents/sandboxes';

const conversationId = crypto.randomUUID();
const box = await project.sandboxes.create(computer(), { ownedBy: { conversation: conversationId } });
const issues = await project.integrations.get({ name: 'linear' });

const room = await project.conversations.create({
  id: conversationId,
  kind: 'group',
  title: 'Release 1.2.0',
  participants: [
    { user: 'usr_your_teammate' },
    { agent, routingMode: 'default', provide: { harness, integrations: { issues } } },
  ],
  provide: { compute: { files: box, shell: box } },
});
```

Choosing the conversation's `id` up front lets you create the sandbox it owns first; the sandbox is deleted with the conversation. Creating fails with `requirements_unmet`, creating nothing, unless every agent's requirements are met.

Each agent's **routing mode** decides which messages it answers:

| Routing mode | The agent... |
| --- | --- |
| `default` | Replies to messages by default. |
| `all` | Reads every message in the room. |
| `mention` | Replies only when someone mentions it. |

Add an agent later with its own `provide`, and mention it by participant ID:

```ts
const reviewer = await project.agents.get({ name: 'release-reviewer' });
const added = await room.addParticipant({ agent: reviewer, routingMode: 'mention', provide: { harness } });
await room.send('Review the release checklist, please.', { mentions: [added.id] });
```

User IDs come from `client.people.all()`, which lists your organization's members. `room.participants()` lists everyone in the room.

## Change an agent's settings

An agent participant's settings are its stored `provide`, plus per-chat `instructions` and a narrower `tools` list. Read them, then change them with the revision you read:

```ts
const settings = await room.participants.settings(added.id);
await room.participants.provide(added.id, {
  harness: serverlessFinal({ model: 'gpt-6.1-sol', inference: finalCredits() }),
  revision: settings.revision,
});
```

`null` removes a capability or slot, like `compute: { browserUse: null }`. A stale `revision` fails with `conflict`. The result must still meet the agent's requirements, or the call fails with `requirements_unmet`.

A change within one harness, like another model, applies to the running session. Switching to a different harness replaces the session after the current turn, keeping the transcript, sandboxes, and integrations.

## Post an event from another system

`postEvent` tells the conversation's default agent that something happened outside the chat, like a finished build. The agent receives it as input and replies in the conversation, with the source shown as the reply's caption:

```ts
await room.postEvent({
  source: { id: 'release-build', name: 'Release build' },
  eventId: `build-${buildId}:completed`,
  text: 'The release build for 1.2.0 completed. All 214 tests passed.',
});
```

Final accepts each `eventId` from a source once, so retrying a failed request never notifies the agent twice. To receive events from systems you don't control, like GitHub webhooks, use a [channel](/build/channels).

## Approvals and stopping work

Agents in conversations ask for approval the same way they do in sessions. Answer with `room.respond({ decisionId, optionId })` or `room.respond({ decisionId, outcome })`; see [handle approvals](/client/sessions#handle-approvals). `client.conversations.decisions()` lists what awaits the person across conversations. `room.cancel()` stops every agent's running turn in the conversation.
