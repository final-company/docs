You'll build a release assistant: an agent that answers "is this release ready to ship?" by calling a checklist tool. You'll define it in one module, start a session from a script, and publish it so others can fetch it by name. It takes about 10 minutes.

<Tip>
Want your coding agent to do this for you? Use the [setup prompt](/agent-sdk#let-an-agent-set-it-up).
</Tip>

**Before you start**, you need:

- Node.js 26 or later. Check with `node --version`.
- A [Final API key](/api-keys) with the `agents:read`, `agents:write`, and `agents:execute` permissions, and the ID of the project it belongs to (`prj_...`). You won't need them until step 4.

<Steps>
  <Step title="Create the project">
    Create a Node.js project and install the SDK. `@finalai/agents` includes the authoring helpers, the client, and the `final-agents` CLI.

    ```bash
    mkdir release-assistant && cd release-assistant
    npm init -y
    npm pkg set type=module
    npm install @finalai/agents zod
    npm install --save-dev typescript tsx @types/node
    ```
  </Step>
  <Step title="Define the agent">
    An agent is one value, made with `defineAgent`, that lists every part explicitly. This one has instructions, one tool, and one requirement:

    ```ts agent.ts
    import { defineAgent, defineServerlessTool, markdown } from '@finalai/agents';
    import * as z from 'zod';

    const releaseChecklist = defineServerlessTool({
      description: 'List the checks a release must pass before it ships.',
      inputSchema: z.object({ version: z.string() }),
      execute: async ({ version }) => ({
        version,
        checks: ['CI is green on main', 'CHANGELOG.md has an entry', 'Release owner signed off'],
      }),
    });

    export const agent = defineAgent({
      name: 'Release Assistant',
      description: 'Checks whether a release is ready to ship.',
      instructions: markdown('./instructions.md', { from: import.meta.url }),
      tools: { release_checklist: releaseChecklist },
      require: {
        harness: { permissionMode: 'ask', recommended: { harness: 'final', model: 'deepseek-v4.1-flash' } },
      },
    });
    ```

    - **The tool** is `release_checklist`, the key in `tools`. It's a **serverless** tool: self-contained, so its source becomes part of the agent and runs on Final's runtime. [Tools](/build/tools) covers the other kind, in-process tools that run in your own process.
    - **`require.harness`** says the agent needs a harness, the program that runs the model loop, held to `ask`: anything that changes something waits for a person. `recommended` is a hint for whoever starts it; it binds nobody.

    Then write the instructions beside it:

    ```markdown instructions.md
    You help maintainers decide whether a release is ready to ship.
    Call release_checklist for the version, then list each check as done or missing.
    Ask for evidence instead of assuming a check passed.
    ```
  </Step>
  <Step title="Check the document">
    `final-agents print` writes the agent's document, the JSON Final stores, without calling anything:

    ```bash
    npx final-agents print ./agent.ts
    ```

    ```json
    {
      "version": 5,
      "identity": { "name": "Release Assistant", "description": "Checks whether a release is ready to ship." },
      "instructions": "You help maintainers decide whether a release is ready to ship.\n...",
      "require": { "harness": { "permissionMode": "ask", ... }, "compute": {}, "integrations": {} },
      "tools": { "release_checklist": { "code": { "placement": "serverless", ... } } },
      ...
    }
    ```

    If a serverless tool uses something defined outside it, `print` fails and names it.
  </Step>
  <Step title="Connect to your project">
    Export your API key and project ID, then create a client module the next scripts share:

    ```bash
    export FINAL_API_KEY='paste-your-key-here'
    export FINAL_PROJECT_ID='prj_your_project'
    ```

    ```ts client.ts
    import { createClient } from '@finalai/agents/client';

    const apiKey = process.env.FINAL_API_KEY;
    const projectId = process.env.FINAL_PROJECT_ID;
    if (apiKey == null || projectId == null) throw new Error('Set FINAL_API_KEY and FINAL_PROJECT_ID');

    export const client = createClient({ auth: { apiKey } });
    export const project = client.project({ id: projectId });
    ```

    Everything you create through `project` belongs to that project.
  </Step>
  <Step title="Start a session">
    Start a session with a first message, providing a harness:

    ```ts run.ts
    import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
    import { workers } from '@finalai/agents/sandboxes';
    import { agent } from './agent.js';
    import { client, project } from './client.js';

    // Final's Workers runtime runs the harness. The key makes reruns reuse the same one.
    const runtime = await project.sandboxes.create(workers(), { idempotencyKey: 'workers' });

    const { handle, response } = await project.sessions.create({
      agent,
      provide: {
        harness: serverlessFinal({
          model: 'deepseek-v4.1-flash',
          inference: finalCredits(),
          environment: runtime.id,
        }),
      },
      message: 'Is 1.2.0 ready to ship? CI is green and the changelog is updated.',
    });

    const result = await response!.result();
    console.log(result.text);
    console.log(`\nStop reason: ${result.stopReason}`);

    await handle.close();
    client.close();
    ```

    - **`serverlessFinal`** builds harness settings for Final's own agent loop, a program that runs on Final's Workers runtime, which `environment` names.
    - **`inference: finalCredits()`** pays for model calls with Final's metered inference, billed to the project. See [inference sources](/harnesses/settings#inference-sources) for your own keys and subscriptions.

    Run it:

    ```bash
    npx tsx run.ts
    ```

    The agent calls `release_checklist`, compares it with what you told it, and replies with something like:

    ```text
    Not yet. Two of the three checks are done:

    - CI is green on main: done
    - CHANGELOG.md has an entry: done
    - Release owner signed off: missing

    Once the release owner signs off, 1.2.0 is ready to ship.

    Stop reason: end_turn
    ```

    Leave out `harness` and the call fails with `requirements_unmet`, naming the harness, and creates nothing.
  </Step>
  <Step title="Publish it by name">
    Publishing gives the agent a name others in the project can fetch it by, such as your teammates' scripts or Final's chats:

    ```bash
    npx final-agents publish ./agent.ts --name release-assistant
    ```

    ```text
    published release-assistant: sha256:4f1c...
    ```

    The hash identifies this exact document. Publish again after a change and the name points at the new hash; sessions already running keep the one they started with.
  </Step>
</Steps>

<Check>
You've defined an agent, started it with what it requires, and published it. To change it, edit `agent.ts` and run `npx tsx run.ts` again: the new document goes with the call, so there's nothing to deploy.
</Check>
