Each VM receives a hostname in its region. When you configure `httpPort`, Final can route HTTP traffic to that port.

## Expose an HTTP service

Create a VM with an HTTP port:

```bash
final-vm new docker.io/library/node:22-slim \
  --name preview-app \
  --port 3000 \
  --command "node server.js"
```

Set `--public` when the service should be reachable without Final authentication:

```bash
final-vm new docker.io/library/node:22-slim \
  --name public-preview \
  --port 3000 \
  --public
```

You can toggle public HTTP access with [update VM visibility](/api-reference/virtual-machines/vms/update-visibility).

## Use custom domains

Add a domain to a VM:

```bash
curl -X POST "https://vm-api.final.ai/v1/vms/preview-app/domains" \
  -H "Authorization: Bearer ${FINAL_VM_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"domain":"preview.example.com"}'
```

Then point a `CNAME` or `A` record for the domain at the VM hostname. Final verifies DNS and issues the certificate automatically.

Use [add a custom domain](/api-reference/virtual-machines/domains/add), [list custom domains](/api-reference/virtual-machines/domains/list), and [delete a custom domain](/api-reference/virtual-machines/domains/delete) to manage domains from automation.

## Share a VM

You can share a VM with a user, email address, team, or link. Shares can grant `http` access or `full` access.

Create a link share with the CLI:

```bash
final-vm share preview-app --link
```

Grant full access to an email address:

```bash
final-vm share preview-app --user teammate@example.com --full
```

Remove an email share:

```bash
final-vm share preview-app --user teammate@example.com --remove
```

For API-based sharing, use [create a share](/api-reference/virtual-machines/shares/create) and [delete a share](/api-reference/virtual-machines/shares/delete).

## Choose access levels

| Access | What it allows |
| --- | --- |
| `http` | Access to the VM's HTTP service. |
| `full` | Full VM access, including SSH when the user has an authorized key. |

Prefer `http` for previews and demos. Use `full` only when the recipient needs to operate the VM.
