title: "Judges"
description: "Score spans, traces and sessions with published Final agents, conditions, TypeScript in your project's Files, or results you submit."
---

A judge scores a span, a trace or a session and returns one of its labels, a score, or pass/fail, with a reason. Judges run [online](/o11y/online-evaluation) as turns and runs finish, on demand, over past traces, and in [test suites](/o11y/experiments).

A judge is a binding: it names what judges (an agent, conditions, code or you), what it scores, and the labels it may return. Versioning comes from what it binds to, and every result records the exact **evaluator version** that produced it.

| Type | What decides | Scopes | Output | Evaluator version |
| --- | --- | --- | --- | --- |
| `agent` | A published Final agent reads the evidence. | Span, trace, session | Binary, categorical or numeric | The agent's content hash |
| `deterministic` | Conditions on duration, cost, errors, span names and attributes. | Span, trace | `Matched` or `Not matched` | A hash of the conditions |
| `code` | TypeScript in the project's Files repository. | Span, trace | Binary, categorical or numeric | A git commit |
| `external` | Results you submit through the API. | Span, trace, session | Binary, categorical or numeric | A hash of the configuration |

Categorical judges list their `choices` (2 to 50 labels, each with an optional description). A binary judge has two choices, pass then fail, or the labels `Pass` and `Fail` when you give none. Numeric judges give a `numericRange`, or choices with a `value` each.

The examples use a project client:

```ts
import { createClient } from '@finalai/agents/client';

const client = createClient({ auth: { apiKey: process.env.FINAL_API_KEY! } });
export const { o11y } = client.project({ id: process.env.FINAL_PROJECT_ID! });
```

## Agent judges

An agent judge references an agent published in the project, by name, and pins the content hash production runs use. The agent is the whole evaluator: its instructions are the rubric, its recommended harness and model are what it judges with, and its spend is its own model use, billed to the project in Final credits and held to the budgets and spending restrictions that apply to it. You version it the way you version any agent: edit it, try it, and [publish](/operate/publishing).

```ts
import { JudgeResponseKind, JudgeScope, JudgeType } from '@finalai/agents/o11y';

const grounded = await o11y.judges.createJudge({
  name: 'Grounded answer',
  definition: {
    type: JudgeType.Agent,
    scope: JudgeScope.Trace,
    agent: { name: 'grounding-judge', hash: 'sha256:…' },
    responseKind: JudgeResponseKind.Categorical,
    choices: [
      { label: 'Grounded', description: 'Every claim is supported by a tool result.' },
      { label: 'Unsupported claim', description: 'At least one claim has no supporting tool result.' },
    ],
  },
});
```

For each evaluation, Final freezes a snapshot of the evidence and starts a short session of the agent at the pinned hash, with the evidence in its prompt and the labels it may return. The agent answers with a structured verdict: a label, score or pass/fail, a reason, and citations of the spans it relied on. Final checks each citation against the snapshot and asks the agent to fix a verdict that doesn't hold up once. The judging session is linked from the result, so you can read how the judge reasoned.

The judge agent needs a recommended harness with a model; it is started with no compute and no integrations, so give it no tools that need them. Leave out `hash` and the judge follows the name's latest publication, which suits a judge you're still writing but not one in production.

To change the rubric, publish the agent again and pass the new hash to `runJudge` as `evaluatorVersion` to compare results on the same traces. When you're satisfied, pin it with `updateJudge`. Test suites keep checking with the hash they pinned until you [repin them](/o11y/experiments#repin-checks).

## Deterministic judges

Conditions combine with `and` and `or`; a nested group is a parenthesis. Fields are `duration_ms`, `cost_usd`, `error`, `span_name` and `attribute` (with `attributeKey`). Operators are `eq`, `ne`, `lt`, `lte`, `gt`, `gte`, `in`, `not_in`, `contains`, `not_contains`, `exists`, `not_exists` and `matches`. A group holds up to 50 conditions.

```ts
import { ConditionField, ConditionJoin, ConditionOperator, JudgeScope, JudgeType } from '@finalai/agents/o11y';

await o11y.judges.createJudge({
  name: 'Slow or failed',
  definition: {
    type: JudgeType.Deterministic,
    scope: JudgeScope.Trace,
    conditions: {
      join: ConditionJoin.Or,
      conditions: [
        { field: ConditionField.DurationMs, op: ConditionOperator.Gt, value: 30_000 },
        { field: ConditionField.Error, op: ConditionOperator.Eq, value: true },
        {
          field: ConditionField.Attribute,
          attributeKey: 'gen_ai.tool.name',
          op: ConditionOperator.Eq,
          value: 'issue_refund',
        },
      ],
    },
  },
});
```

On a trace, a condition on span names or attributes holds when any span satisfies it, and its negation (`ne`, `not_in`, `not_contains`, `not_exists`) holds when no span does. Attribute keys are [span attribute](/o11y/reference/attributes) names. Deterministic judges call no model, so they cost nothing to run.

## Code judges

A code judge is TypeScript kept in the project's Files repository, in its own folder under `o11y/judges/`. Its git commits are its versions: pin one, or leave the pin out to run the latest commit that changed the folder.

The folder's `index.ts` is the judge, and it must be self-contained. Its default export is a function, or a class with an `evaluate` method, that takes `{ evidence, target, env }` and returns a verdict:

```ts index.ts
interface SpanIface {
  spanId: string;
  name: string;
  attributes: Record<string, unknown>;
}

interface InputIface {
  evidence: { spans: SpanIface[]; missing: string[]; truncated: boolean };
  env: Record<string, string>;
}

export default (input: InputIface) => {
  const root = input.evidence.spans.find((span) => span.name.startsWith('invoke_agent'));
  const messages = root?.attributes['gen_ai.output.messages'];
  if (root == null || messages == null) return { insufficientEvidence: true, reason: 'No output.' };
  const length = JSON.stringify(messages).length;
  const passed = length <= 4_000;
  return {
    label: passed ? 'Pass' : 'Fail',
    passed,
    reason: `The answer is ${length} characters long.`,
    citations: [{ spanId: root.spanId }],
  };
};
```

- **`evidence.spans`** are the target's spans, each with `spanId`, `parentSpanId`, `name`, `kind`, `startTime`, `endTime`, `statusCode`, `errorMessage`, `model`, `attributes` and `events`. Long values may be cut to fit; `truncated` and each span's `truncatedKeys` say where.
- **`target`** is what's being judged: its `kind` and `traceId`, `spanId` or `sessionId`.
- **`env`** holds the environment variables you mapped to project secrets.
- **The verdict** has `label` (categorical and binary), `score` (numeric), `passed` (binary), `reason`, and `citations` of `{ spanId, quote? }`. Return `insufficientEvidence: true` when the evidence can't decide.

A code judge runs in an isolate with no network access, no bindings and a 5-second CPU limit.

Create the judge, then commit its source with `setCodeJudgeSource`, which replaces the files in its folder in one commit. `secrets` maps environment variable names to [project secrets](/o11y/settings#project-secrets) by name; values are never sent or returned.

```ts
import { JudgeResponseKind, JudgeScope, JudgeType } from '@finalai/agents/o11y';
import { readFile } from 'node:fs/promises';

const judge = await o11y.judges.createJudge({
  name: 'Answer length',
  definition: { type: JudgeType.Code, scope: JudgeScope.Trace, responseKind: JudgeResponseKind.Binary },
});

const source = await o11y.judges.setCodeJudgeSource({
  judgeId: judge.judgeId,
  files: [{ path: 'index.ts', content: await readFile('./index.ts', 'utf8') }],
  message: 'First version',
});

// Pin production runs to this commit.
await o11y.judges.updateJudge({
  judgeId: judge.judgeId,
  definition: {
    type: JudgeType.Code,
    scope: JudgeScope.Trace,
    responseKind: JudgeResponseKind.Binary,
    commit: source.commit,
  },
});
```

`getCodeJudgeSource({ judgeId, commit })` reads the files at any commit. Because the source is an ordinary folder in the project's Files, you and your agents can also edit it there; the next run picks up the new commit unless the judge is pinned.

## External judges

An external judge holds results you submit: user feedback on Final sessions, reviews from your support team, or scores from evaluators you run yourself. Its output shape is fixed when you create it.

```ts
import { EvaluationTargetKind, JudgeResponseKind, JudgeScope, JudgeType } from '@finalai/agents/o11y';

const feedback = await o11y.judges.createExternalJudge({
  name: 'User feedback',
  definition: {
    type: JudgeType.External,
    scope: JudgeScope.Session,
    responseKind: JudgeResponseKind.Binary,
    choices: [{ label: 'Helpful' }, { label: 'Not helpful' }],
  },
});

await o11y.judges.submitJudgeResult({
  judgeId: feedback.judgeId,
  target: { kind: EvaluationTargetKind.Session, sessionId: 'ases_…' },
  value: { label: 'Not helpful' },
  reason: 'The customer said the refund policy was wrong.',
});
```

A target is a trace, a span, a session or a conversation. Submitting again for the same target replaces the current result and keeps the earlier ones as history (`listJudgeResults({ includeHistory: true })`). `metadata` carries your own fields, and `citations` can point at spans. Submitted results trigger no other judges and start no actions.

## Choose the agents and workflows it judges

By default, a judge's [online evaluation](/o11y/online-evaluation) takes every agent's turns and every workflow's runs in the project. `appliesTo` narrows it to the published agents and workflows you name, each by ID or by name (up to 50 of each):

```ts
import { JudgeResponseKind, JudgeScope, JudgeType } from '@finalai/agents/o11y';

const refunds = await o11y.judges.createJudge({
  name: 'Refund policy followed',
  definition: {
    type: JudgeType.Agent,
    scope: JudgeScope.Trace,
    agent: { name: 'refund-policy-judge', hash: 'sha256:…' },
    responseKind: JudgeResponseKind.Binary,
  },
  appliesTo: { agents: [{ name: 'support' }], workflows: [{ id: 'wf_…' }] },
});

// Back to every agent and workflow.
await o11y.judges.updateJudge({ judgeId: refunds.judgeId, appliesTo: null });
```

- An agent turn is taken when `agents` names its agent; a workflow run when `workflows` names its workflow. Naming only agents leaves out every workflow run, and naming only workflows leaves out every agent turn.
- Both lists empty or left out, or `appliesTo: null` on `updateJudge`, takes every agent and workflow. Leaving `appliesTo` out of `updateJudge` keeps what the judge has.
- `getJudge` returns `appliesTo` as you gave it: each entry has the `id` or the `name` you named it by, and `null` for the other. A judge that applies to everything returns `null`.

`appliesTo` is checked before the judge's [run conditions](/o11y/online-evaluation#what-conditions-see), and only for online evaluation. Runs you start yourself take the traces you choose or the [trace filter](/o11y/online-evaluation#backfills) you pass.

## Run a judge now

| Operation | What it does |
| --- | --- |
| `runJudge` | Runs one judge on up to 100 traces or sessions. `evaluatorVersion` tries another agent hash or commit before you pin it. |
| `evaluateTraces` | Runs up to 20 judges, at their pinned versions, on up to 1,000 traces. |
| `evaluateAllTraces` | Runs judges on every trace matching a filter. `dryRun: true` returns the count and cost estimate first. |
| `backfillJudge` | Runs a judge over a time range. See [backfills](/o11y/online-evaluation#backfills). |
| `cancelEvaluations` | Cancels pending or running evaluations by ID or batch. |

Each returns a batch with its `batchId`, target count and cost estimate. None of them publishes `o11y.judge.matched`, so they never start [actions](/o11y/actions).

## Results

`listEvaluations` and `getEvaluation` return each result with its value (label, score or pass/fail), reason, citations, model, cost, latency, the sampling rate in force, the trigger (`online`, `backfill`, `manual`, `test` or `rescore`), the exact `evaluatorVersion`, and for agent judges the judging session. Filter by judge, evaluator version, trace, session, batch, review session, label, trigger or status.

| Status | Meaning |
| --- | --- |
| `pending`, `running` | Not finished. |
| `value` | The judge produced a value. |
| `insufficient_evidence` | The evidence couldn't support a verdict. Never counted as a pass or a fail. |
| `evaluator_error` | The judge failed, such as a code judge that threw or an agent that returned no valid verdict. |
| `timeout` | The judge ran past its deadline. |
| `skipped_rate_limited` | Over the project's evaluation rate. Recorded, never silently dropped. |
| `skipped_budget` | The judge agent's budget or spending restriction refused the spend. |
| `cancelled` | Cancelled before it finished. |

Each citation links to its span as `final://o11y/<project>/trace/<trace>#span=<span>`; `evidenceLink` from `@finalai/agents/o11y` builds the same link.

## Labels

A label is one of a judge's outputs. Each has a description, an optional category, a rate over the last 7 days, its last application and a time series (`getLabelAnalytics`). `updateJudgeLabel` changes the description or category. Labels index your traces: filter `searchTraces` by `labels`, join `labels` and `scores` in [SQL](/o11y/dashboards-and-sql), and chart `getLabelDistribution` and `getLabelRelations`.

Deleting a judge stops its online evaluation; its past results remain.
