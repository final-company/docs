An issue is a recurring failure in your agents or workflows, backed by evidence. Each issue is a **Task** in the project, labeled `o11y: issue`, plus a fingerprint Observability keeps for it: the key detection matches it by, its evidence, incidents over time, and the judge that monitors it. You triage an issue the way you work any Task: comment, assign, follow, complete or cancel it. Observability moves the Task when the failure stops or comes back.

## What an issue holds

| Field | What it holds |
| --- | --- |
| `title` | A short name for the failure. It's the Task's title. |
| `observed` | What the evidence shows, as fact. |
| `suspectedCause` | Why it happens. Kept apart from what was observed, and it must cite evidence in `suspectedCauseCitations`. |
| `impact`, `consider` | Who is affected, and what to look at. |
| `severity` | `critical`, `high`, `medium` or `low`. |
| `trend` | `first_seen`, `ongoing` or `regressed`. |
| `evidence` | Cited traces and spans, each with an optional note, quote and `final://o11y/…` link. |
| `incidents` | How often it was seen, over time. |
| `monitorJudgeId`, `monitorLabelId` | The judge and label that track it. |
| `issueKey` | The key detection updates it by, instead of opening a duplicate. |
| `taskId` | The Task it's triaged on. |

## Create an issue

Detection opens most issues. You, the [o11y agent](/o11y/agent) or your own code can also open one:

```ts
import { IssueSeverity } from '@finalai/agents/o11y';

const issue = await o11y.issues.createIssue({
  title: 'Quotes the old refund window',
  issueKey: 'refund-policy/wrong-window',
  severity: IssueSeverity.High,
  observed: 'The agent quotes a 14-day refund window in 12 turns since Monday.',
  suspectedCause: 'The policy lookup returns the archived policy page.',
  suspectedCauseCitations: [
    { traceId: '4bf92f3577b34da6a3ce929d0e0e4736', spanId: '00f067aa0ba902b7' },
  ],
  evidence: [{ traceId: '4bf92f3577b34da6a3ce929d0e0e4736', note: 'Quotes 14 days.' }],
});
console.log(issue.taskId, issue.status);
```

Creating an issue with the `issueKey` of an existing one adds to it instead. `addIssueEvidence` cites more traces, `updateIssue` changes the severity and the text, and `mergeIssues` folds duplicates into one issue. Status, assignee and comments belong to the Task, so change them there.

## Status

An issue's status reads its Task together with what Observability has seen:

| Status | Meaning |
| --- | --- |
| `needs_review` | The Task is open and nobody has settled it. A failed Task (the fix didn't work) also comes back here. |
| `monitored` | A judge and label are linked, and the judge runs online with sampling above 0. |
| `regressed` | Seen again after it was settled. Its Task is reopened. |
| `dismissed` | Its Task was cancelled by a person. Detection doesn't reopen it. |
| `inactive` | No new evidence for the stale window, so Observability cancelled its Task. It comes back as `regressed` if seen again. |
| `resolved` | The Task was completed, or Observability completed it because the monitored label stayed at zero for the stale window. |
| `merged` | Merged into another issue, which carries on. Final. |

## Monitor with a judge

Link a judge and one of its labels to an issue. Once the judge runs [online](/o11y/online-evaluation) with sampling above 0, the issue is `monitored`: Observability watches the label's rate, resolves the issue when the label stays at zero for the stale window, and marks it `regressed` when the label fires again.

```ts
await o11y.issues.monitorIssueWithJudge({
  issueId: 'oiss_…',
  judgeId,
  labelId: 'olbl_…',
});
```

## Detection

Detection opens and updates issues on its own. It has two parts, both set with `updateIssueDetection` or in **Observability** > **Issues** > **Detection**.

**Agentic detection** is an [agent schedule](/build/schedules): the detection agent, `final/o11y-detection`, runs on your schedule with your instructions, reads the period since its last run, and files or updates issues with cited evidence. It runs as the person who set it up, and its runs are that schedule's runs.

**Deterministic detectors** are fixed SQL over the [catalog](/o11y/dashboards-and-sql#catalog), run every hour. Each compares the last hour with the 24 before it:

| Detector | Opens an issue when | Threshold (default) |
| --- | --- | --- |
| `error_spike` | The error rate of agent turns rises well above its baseline. | Multiple of the baseline rate (3) |
| `judge_failure_rate` | A judge's failing-label rate rises. | Absolute rise in the rate (0.2) |
| `cost_outlier` | Agent turns cost far more than usual. | Robust z-score (5) |
| `latency_outlier` | Agent turns take far longer than usual. | Robust z-score (5) |

```ts
import { IssueDetector, ScheduleKind } from '@finalai/agents/o11y';

await o11y.issues.updateIssueDetection({
  agentic: {
    enabled: true,
    instructions: 'Refund and billing failures matter most.',
    schedule: { kind: ScheduleKind.Daily, timeOfDay: '08:00', timezone: 'America/New_York' },
  },
  deterministic: [
    { detector: IssueDetector.ErrorSpike, enabled: true },
    { detector: IssueDetector.CostOutlier, enabled: true, threshold: 6 },
  ],
  staleAfterDays: 14,
});
```

`schedule.kind` is `daily` or `weekly` (with `timeOfDay`, and `weekday` for weekly), `interval` (`intervalMinutes`, 15 to 1,440) or `cron`, always with an IANA `timezone`. `model` picks the model agentic detection runs on. `runIssueDetection` runs detection now, `stopIssueDetection` stops a run, and `getIssueDetection` returns the settings, the agent schedule's ID, and the last and next run.

`staleAfterDays` (1 to 365) turns on the stale rule, and `null` turns it off. Without it, issues never go `inactive`, and a monitored issue is resolved after its label stays at zero for 10 days.

## Events

Every change publishes an event to the project's feed: `o11y.issue.created`, `o11y.issue.updated`, `o11y.issue.regressed` and `o11y.issue.resolved`, each with the issue's ID, title, severity and status. Start a workflow from one, such as paging on-call when a critical issue regresses. See [actions](/o11y/actions#events).
