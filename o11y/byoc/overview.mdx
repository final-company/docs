By default Final hosts all of Observability. With a BYOC (bring your own cloud) data plane, telemetry and evaluation content stay in your AWS account, while Final's hosted control plane keeps configuration, judges, agents and the console. Ingest, storage and queries run on infrastructure you own.

## Architecture

| | Data plane (your AWS account) | Control plane (Final) |
| --- | --- | --- |
| Runs | Ingest (OTLP and observations), durable storage, processing into searchable traces, evidence reads, SQL queries, deletion | Configuration and versions, evaluation scheduling and judges, actions, alignment, datasets, tests, issues, dashboards, agents, usage, events, the console and MCP tools |
| Stores | Raw batches and attachments (S3), traces, spans, observations, scores and the SQL catalog (ClickHouse), ingest state and checkpoints (PostgreSQL) | Configuration, versions, job state, IDs, metrics and references to content in the data plane |

Your apps still send to `https://api.final.ai/v1/o11y/otlp` with the same keys. Final's edge checks the key and forwards telemetry to your data plane, which stores it before acknowledging. Nothing else about instrumentation changes.

## The content boundary

**In your data plane:** span payloads (inputs, outputs, model context, attributes), observations, attachments, dataset example payloads, judge reasons and citations.

**In Final's control plane:** configuration (judges, rubrics, run settings, actions, datasets' schemas, suites, dashboards, saved queries), versions, job state, IDs, metrics such as counts, rates, costs and latencies, and references to content in the data plane. Issue text that the detection agent or a person writes, such as the observed facts and suspected cause, and judge rubrics live in the control plane.

The control plane reads content only through your data plane's evidence API, when work needs it: a judge evaluating a trace, the observability agent reading a span, or the console showing one. The data plane accepts these calls only from Final's control plane; see [signed calls](#signed-calls). Judges and agents that use models send the evidence they read to the named model, as in managed mode.

## How it connects

<Steps>
  <Step title="Deploy">
    [Deploy the data plane](/o11y/byoc/aws) in your AWS account. It runs as containers behind your load balancer and TLS certificate.
  </Step>
  <Step title="Register">
    An organization admin registers the data plane's endpoint, region and public key with `register_data_plane`. From then on, telemetry goes to it. An organization has one data plane: registering another, in a new region say, revokes the previous registration.
  </Step>
  <Step title="Operate">
    `get_data_plane` shows its status (`pending`, `active`, `unreachable` or `revoked`) and when Final last reached it. See the [runbooks](/o11y/byoc/runbooks).
  </Step>
</Steps>

## Signed calls

Every call between Final's control plane and your data plane is signed, in both directions: Final's evidence reads, queries and deletions, and the data plane's reports back to Final. The sender signs each request as a compact JWS with EdDSA (Ed25519). The signature covers the method, the path, a SHA-256 digest of the exact body, the time and a one-time nonce. The receiver verifies it with the sender's pinned public key, and refuses a request that is signed for another method, path or body, signed more than five minutes from its own clock, or replayed.

Each side pins the other's public key when you set the data plane up. Final pins the data plane's key when you register it with `register_data_plane`, and your deployment pins Final's control plane keys, which you confirm with Final out of band. A request signed with any other key is refused. TLS on your load balancer protects the connection; the signatures authenticate each request.

## What stays the same

Every API operation, SDK method, CLI command and MCP tool works the same in both modes. Retention, deletion, redaction and mappers run in your data plane, and SQL queries run against your ClickHouse, scoped to each project by the database.
