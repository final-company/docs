Final Observability shows what your [Final agents](/agent-sdk) and [AI Workflows](/workflows/overview) did, scores it, and turns failures into tests and fixes. Final records every agent turn and every workflow run as it happens, so there's nothing to instrument: Observability reads those records in place, as OpenTelemetry traces.

```ts
import { createClient } from '@finalai/agents/client';

const client = createClient({ auth: { apiKey: process.env.FINAL_API_KEY! } });
const { o11y } = client.project({ id: process.env.FINAL_PROJECT_ID! });

const { items } = await o11y.traces.searchTraces({ filter: { agentIds: ['adef_…'] }, limit: 10 });
for (const trace of items) console.log(trace.name, trace.status.code, trace.durationMs, trace.costUsd);
```

Every operation is available four ways, all generated from one inventory in `@finalai/agents/o11y`: the `project.o11y` client in `@finalai/agents`, the `final-agents o11y` CLI, the HTTP API at `https://agent-session.final.ai/api/v1/o11y`, and [tools on the Final MCP gateway](/o11y/mcp) that your coding agent or the [o11y agent](/o11y/agent) can call. `final-agents o11y openapi --out openapi.json` writes the HTTP API as an OpenAPI 3.1 document, with each operation's scope.

## Concepts

| Term | What it means |
| --- | --- |
| **Trace** | One agent turn or one workflow run, as OpenTelemetry spans that follow the GenAI semantic conventions. A turn is an `invoke_agent` root with a `chat` span per model call and an `execute_tool` span per tool call; a workflow run is a `workflow` root with a span per step. See [traces and span attributes](/o11y/reference/attributes). |
| **Session** | The turns of one Final session, sharing `gen_ai.conversation.id`. |
| **Judge** | An evaluator that scores a span, a trace or a session. An `agent` judge is a published Final agent, a `deterministic` judge is conditions, a `code` judge is TypeScript in the project's Files, and an `external` judge holds results you submit. See [judges](/o11y/judges). |
| **Label** | One of a judge's outputs, such as `Pass` or `Unsupported claim`. Labels have rates and time series, and they index your traces for search and SQL. |
| **Evaluation** | One judge's result on one target, with its value, reason, citations, cost and the exact evaluator version. [Online evaluation](/o11y/online-evaluation) scores turns and runs as they finish. |
| **Dataset** | A JSON Lines file in the project's Files repository; its versions are git commits. See [datasets](/o11y/datasets). |
| **Test suite** | Versioned cases with checks against judges. A run rescores stored traces, or runs a published agent or workflow on every case as an experiment. See [experiments and CI](/o11y/experiments). |
| **Issue** | A recurring failure: a Task in the project labeled `o11y`, plus the fingerprint Observability keeps for it. See [issues](/o11y/issues). |
| **Action** | An AI Workflow that a judge's matches start, through the `o11y.judge.matched` event. See [actions](/o11y/actions). |

## How it fits together

<Steps>
  <Step title="Read traces">
    Every turn and run is already a trace. Search them, open the waterfall, and compare agent versions in the console under **Observability**, or with `o11y.traces`.
  </Step>
  <Step title="Judge">
    Publish a judge agent or write conditions or code, then turn on [online evaluation](/o11y/online-evaluation). Check judges against people with [alignment](/o11y/alignment).
  </Step>
  <Step title="Act">
    [Actions](/o11y/actions) start AI Workflows when a judge matches. [Issue detection](/o11y/issues) runs on a schedule and opens Tasks for recurring failures.
  </Step>
  <Step title="Test">
    Turn failures into [test cases](/o11y/experiments), run experiments against new agent and workflow revisions, and gate CI with `final-agents o11y test run`.
  </Step>
  <Step title="Analyze and export">
    Query traces and results with [SQL](/o11y/dashboards-and-sql), build dashboards, ask the [o11y agent](/o11y/agent), and [export traces over OTLP](/o11y/trace-export) to your own collector.
  </Step>
</Steps>
