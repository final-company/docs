Final Observability records what your AI agents and workflows do, scores it, and turns failures into tests and fixes. It works with agents that run anywhere: send OpenTelemetry from any language, or use the TypeScript SDK. Final's own agents and workflows report through the same interfaces.

```ts
import { SpanKind, init, observe, setSession } from '@finalai/o11y/node';
import { wrapOpenAI } from '@finalai/o11y/integrations';
import OpenAI from 'openai';

init({ environment: 'production' }); // reads FINAL_API_KEY

const openai = wrapOpenAI(new OpenAI());

export const answer = observe(
  async (question: string, conversationId: string) => {
    setSession(conversationId);
    const response = await openai.chat.completions.create({
      model: 'gpt-5.1',
      messages: [{ role: 'user', content: question }],
    });
    return response.choices[0]?.message.content;
  },
  { name: 'answer', kind: SpanKind.Agent },
);
```

Every operation is available four ways, all generated from one contract: the HTTP API under `https://api.final.ai/v1/o11y`, the `@finalai/o11y` SDK, the `final-o11y` CLI, and [Final MCP tools](/o11y/mcp) that your coding agent or the observability agent can call.

## Concepts

| Term | What it means |
| --- | --- |
| **Trace** | One unit of work, such as an agent turn or a workflow run, as a tree of spans. Each span has a kind (`llm`, `tool`, `function`, `agent`, `generator` or `span`), input, output, usage and cost. |
| **Session** | The traces of one conversation or thread, grouped by `final.session_id` on each root span. |
| **Trace health** | Checks that each trace is complete enough to evaluate: one root, valid timing, inputs and outputs, models, usage and cost. See [trace health](/o11y/reference/trace-health). |
| **Judge** | An evaluator that scores spans, traces or sessions. Judges are agentic (a model with a rubric), deterministic (conditions), code (TypeScript), or external (results you submit). See [judges](/o11y/judges). |
| **Label** | One of a judge's possible outputs, such as `Hallucinated` or `Matched`. Labels have rates and time series, and they index your traces for search, SQL and the agent. |
| **Evaluation** | One judge version's result on one target, with its value, reason, citations, cost and provenance. Online evaluation runs production judge versions on new traces. |
| **Dataset** | Versioned rows with a JSON Schema, built from traces, files or judge reviews. See [datasets and prompts](/o11y/datasets-and-prompts). |
| **Test suite** | Versioned cases with checks against judge results. Runs score your agent, compare against a baseline, and gate CI. See [tests](/o11y/tests). |
| **Issue** | A recurring failure with cited evidence, severity, status and a monitoring judge. Detection opens issues; you triage them and hand them to a coding agent. See [issues](/o11y/issues). |
| **Observability agent** | A Final agent with every Observability tool, for investigation in chat, on a schedule, or in Slack. See [the observability agent](/o11y/agent). |
| **Data plane** | Where ingest, telemetry, attachments and evaluation outputs live. Final hosts it by default; you can run it in your own AWS account. See [BYOC data plane](/o11y/byoc/overview). |

## How it fits together

<Steps>
  <Step title="Send traces">
    Instrument with the [TypeScript SDK](/o11y/quickstart), any [OpenTelemetry SDK or Collector](/o11y/quickstart-otlp), or [Workers](/o11y/quickstart-workers). For [Final agents and workflows](/o11y/final-agents-and-workflows), turn on the native producers.
  </Step>
  <Step title="Check trace health">
    Fix what the health checks report, so judges see complete evidence.
  </Step>
  <Step title="Score">
    Create judges, publish a version, and turn on [online evaluation](/o11y/online-evaluation). [Actions](/o11y/judge-actions) start workflows, notify people, post to Slack, or add traces to datasets when a judge matches.
  </Step>
  <Step title="Find and fix">
    Detection opens [issues](/o11y/issues). Monitor each with a judge, turn failures into [test cases](/o11y/tests), and gate changes in [CI](/o11y/tests-in-ci).
  </Step>
</Steps>
