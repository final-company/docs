Observability publishes lifecycle events to a per-project feed. Read the feed, or have it delivered to webhooks. `LifecycleEventKind` in `@finalai/o11y/contract` names each kind.

## Kinds

| Kind | When |
| --- | --- |
| `o11y.judge.matched` | An online result from a judge's production version matched. Fires on every match, whether or not an action group fires. |
| `o11y.judge.version_promoted` | A judge version became the production version. |
| `o11y.evaluation.failed` | An evaluation ended in an error or timeout. |
| `o11y.issue.created` | An issue was opened. |
| `o11y.issue.updated` | An issue's status, severity or content changed. |
| `o11y.issue.regressed` | A monitored or inactive issue was seen again. |
| `o11y.issue.resolved` | A monitored issue's label stayed at zero for the stale window. |
| `o11y.test_run.completed` | A test run finished. |
| `o11y.dataset.version_created` | A dataset changed. |
| `o11y.usage.threshold_crossed` | A usage alert threshold was crossed. |
| `o11y.deletion.completed` | A deletion request finished purging. |

## Read the feed

```bash
curl -sS "https://api.final.ai/v1/o11y/projects/$FINAL_PROJECT_ID/events?kinds=o11y.issue.created&limit=50" \
  -H "Authorization: Bearer $FINAL_API_KEY"
```

`list_events` returns events in order, filtered by `kinds` and time (`from`, `to`), with `nextCursor` for the next page. Each event has `eventId`, `kind`, `occurredAt` and `data`. It needs `o11y:read`.

## Webhooks

Create a subscription with an HTTPS URL and the kinds to deliver. The response includes a signing secret, shown once:

```ts
import { LifecycleEventKind } from '@finalai/o11y/contract';

const subscription = await project.admin.createEventSubscription({
  url: 'https://hooks.example.com/final',
  kinds: [LifecycleEventKind.IssueCreated, LifecycleEventKind.IssueRegressed],
  description: 'Incident tooling',
});
// subscription.signingSecret is shown only here: store it now.
```

Each delivery is a `POST` of a batch of up to 100 events:

```json
{
  "subscription": "…",
  "events": [
    {
      "id": "…",
      "kind": "o11y.issue.created",
      "createdAt": "2026-11-19T10:00:00Z",
      "organizationId": "…",
      "projectId": "…",
      "data": {}
    }
  ],
  "cursor": "…"
}
```

Deliveries are signed per [Standard Webhooks](https://www.standardwebhooks.com/), with `webhook-id`, `webhook-timestamp` and `webhook-signature` headers and the subscription's `whsec_` secret. Verify the signature with any Standard Webhooks library before trusting a delivery, and pass the body exactly as received. `webhook-id` identifies the batch, so use each event's `id` to deduplicate.

A failed delivery is retried with backoff, from 10 seconds up to an hour between attempts. The subscription shows `failing` meanwhile, and one that keeps failing for 3 days is paused.

| Operation | What it does |
| --- | --- |
| `update_event_subscription` | Change the URL, kinds or description, or pause with `paused: true`. |
| `replay_events` | Redeliver past events in a time range to a subscription. |
| `delete_event_subscription` | Stop delivering. |
| `list_event_subscriptions` | List subscriptions with their status: `active`, `paused` or `failing`. |

## Workflows

To run a workflow when a judge matches, use a [`start_workflow` action](/o11y/judge-actions#targets). For other kinds, subscribe a workflow's [webhook URL](/workflows/triggers#webhooks): each delivery starts a run with the delivery body as its input, so the workflow's input schema must accept it.

There is no email channel. To email someone about an event, start a workflow that sends the email.
