Every Observability operation is a tool on the Final MCP gateway. Connect Claude Code, Codex, Cursor or any MCP client to Final, and your coding agent can read your agents' traces, write judges, run experiments and fix issues in the same session where it edits your agents and workflows.

## Connect a coding agent

Observability tools come through the same server as the rest of Final's MCP gateway:

```text
https://api.final.ai/v1/connectors/mcp
```

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http --scope user final https://api.final.ai/v1/connectors/mcp
    ```

    Start Claude Code, run `/mcp`, select **final** and sign in.
  </Tab>
  <Tab title="Codex">
    ```bash
    codex mcp add final --url https://api.final.ai/v1/connectors/mcp
    codex mcp login final
    ```
  </Tab>
  <Tab title="Cursor">
    ```json ~/.cursor/mcp.json
    {
      "mcpServers": {
        "final": {
          "url": "https://api.final.ai/v1/connectors/mcp"
        }
      }
    }
    ```

    Then sign in from Cursor's MCP server list.
  </Tab>
</Tabs>

You sign in with your Final account; no API key is needed. If you already added Final for the [MCP gateway](/mcp-gateway/quickstart), there is nothing more to set up. See that quickstart for other clients.

Then ask:

```text
Using Final, find yesterday's turns of the support agent in project prj_your_project where the
"Grounded answer" judge returned "Unsupported claim", and show me the span that caused it.
```

## How agents find the tools

Your client doesn't load every tool. It sees Final's discovery tools and searches for what it needs: `search_tools` finds a tool, `describe_tools` returns its exact input schema, and `call_tool` runs it. Observability tools have catalog paths of the form `final.o11y.<group>.<verb>`, such as `final.o11y.traces.search` for `search_traces` and `final.o11y.judges.create` for `create_judge`. Agents running on Final, including the [o11y agent](/o11y/agent) and agents your workflows start, find them the same way, through tool search.

Every tool takes `projectId`. Agents running in a Final session are confined to their own project and the projects below it.

## Tool groups

| Group | Covers |
| --- | --- |
| `final.o11y.traces` | Traces of agent turns and workflow runs, spans, sessions, conversations, comparisons and saved views. |
| `final.o11y.judges` | Judges, run settings, code judge source, labels, evaluations, backfills and external results. |
| `final.o11y.alignment` | Review sessions, reviews, alignment summaries and golden datasets. |
| `final.o11y.data` | Datasets and their examples. |
| `final.o11y.tests` | Test suites, cases, runs and comparisons. |
| `final.o11y.issues` | Issues, evidence, monitoring and detection. |
| `final.o11y.analytics` | SQL, saved queries, dashboards and charts. |
| `final.o11y.admin` | Settings, the audit log and trace export. |

The [tool reference](/o11y/mcp-tools) lists every tool with its SDK method, scope and effect. The tools are generated from the same inventory as the `project.o11y` client and the HTTP API, so they never drift apart.

## Permissions and approvals

Tools act with your project role. Read tools run without asking. Tools that write, execute or delete ask for approval when an agent session calls them: Final shows an approval card with the tool's title and the exact input, and runs exactly what you approved. See [accounts and approvals](/mcp-gateway/accounts-and-approvals).

## Useful prompts for coding agents

- "Read the open issues with `list_issues`, pick the most severe, and fix it in this repository. Cite the traces you used."
- "Create a test suite from the failing traces of issue `oiss_…`, then run it against the agent I just published with `final-agents o11y test run`."
- "Write a deterministic judge for turns that call `issue_refund` more than once, try it on last week's traces with `run_judge`, and show me what it matched."
- "Compare the last two content hashes of the support agent with `compare_traces` on cost, latency and label rates."
