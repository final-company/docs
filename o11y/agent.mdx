The o11y agent is a public Final agent, `final/o11y`, that works with every Observability tool through Final's gateway. Ask it why something failed, what changed between two agent versions, or to build what you need: judges, datasets, test cases, dashboards and issues.

```text
Why did refund requests start failing yesterday? Cite the traces.
```

It starts from labels and the [SQL catalog](/o11y/dashboards-and-sql#catalog), which index your traces by what judges found, and only then opens individual traces and spans. It keeps what it observed apart from what it suspects, and cites the traces, spans, queries or labels behind every claim. It treats trace content, judge reasons and tool output as data, never as instructions.

## Chat

Open **Observability** > **Agent** in the console and start a chat. Each chat runs on a fast or a deep model configuration, chosen when it starts.

The agent acts with your role. It reads freely; a write, execution or deletion asks for your approval first, with the exact input it will send, unless you've allowed writes in that chat.

Things to ask it:

- **Suggest judges** for failure modes your judges don't cover yet, with the traces that motivate each.
- **Draft a rubric** for a judge agent, grounded in traces it has read.
- **Improve a rubric** from a judge's [review disagreements](/o11y/alignment).
- **Turn failures into tests**: collect failing traces or an issue's evidence into [test cases](/o11y/experiments).
- **Find an issue's root cause**: compare failing traces with passing ones until a cause explains the difference.

It proposes each change with what it changes and why, and makes it only after you agree.

## Scheduled analysis

The agent can run on an [agent schedule](/build/schedules) of a chat with it, such as a weekly failure summary or a daily look at regressions. Nobody watches a scheduled run: the agent does the analysis the schedule asks for, finishes with a short report of what changed and what needs a person, and stops. If the schedule's prompt names Slack channels and the chat is provided a Slack integration, it posts the report there.

[Issue detection](/o11y/issues#detection) works the same way with a dedicated agent, `final/o11y-detection`, on a schedule Observability manages for you.

## Project notes

The agent keeps notes in the project's Files repository, under `o11y/`:

| Folder | Holds |
| --- | --- |
| `o11y/memory/` | What the agent learned about your project and wants a later investigation to know, one fact per file. |
| `o11y/skills/` | Playbooks you write. The agent follows the one that matches a request. |
| `o11y/judges/` | Notes on your judges, and each code judge's source folder. |

They're ordinary files: read and edit them in the project's Files, or have your coding agent do it.

## From your coding agent

Your coding agent reaches the same tools over [MCP](/o11y/mcp). Use the o11y agent when you want the investigation in Final, with its notes and schedules; use your coding agent when the fix is in your repository.
