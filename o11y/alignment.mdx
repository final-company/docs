---
title: "Alignment"
description: "Check a judge against people, measure agreement per label, and turn reviews into a golden dataset."
---

Before you act on a judge's results, check that people agree with it. Reviewers agree or disagree with a sample of its results; the alignment summary measures agreement per label; and the reviewed results become a golden dataset for testing the next version of the judge.

## Review sessions

A review session collects a judge's results that match a filter: a time range, an evaluator version, labels, triggers and environments, up to 1,000 results. Reviewers agree or disagree with each one, and give the correct label and a comment when they disagree. In the console, open **Observability** > **Alignment**.

```ts
import { EvaluationTrigger, ReviewVerdict } from '@finalai/agents/o11y';

const review = await o11y.alignment.createReviewSession({
  name: 'Grounding, week 47',
  judgeId,
  filter: { triggers: [EvaluationTrigger.Online], limit: 100 },
});

const { items } = await o11y.judges.listEvaluations({ reviewSessionId: review.reviewSessionId });
await o11y.alignment.submitReview({
  reviewSessionId: review.reviewSessionId,
  evaluationId: items[0]!.evaluationId,
  verdict: ReviewVerdict.Disagree,
  correctedLabelId: 'olbl_…',
  comment: 'The order number came from the lookup tool.',
});
```

`listReviews` filters by verdict, so you can read only the disagreements. Each review keeps the evaluator version it reviewed.

## Alignment summary

`getAlignmentSummary` reports, for a judge, optionally narrowed to one evaluator version or review session:

- how many results were reviewed, and the agreement rate;
- precision and recall per label;
- the confusion matrix of the judge's labels against the reviewers';
- a warning when a label has too few reviews to trust its numbers.

```ts
const summary = await o11y.alignment.getAlignmentSummary({ judgeId });
console.log(summary.agreementRate);
for (const label of summary.labels) console.log(label.label, label.precision, label.recall);
```

## Improve the judge

For an agent judge, the fix is a better rubric. Ask the [o11y agent](/o11y/agent) to improve it from the disagreements: it reads the reviews and proposes revised instructions. Publish the judge agent with them, run the new hash with `runJudge({ evaluatorVersion })` on the reviewed traces, and compare its summary with `getAlignmentSummary({ evaluatorVersion })` before you pin it. For a code judge, the same loop runs on a new commit.

## Golden datasets

`createGoldenDataset` turns reviewed results into a [dataset](/o11y/datasets) with an `expected_<judge>` column holding the reviewers' labels: the judge's label where they agreed, and the corrected one where they didn't.

```ts
const golden = await o11y.alignment.createGoldenDataset({ judgeId, name: 'Grounding golden set' });
console.log(golden.path);
```

Add its rows to a test suite with `addTestCasesFromDataset`, mapping `expected_<judge>` to a check on the judge, and every future version of the judge is tested against what people decided. See [experiments and CI](/o11y/experiments#cases-from-a-dataset).
