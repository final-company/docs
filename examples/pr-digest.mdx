Every weekday at 9 a.m., this agent reads your repository's pull requests and posts a short digest: what merged since the last one, what's been waiting on review, and which ready pull requests have failing checks. Use it to replace the "what happened yesterday?" part of standup, or to keep reviews from going stale.

**What it shows:** a [schedule](/build/schedules) declared on the agent, an [integration requirement](/build/integrations) limited to read-only tools with an annotation selector, giving the schedule what its runs need, and triggering a run with `runNow`.

Use your personal **My Work** project for this version. The schedule's default `owner-direct` target posts to your direct chat with the agent there. For a Shared project, see [make it yours](#make-it-yours).

The agent requires a `github` slot. `allowAnnotations: [{ readOnlyHint: true }]` exposes every tool the server marks as read-only, so whatever GitHub server fills the slot, the agent can search and read pull requests but can't comment, merge, or push. The schedule is a prompt with a timer: 9:00 a.m. New York time, Monday through Friday.

```ts agent.ts
import { defineAgent, markdown } from '@finalai/agents';

export const agent = defineAgent({
  name: 'PR Digest',
  description: 'Posts a weekday digest of pull request activity in acme/web.',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  require: {
    harness: { permissionMode: 'ask' },
    integrations: {
      github: {
        description: 'GitHub, to read pull requests, reviews, and checks',
        tools: { allowAnnotations: [{ readOnlyHint: true }] },
      },
    },
  },
  schedules: {
    'morning-digest': {
      cron: '0 9 * * 1-5',
      timezone: 'America/New_York',
      prompt: "Write this morning's pull request digest for acme/web.",
    },
  },
});
```

Annotation selectors rely on the server labeling its tools accurately, so use them only with servers you trust. The instructions say what a good digest looks like, so the schedule's prompt can stay short:

```markdown instructions.md
You write a short morning digest of pull request activity in the acme/web GitHub repository.

Cover these sections, in this order:
1. Merged: pull requests merged since the previous weekday at 9:00 a.m. New York time (on Mondays, since Friday). One line each, with the number, title, and author.
2. Waiting on review: open, non-draft pull requests with no review for more than one business day. Say who's been asked to review.
3. Failing checks: open, non-draft pull requests whose latest checks failed.

Link every pull request. If a section is empty, write "Nothing today" under it.
Keep the digest under 25 lines, and don't add a greeting or sign-off.
```

## Set it up

<Steps>
  <Step title="Create the project">
    Create the project the same way as in the [quickstart](/quickstart), add the files above, and export `FINAL_API_KEY` and `FINAL_PROJECT_ID` for your My Work project. `client.ts` is the same as in the quickstart.

    ```bash
    mkdir pr-digest && cd pr-digest
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    npm install --save-dev typescript tsx @types/node
    ```
  </Step>
  <Step title="Add a GitHub token">
    Create a fine-grained personal access token in GitHub with read access to the repository's **Pull requests**, **Commit statuses**, and **Contents**. In the same project in Final, add it under **Developer** > **Secrets** with the name `GITHUB_TOKEN`.
  </Step>
  <Step title="Create the integration">
    A schedule runs with nobody present to sign in, so give it an integration that authenticates with the stored token:

    ```ts setup.ts
    import { secret } from '@finalai/agents/integrations';
    import { client, project } from './client.js';

    const github = await project.integrations.create({
      name: 'github',
      mcp: { url: 'https://api.githubcopilot.com/mcp/' },
      auth: secret('GITHUB_TOKEN'),
    });
    console.log(`Created ${github.id}`);
    client.close();
    ```

    ```bash
    npx tsx setup.ts
    ```
  </Step>
  <Step title="Publish it">
    Publishing gives the agent a name in the project and creates its schedules:

    ```bash
    npx final-agents publish ./agent.ts --name pr-digest
    ```

    ```text
    published pr-digest: sha256:4be1...
    id: agt_...
    ```
  </Step>
</Steps>

## Give the schedule what it needs

A published schedule has no harness or integrations yet, so it can't run. Like every call that starts work, it needs a `provide` that meets the agent's requirements; an incomplete one is refused with `requirements_unmet`. This script sets it, then runs the schedule once so you don't have to wait for 9 a.m.:

```ts schedule.ts
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { workers } from '@finalai/agents/sandboxes';
import { client, project } from './client.js';

const agent = await project.agents.get({ name: 'pr-digest' });
const runtime = await project.sandboxes.create(workers(), { idempotencyKey: 'workers' });
const github = await project.integrations.get({ name: 'github' });

const schedules = await client.schedules.list({ agent: agent.id ?? undefined });
const digest = schedules.find((schedule) => schedule.key === 'morning-digest');
if (digest == null) throw new Error('Publish the agent first: its schedules appear when it is published');

// What every run of the schedule starts with.
await client.schedules.update({
  scheduleId: digest.id,
  provide: {
    harness: serverlessFinal({
      model: 'deepseek-v4.1-flash',
      inference: finalCredits(),
      environment: runtime.id,
    }),
    integrations: { github },
  },
});
console.log(`Next run: ${digest.nextRunAt}`);

// Run it once now instead of waiting for 9 a.m.
const run = await client.schedules.runNow({ scheduleId: digest.id });
console.log(JSON.stringify(run, null, 2));
client.close();
```

```bash
npx tsx schedule.ts
```

After a minute or so, open your direct chat with **PR Digest** in Final to read a digest like:

```text
Merged
- #1287 Add Apple Pay to checkout (@dana)
- #1291 Fix timezone offset in order history (@lee)

Waiting on review
- #1279 Migrate settings page to the new form library (@sam), waiting 3 days on @priya

Failing checks
- #1293 Bump the payments SDK to 4.2 (@renovate): e2e / checkout failed
```

To change the time or pause it, use `client.schedules.update` with `cron`, `timezone`, or `enabled: false`. See [schedules](/build/schedules#provide-what-runs-need).

## Make it yours

- **Post it in a Shared chat.** Add `target: 'bound-conversation'` to the schedule and publish in the Shared project, then connect a provider place to the chat it should post in, as described in [channels](/build/channels). Runs are refused until exactly one chat is connected.
- **Cover more repositories.** List them in `instructions.md`, and give the token read access to each one.
