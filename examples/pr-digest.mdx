Every weekday at 9 a.m., this agent reads your repository's pull requests and posts a short digest: what merged since the last one, what's been waiting on review, and which ready pull requests have failing checks. Use it to replace the "what happened yesterday?" part of standup, or to keep reviews from going stale.

**What it shows:** a [schedule](/build/schedules) written in Markdown, an MCP [connection](/build/connections) to GitHub limited to read-only tools with an annotation selector, and triggering a schedule from a script with [`runNow`](/build/schedules#run-a-schedule-now).

Use your personal **My Work** project for this version and sign in as its owner with an **organization admin** role: the GitHub connection declares a secret, so you must approve publication. The default `owner-direct` schedule target posts to your direct chat. Create the API key for My Work and register the agent there. If you are not an organization admin, use a Shared project with the `bound-conversation` option below and have an organization admin with project edit access publish it; a Shared project has no personal owner for `owner-direct`.

```ts agent/agent.ts
import { credentials, defineAgent } from '@finalai/agents';
import { serverlessFinal } from '@finalai/agents/harnesses';

export default defineAgent({
  name: 'PR Digest',
  description: 'Posts a weekday digest of pull request activity in acme/web.',
  harness: serverlessFinal({
    credentials: credentials.chain({
      payer: 'organization',
      tryInOrder: [credentials.platform()],
    }),
    permissionMode: 'auto',
  }),
});
```

The connection points at GitHub's MCP server. Instead of naming each tool, `allow: [{ readOnlyHint: true }]` exposes every tool the server marks as read-only, so the agent can search and read pull requests but can't comment, merge, or push:

```ts agent/connections/github.ts
import { defineMcpClientConnection } from '@finalai/agents';

export default defineMcpClientConnection({
  url: 'https://api.githubcopilot.com/mcp/',
  description: "GitHub's MCP server, limited to tools that only read.",
  auth: { secretKey: 'github-token', headerName: null },
  tools: { allow: [{ readOnlyHint: true }] },
});
```

The schedule is a prompt with a timer. It runs at 9:00 a.m. New York time, Monday through Friday, and posts to the agent owner's direct conversation:

```markdown agent/schedules/morning-digest.md
---
cron: '0 9 * * 1-5'
timezone: America/New_York
---

Write this morning's pull request digest for acme/web.
```

The instructions say what a good digest looks like, so the schedule's prompt can stay short:

```markdown agent/instructions.md
You write a short morning digest of pull request activity in the acme/web GitHub repository.

Cover these sections, in this order:
1. Merged: pull requests merged since the previous weekday at 9:00 a.m. New York time (on Mondays, since Friday). One line each, with the number, title, and author.
2. Waiting on review: open, non-draft pull requests with no review for more than one business day. Say who's been asked to review.
3. Failing checks: open, non-draft pull requests whose latest checks failed.

Link every pull request. If a section is empty, write "Nothing today" under it.
Keep the digest under 25 lines, and don't add a greeting or sign-off.
```

## Build and publish it

<Steps>
  <Step title="Set up the project">
    Create the project the same way as in the [quickstart](/quickstart), then add the files above:

    ```bash
    mkdir pr-digest && cd pr-digest
    git init
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    npm install --save-dev typescript tsx @types/node
    printf 'node_modules/\n.final/\n.env*\n' > .gitignore
    ```
  </Step>
  <Step title="Add a GitHub token">
    Create a fine-grained personal access token in GitHub with read access to the repository's **Pull requests**, **Commit statuses**, and **Contents**. In the same My Work project in Final, add it under **Developer** > **Secrets** with the name `github-token`.
  </Step>
  <Step title="Compile it">
    ```bash
    npx final-agents build ./agent
    ```

    The summary shows the connection and the schedule with its time zone:

    ```text
    agent: PR Digest
    description: Posts a weekday digest of pull request activity in acme/web.
    harness: package:@finalai/final-agent-provider/harnesses/serverless-final
    mcp servers: github (http)
    ...
    schedules: morning-digest (0 9 * * 1-5, America/New_York)
    secrets: github-token
    ...
    wrote agent/.final/compile
    ```
  </Step>
  <Step title="Register and publish it">
    Register the `pr-digest` slug once in My Work, as in the [quickstart](/quickstart#register-the-agent), substituting that slug and the name **PR Digest**. Its GitHub connection declares a secret, so publication needs an organization admin who can edit this project.

    Save the [`upload-draft.ts` script](/operate/publishing#publish-code-that-uses-secrets) beside `agent/`, then upload this initial draft with your project API key:

    ```bash
    node upload-draft.ts pr-digest agent.ts instructions.md connections/github.ts schedules/morning-digest.md
    ```

    Ask that admin to review the uploaded files in the agent's **Code** view in Final and choose **Save and publish**. Uploading and compiling do not activate the schedule; it starts when published. Future source changes also use that admin's Code view, rather than API-key CI publishing.
  </Step>
</Steps>

## Try it

You don't have to wait for 9 a.m. This script requests one run and prints its receipt. Read the finished digest in your direct chat with **PR Digest** in Final; the publishing API key does not provide person-owned conversation history or events.

```ts run-now.ts
import { createClient } from '@finalai/agents/client';

const client = createClient({
  host: 'https://agent-session.final.ai/api',
  auth: { apiKey: process.env.FINAL_API_KEY! },
});

try {
  const run = await client.schedules.runNow({ agent: 'pr-digest', key: 'morning-digest' });
  console.log(JSON.stringify(run, null, 2));
  console.log('Open your direct chat with PR Digest in Final to read the result.');
} finally {
  client.close();
}
```

```bash
npx tsx run-now.ts
```

After a minute or so, open Final to read a digest like:

```text
Merged
- #1287 Add Apple Pay to checkout (@dana)
- #1291 Fix timezone offset in order history (@lee)

Waiting on review
- #1279 Migrate settings page to the new form library (@sam), waiting 3 days on @priya

Failing checks
- #1293 Bump the payments SDK to 4.2 (@renovate): e2e / checkout failed
```

## Make it yours

- **Post it in a Shared chat.** Add an authored channel and set `target: bound-conversation` in the schedule **before publishing**, especially if the agent belongs to a Shared project. Publish, then connect the provider place to the intended Shared chat as described in [channels](/build/channels#link-a-person-and-connect-a-place). Runs are refused until exactly one chat is connected. If the agent is already published, publish again to activate the target change. All active chat routes for that agent must select the same chat; observe routes do not choose the schedule target.
- **Cover more repositories.** List them in `instructions.md`, and give the token read access to each one.
