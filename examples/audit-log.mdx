This example is an ops assistant that can reach every service connected to your Final project, with an audit trail of what it did. A hook records each tool call, each approval request and its answer, and each finished turn to Datadog, with the session and the person who asked. A second hook reports failed turns to your incident tool. Use this pattern for any agent that takes real actions, so you can answer "who did what, and who approved it?" later.

**What it shows:** serverless [lifecycle hooks](/build/hooks) for `tool_call_update`, `decision.created`, `decision.resolved`, and `turn.ended`, and an [integration slot](/build/integrations) that the caller fills with Final's gateway, which gives the agent the tools of your connected services.

### The agent and its hooks

A hook watches the session without changing it. Both hooks here are serverless: their code is part of the agent and runs on Final, so the audit trail keeps working whoever starts the agent and whether or not your process is running. Serverless code can't import helpers or use variables from outside the function, so the Datadog call lives inside the hook.

- `tool_call_update` fires each time a tool call's status changes. The hook logs only `completed` and `failed`, so each call is logged once.
- `decision.created` and `decision.resolved` record each approval request and its answer.
- `turn.ended` records why each turn ended. The `report_failures` hook also sends failed turns to an incident webhook.

```ts agent.ts
import { defineAgent, defineServerlessHook, markdown } from '@finalai/agents';
import { FinalHarness } from '@finalai/agents/harnesses';

const audit = defineServerlessHook({
  events: ['tool_call_update', 'decision.created', 'decision.resolved', 'turn.ended'],
  execute: async (event, ctx) => {
    let message: string;
    let attributes: Record<string, unknown>;
    switch (event.type) {
      case 'tool_call_update': {
        const { status, toolName, toolCallId } = event.data;
        // Log each call once, when it finishes.
        if (status !== 'completed' && status !== 'failed') return;
        message = `${toolName} ${status}`;
        attributes = { tool: toolName, tool_call_id: toolCallId, status };
        break;
      }
      case 'decision.created':
        message = `approval requested (${event.data.kind})`;
        attributes = { decision_id: event.data.decisionId, kind: event.data.kind };
        break;
      case 'decision.resolved':
        message = 'approval answered';
        attributes = { decision_id: event.data.decisionId, outcome: event.data.outcome };
        break;
      case 'turn.ended':
        message = `turn ended: ${event.data.stopReason}`;
        attributes = { turn_id: event.data.turnId, stop_reason: event.data.stopReason };
        break;
    }

    const apiKey = await ctx.secrets.get('DATADOG_API_KEY');
    if (apiKey == null) throw new Error('The DATADOG_API_KEY secret is not set');
    const response = await fetch('https://http-intake.logs.datadoghq.com/api/v2/logs', {
      method: 'POST',
      headers: { 'content-type': 'application/json', 'dd-api-key': apiKey },
      signal: ctx.signal,
      body: JSON.stringify([
        {
          ddsource: 'final-agents',
          service: 'ops-assistant',
          message,
          event_type: event.type,
          event_id: event.meta.id,
          occurred_at: event.meta.at,
          session_id: ctx.sessionId,
          acting_user_id: ctx.actingUserId,
          ...attributes,
        },
      ]),
    });
    if (!response.ok) throw new Error(`Datadog returned ${response.status}`);
  },
});

const reportFailures = defineServerlessHook({
  events: ['turn.ended'],
  execute: async (event, ctx) => {
    if (event.data.stopReason !== 'error') return;
    const url = await ctx.secrets.get('INCIDENT_WEBHOOK_URL');
    if (url == null) return;
    await fetch(url, {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      signal: ctx.signal,
      body: JSON.stringify({
        summary: 'Ops Assistant turn failed',
        session_id: ctx.sessionId,
        turn_id: event.data.turnId,
        dedup_key: event.meta.id,
      }),
    });
  },
});

export const agent = defineAgent({
  name: 'Ops Assistant',
  description: 'Helps the platform team across the services connected to Final.',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  secrets: ['DATADOG_API_KEY', 'INCIDENT_WEBHOOK_URL'],
  hooks: { audit, report_failures: reportFailures },
  require: {
    harness: { permissionMode: 'auto', recommended: { harness: FinalHarness.Final, model: 'deepseek-v4.1-flash' } },
    integrations: {
      final: { description: "Final's gateway: the services connected to this project" },
    },
  },
});
```

`event.meta.id` is unique to each event and stays the same if a hook is delivered twice, so you can drop duplicates in Datadog by `event_id`, and the incident tool can deduplicate on `dedup_key`. `ctx.actingUserId` is the person whose message started the turn.

The hook logs tool names and outcomes but not tool inputs or results, which can contain customer data. Add only the fields your audit needs, and never log secret values.

The agent declares the `final` integration slot but doesn't say which server fills it. Whoever starts the agent provides one; here it's Final's gateway, which gives the agent the tools of every service connected to the project, like GitHub, Linear, or Slack. The agent searches for the tools it needs. The `auto` permission ceiling lets a caller run it without approval prompts; lower it to `ask` to require a person's OK for changes.

## Set it up

<Steps>
  <Step title="Create the project">
    ```bash
    mkdir ops-assistant && cd ops-assistant
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    ```

    Add `agent.ts` and `instructions.md` from above. Export your [API key](/api-keys) as `FINAL_API_KEY` and the project's ID as `FINAL_PROJECT_ID`.
  </Step>
  <Step title="Add the secrets">
    In Datadog, create an API key under **Organization Settings** > **API Keys**. In Final, add it under **Developer** > **Secrets** as `DATADOG_API_KEY`. Add your incident tool's webhook URL as `INCIDENT_WEBHOOK_URL`; the failure hook skips reporting when it isn't set. See [secrets](/operate/authentication#use-secrets-in-your-code).
  </Step>
  <Step title="Check the document">
    ```bash
    npx final-agents print ./agent.ts
    ```

    The printed document lists both hooks under `hooks`, each with `"placement": "serverless"` and its source. If a hook used a variable from outside itself, `print` fails and names the variable.
  </Step>
</Steps>

## Try it

`ask.ts` provides the harness and fills the `final` slot with the project's gateway integration, creating it the first time:

```ts client.ts
import { createClient } from '@finalai/agents/client';

const apiKey = process.env.FINAL_API_KEY;
const projectId = process.env.FINAL_PROJECT_ID;
if (apiKey == null || projectId == null) throw new Error('Set FINAL_API_KEY and FINAL_PROJECT_ID');

export const client = createClient({ auth: { apiKey } });
export const project = client.project({ id: projectId });
```

```ts ask.ts
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { finalGateway } from '@finalai/agents/integrations';
import { agent } from './agent.js';
import { client, project } from './client.js';

// The project's Final gateway integration: created once, then found by name.
const final = await project.integrations
  .get({ name: 'final' })
  .catch(() =>
    project.integrations.create(finalGateway({ url: 'https://api.final.ai/v1/connectors/mcp' })),
  );

const { handle, response } = await project.sessions.create({
  agent,
  provide: {
    harness: serverlessFinal({
      model: 'deepseek-v4.1-flash',
      inference: finalCredits(),
    }),
    integrations: { final },
  },
  message: 'Which GitHub issues labeled incident were opened in acme/web this week?',
});
console.log(await response!.text());

await handle.close();
client.close();
```

```bash
npx tsx ask.ts
```

Leaving out `integrations` makes the call fail with `requirements_unmet`, naming the `final` slot, and nothing starts. See [requirements](/build/requirements).

Then search Datadog's Log Explorer for `service:ops-assistant`. Each tool call and the end of the turn has its own entry. Leaving out the IDs, a tool call looks like this:

```json
{
  "message": "search_issues completed",
  "event_type": "tool_call_update",
  "service": "ops-assistant",
  "tool": "search_issues",
  "status": "completed"
}
```

The tool names depend on which services are connected to the project.

## Make it yours

- **Add the hooks to any agent.** Copy `audit` and `reportFailures` into another agent, add the two secrets to its `secrets`, and change `service`. The [billing support agent](/examples/billing-support) is a good candidate.
- **Send it somewhere else.** Replace the `fetch` with your log pipeline or SIEM's HTTP endpoint. For a Datadog site outside US1, change the intake host, for example to `http-intake.logs.datadoghq.eu`.
- **Log to your own database.** Use `defineInProcessHook` instead, so the hook runs in your process and can use your database client. It then records events only while that process is running; see [where code runs](/build/where-code-runs).
