This agent explains deployment events and log excerpts supplied by CI. It posts its answer in Final and suggests a next check. It has no rollback tool, so it cannot change your deployment.

## Create the project

Use Node.js 26 or later and install:

```bash
mkdir deployment-watcher && cd deployment-watcher
git init
pnpm init --init-type module --no-init-package-manager
printf 'node_modules/\n.final/\n.env*\n' > .gitignore
pnpm add @finalai/agents @finalai/final-agent-provider zod
mkdir -p agent/channels
```

The agent has three files:

```text
agent/
  agent.ts
  instructions.md
  channels/deploys.ts
```

```ts agent/agent.ts
import { credentials, defineAgent } from '@finalai/agents';
import { serverlessPi } from '@finalai/agents/harnesses';
export default defineAgent({
  name: 'Deployment watcher',
  harness: serverlessPi({ credentials: credentials.chain({ payer: 'organization', tryInOrder: [credentials.platform()] }) }),
});
```

```markdown agent/instructions.md
Explain the deployment event and supplied log excerpt.
Separate facts from hypotheses. Include the supplied run link and suggest the
next read-only check. Never claim you fetched logs or ran validation yourself.
Do not attempt a rollback or other change.
```

```ts agent/channels/deploys.ts
import { defineChannel, POST } from '@finalai/agents/channels';
import { z } from 'zod';

const eventSchema = z.object({
  place: z.object({ kind: z.literal('webhook'), id: z.string(), title: z.string().optional() }),
  label: z.string(), content: z.array(z.object({ type: z.literal('text'), text: z.string() })),
  idempotencyKey: z.string(),
});

export default defineChannel({
  name: 'deploys',
  credentials: { app: null, secrets: ['deploy-webhook-secret'] },
  identity: { kind: 'none' },
  places: { kinds: ['webhook'] },
  routes: [POST('/webhook', async (ctx) => {
    const body = await ctx.request.text();
    const secret = await ctx.credentials.secret('deploy-webhook-secret');
    const signature = (ctx.request.headers.get('x-final-signature') ?? '').replace(/^sha256=/, '');
    if (secret == null || !/^[a-f0-9]{64}$/i.test(signature))
      return new Response('Invalid signature', { status: 401 });
    const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(secret),
      { name: 'HMAC', hash: 'SHA-256' }, false, ['verify']);
    const bytes = new Uint8Array(Array.from({ length: 32 }, (_, i) =>
      Number.parseInt(signature.slice(i * 2, i * 2 + 2), 16)));
    if (!(await crypto.subtle.verify('HMAC', key, bytes, new TextEncoder().encode(body))))
      return new Response('Invalid signature', { status: 401 });
    let event: z.infer<typeof eventSchema>;
    try { event = eventSchema.parse(JSON.parse(body)); }
    catch { return new Response('Invalid event', { status: 400 }); }
    const result = await ctx.receive(event);
    return Response.json(result, { status: 'accepted' in result && !result.accepted ? 403 : 202 });
  })],
  receive: async (input, ctx) => {
    const event = eventSchema.parse(input);
    const place = event.place;
    const route = await ctx.places.resolve(place);
    if (route.kind !== 'connected')
      return { accepted: false, refusal: { refused: 'unconnected',
        message: 'Connect this deployment feed to a chat.', connectUrl: route.connectUrl } };
    const result = await ctx.conversation(route.conversation).input({
      label: event.label, content: event.content,
      origin: { place }, idempotencyKey: event.idempotencyKey,
    });
    return 'refused' in result ? { accepted: false, refusal: result } : { accepted: true };
  },
  events: {
    'turn.completed': async (event, ctx) => { ctx.log('Deployment turn completed', { turnId: event.turnId }); },
  },
});
```

## Configure and publish

Create a [project secret](/operate/authentication#use-secrets-in-your-code) named `deploy-webhook-secret`, and put the same random value in your CI secret store as `DEPLOY_WEBHOOK_SECRET`. The channel declares the secret name; never put its value in source.

Export your [API key](/api-keys) as `FINAL_API_KEY`. Register this agent once in the same project as the key and webhook secret. Save the following as `register.ts`, replacing `prj_your_project` with that project's ID:

```ts register.ts
import { createClient } from '@finalai/agents/client';

const client = createClient({
  host: 'https://agent-session.final.ai/api',
  auth: { apiKey: process.env.FINAL_API_KEY! },
});
try {
  const definition = await client.definitions.create({
    slug: 'deployment-watcher',
    name: 'Deployment watcher',
    projectId: 'prj_your_project',
  });
  console.log(`Registered ${definition.slug} (${definition.id})`);
} finally {
  client.close();
}
```

```bash
node register.ts
```

This agent declares a secret, so an organization admin with edit access to this project must publish it. Build locally, then save the [`upload-draft.ts` script](/operate/publishing#publish-code-that-uses-secrets) beside `agent/` and upload these exact files with the project API key:

```bash
pnpm exec final-agents build ./agent
node upload-draft.ts deployment-watcher agent.ts instructions.md channels/deploys.ts
```

Ask that admin to review the uploaded draft in the agent's **Code** view in Final and choose **Save and publish**. The API key can upload this initial draft and compile it, but cannot approve a secret-using revision or edit it after publication. Later edits also use that admin's Code view.

After publication, use the same guide's `show-routes.ts` script:

```bash
node show-routes.ts deployment-watcher
```

Copy the POST `/webhook` route's `aliasUrl` ending in `/b/<raw-binding-id>/webhook` to CI as `CHANNEL_WEBHOOK_URL`. New webhook channels use your project secret; publishing does not generate a different key.

[Create a Shared chat in the Final web app](/build/channels#create-a-shared-chat-in-final), inside the same project. Select your own name and the published `deployment-watcher` agent through the project's **+ → New Chat** menu, then **Start chat**. This gives the agent `default` routing. Do this as a signed-in person, not with the publishing API key; a chat without this agent cannot run the example.

The place is discovered by the first event, so it is not listed in **Connected** yet. Send the event below once. On `403`, the sender prints a response containing `refusal.connectUrl`. Open it while signed in, connect `production-deploys` to a Shared chat you can manage, and run the sender again with the same idempotency key. The discovered place is now available in **Connected**.

## Send an event

Save this as `send-deploy.mjs` and run it in CI with the two environment values configured above:

```js send-deploy.mjs
import { createHmac } from 'node:crypto';

const url = process.env.CHANNEL_WEBHOOK_URL;
const secret = process.env.DEPLOY_WEBHOOK_SECRET;
if (url == null || secret == null) throw new Error('Configure the webhook URL and CI secret.');
const body = JSON.stringify({
  place: { kind: 'webhook', id: 'production-deploys', title: 'Production deploys' },
  label: 'Deployment 1042',
  content: [{ type: 'text', text: 'web 1.2.0 failed. Log excerpt: readiness check returned 503 after 60 seconds. Run: https://ci.example.com/runs/1042' }],
  idempotencyKey: 'deploy:1042',
});
const signature = createHmac('sha256', secret).update(body).digest('hex');
const response = await fetch(url, {
  method: 'POST',
  headers: { 'content-type': 'application/json', 'x-final-signature': `sha256=${signature}` },
  body,
});
const responseBody = await response.text();
if (response.status !== 202) {
  console.error(responseBody); // Includes refusal.connectUrl when the place needs connecting.
  throw new Error(`Webhook returned ${response.status}`);
}
console.log('Deployment event accepted.');
```

```bash
node send-deploy.mjs
```

Use the real CI run ID in `idempotencyKey`; keep it unchanged when retrying that event. `401` means the signature or stored secret differs; `400` means the envelope is malformed. See [webhook setup](/build/channels#write-a-custom-channel).

The chat receives a captioned deployment input and the agent's answer. For example, it can identify the failing readiness check and suggest checking the new version's health endpoint, while noting that the excerpt alone does not establish the root cause. The event is nonhuman input, not a message impersonating the installer.

## Try the route locally

```bash
AGENT_LOCAL_SECRETS_JSON='{"deploy-webhook-secret":"local-test-value"}' \
  pnpm exec final-agents dev ./agent
```

For this preview, set `CHANNEL_WEBHOOK_URL` to `http://localhost:3000/deploys/webhook` and `DEPLOY_WEBHOOK_SECRET` to `local-test-value`, then run the same sender. Local preview logs the verified event without running the agent. Use the published URL to test a real turn.

## Extend it

Add read-only tools for deployment logs or service status, then give the agent instructions for using them. Keep remediation tools behind [approval](/build/tools#ask-before-a-tool-runs). Disconnect the place to stop delivery. This application is inbound-only; it does not mirror chat replies to CI.
