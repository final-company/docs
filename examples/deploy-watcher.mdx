A deployment watcher connects CI events to a chat where your team can follow the result. The event is nonhuman input, so it does not impersonate the person who installed the integration.

## Add the channel

```ts agent/channels/deploys.ts
import { webhookChannel } from '@finalai/final-agent-provider/channels/webhook';
export default webhookChannel({ secret: 'deploy-webhook-secret' });
```

Set that secret in your project and publish the agent. In the chat's Connected section, connect the channel's `webhook` place `production-deploys`. The place connects to a Shared chat whose policy asks before writes.

## Send a deployment event

Have CI POST the standard envelope to the binding's `/webhook` route:

```json
{
  "place": { "kind": "webhook", "id": "production-deploys", "title": "Production deploys" },
  "label": "Deployment 1042",
  "content": [{ "type": "text", "text": "web 1.2.0 failed deployment. Logs: https://ci.example.com/runs/1042" }],
  "idempotencyKey": "deploy:1042"
}
```

Sign the exact body with HMAC-SHA256 and send `X-Final-Signature: sha256=<hex digest>`. Keep the same idempotency key on retries. See [authenticated webhooks](/build/channels#add-an-authenticated-webhook).

## Configure the agent

Give the agent tools for reading deployment logs and service status. Mark read-only tools accordingly, and keep remediation writes behind approval. Tell the agent to report what failed, link the logs, distinguish its diagnosis from evidence, and ask before attempting a rollback.

The reply appears in the connected chat with the deployment caption. Disconnect the place to stop delivery. Choose `replies: all` only if every message in that chat should also be mirrored to the outside surface.
