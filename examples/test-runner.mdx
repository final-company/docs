This agent runs your test suite on a cloud computer, reads the failing tests and the code they cover, and explains what broke. It runs the tests freely through a dedicated tool, but asks before any other shell command or file edit, so you stay in control while you build trust in it. Use it to triage a red build, or to ask "why does this test fail?" without setting up the project yourself.

**What it shows:** an agent that [requires compute](/build/requirements) (files and a shell), providing a [computer](/build/sandboxes) prepared by a [sandbox setup](/build/sandbox-setups), a tool that reaches the provided machine with `ctx.sandbox('shell')`, a permission ceiling of `ask`, and answering [permission](/client/sessions#handle-approvals) requests from a script.

### The agent

The agent says what it needs, not where it runs. `compute: { files: 'write', shell: 'execute' }` asks for a machine whose files the model can edit and where it can run commands. Whoever starts the agent decides which machine that is. `permissionMode: 'ask'` is a ceiling: no caller can give it a harness that runs commands or edits files without asking.

`run_tests` is a serverless tool. It runs on Final and reaches whatever sandbox the session was provided for `shell`, runs `npm test` in the `acme-web` checkout, and returns only the end of the log, which is where test runners print failures. Your own tools don't ask unless you give them an approval policy, so the agent can run the tests as often as it needs, while the harness's own shell and file tools still ask.

```ts agent.ts
import { defineAgent, defineServerlessTool, markdown } from '@finalai/agents';
import * as z from 'zod';

// Runs on Final and reaches the machine provided for `shell`.
const runTests = defineServerlessTool({
  description: 'Run the test suite and report whether it passed.',
  inputSchema: z.object({ filter: z.string().optional().describe('Only run matching tests') }),
  execute: async ({ filter }, ctx) => {
    const shell = await ctx.sandbox('shell');
    const result = await shell.run({
      command: 'npm',
      args: filter == null ? ['test'] : ['test', '--', filter],
      cwd: 'acme-web',
      timeoutMs: 10 * 60_000,
      abortSignal: ctx.signal,
    });
    return {
      passed: result.exitCode === 0,
      output: result.stdout.slice(-4000) + result.stderr.slice(-2000),
    };
  },
});

export const agent = defineAgent({
  name: 'Test Runner',
  description: 'Runs the acme-web test suite and explains failures.',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  tools: { run_tests: runTests },
  require: {
    harness: { permissionMode: 'ask' },
    compute: { files: 'write', shell: 'execute' },
  },
});
```

`cwd: 'acme-web'` is relative to the sandbox's working directory, where the setup below checks out the repository. Never hardcode an absolute checkout path; ask the sandbox for its description if you need one (see [inspect the machine](#inspect-the-machine)).

## Set it up

<Steps>
  <Step title="Create the project">
    Create the project the same way as in the [quickstart](/quickstart), then add the files above:

    ```bash
    mkdir test-runner && cd test-runner
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    npm install --save-dev typescript tsx @types/node
    ```

    `client.ts` creates the client and project from your environment:

    ```ts client.ts
    import { createClient } from '@finalai/agents/client';
    
    const apiKey = process.env.FINAL_API_KEY;
    const projectId = process.env.FINAL_PROJECT_ID;
    if (apiKey == null || projectId == null) throw new Error('Set FINAL_API_KEY and FINAL_PROJECT_ID');
    
    export const client = createClient({ auth: { apiKey } });
    export const project = client.project({ id: projectId });
    ```
  </Step>
  <Step title="Let Final reach the repository">
    The sandbox setup clones `https://github.com/acme/acme-web.git` inside the computer. Replace it with your repository's HTTPS URL. A public repository needs nothing more. For a private one, create an [egress integration](/build/integrations#credentials-for-a-sandboxs-traffic) that holds a token for `github.com`, and name it on the repository's entry with `integration`.
  </Step>
</Steps>

## Try it

`run.ts` creates a computer with a [sandbox setup](/build/sandbox-setups) that clones the repository and installs its dependencies, then starts a session with that computer provided for both `files` and `shell`. The computer is owned by the session, so it's deleted with it.

When the agent wants to run a shell command, the turn pauses on a **permission** decision. Its options, like allow once or reject, come with the request, so the script lists them and sends back the one you pick:

```ts run.ts
import { createInterface } from 'node:readline/promises';
import { DecisionKind, sessionUpdateOf, textOf } from '@finalai/agents/client';
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { computer, defineSandboxSetup } from '@finalai/agents/sandboxes';
import { agent } from './agent.js';
import { client, project } from './client.js';

const terminal = createInterface({ input: process.stdin, output: process.stdout });

// What should be on the machine. Paths are relative to the sandbox's working directory.
const setup = defineSandboxSetup({
  repositories: [{ alias: 'acme-web', url: 'https://github.com/acme/acme-web.git', ref: 'main' }],
  steps: [{ name: 'Install dependencies', cwd: 'acme-web', run: 'npm ci' }],
  notes: 'The repository is checked out in acme-web. Run tests from there.',
});

// The session owns the computer, so it is deleted when the session is.
const sessionId = crypto.randomUUID();
const box = await project.sandboxes.create(computer({ image: 'docker.io/library/node:26-bookworm' }), {
  setup,
  ownedBy: { session: sessionId },
});

const { handle, response } = await project.sessions.create({
  id: sessionId,
  agent,
  provide: {
    harness: serverlessFinal({
      model: 'deepseek-v4.1-flash',
      inference: finalCredits(),
      permissionMode: 'ask',
    }),
    // Files and shell must be the same sandbox.
    compute: { files: box, shell: box },
  },
  message: 'Run the checkout tests and tell me why they fail.',
});

const answered = new Set<string>();
for await (const event of response!.stream()) {
  const update = sessionUpdateOf(event);
  if (update?.sessionUpdate === 'agent_message_chunk') process.stdout.write(textOf(update));

  if (event.decisionId != null && !answered.has(event.decisionId)) {
    answered.add(event.decisionId);
    const decision = (await handle.decisions()).find((d) => d.id === event.decisionId);
    if (decision?.kind !== DecisionKind.Permission) continue;

    const { title, options } = decision.request;
    console.log(`\n\n${title}`);
    options.forEach((option, i) => console.log(`  ${i + 1}. ${option.name}`));
    const picked = Number(await terminal.question('Choose: ')) - 1;
    const option = options[picked] ?? options[options.length - 1]!;
    await handle.respond({ decisionId: decision.id, optionId: option.optionId });
  }
}

terminal.close();
await handle.close();
client.close();
```

```bash
npx tsx run.ts
```

The computer boots on first use, and the setup runs before the agent's first command. The agent runs the tests with `run_tests`, which doesn't ask. Reading the failing files doesn't ask either. When it wants to run another command, you choose, and the session looks something like this:

```text
Two checkout tests fail, both in src/checkout/total.test.ts.

Run git log -3 --oneline -- src/checkout/total.ts
  1. Allow once
  2. Always allow
  3. Reject
Choose: 1

Both failures come from the same change: applyDiscount now rounds before it adds
tax (commit 4f1c2ab), so a $19.99 cart with a 10% discount totals $19.78 instead
of $19.79. The smallest fix is to round once, after tax:

-  const discounted = Math.round(subtotal * (1 - rate));
-  return discounted + tax(discounted);
+  const discounted = subtotal * (1 - rate);
+  return Math.round(discounted + tax(discounted));
```

### Run it on your own machine instead

Leave `compute` out, and the SDK serves the model's files and shell from the process that creates the session, rooted at its working directory. Run this from the directory that contains your `acme-web` checkout, and the agent works on your local files:

```ts local.ts
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { agent } from './agent.js';
import { project } from './client.js';

// No `compute`: the model's files and shell are this process's working directory.
const { response } = await project.sessions.create({
  agent,
  provide: {
    harness: serverlessFinal({ model: 'deepseek-v4.1-flash', inference: finalCredits() }),
  },
  message: 'Run the checkout tests and tell me why they fail.',
});
console.log(await response?.text());
```

This sketch only prints the reply; to answer the agent's permission requests, reuse the decision loop from `run.ts`. Commands then run on your machine with your user's access, so keep the `ask` ceiling. When the script exits, the session survives but its files and shell become unavailable. A server should never rely on this default; see [where code runs](/build/where-code-runs).

### Inspect the machine

The sandbox description lists what the setup produced, including each checkout's real path on that machine:

```ts
const description = await box.description();
for (const checkout of description.checkouts) console.log(checkout.alias, checkout.path);
```

## Make it yours

- **Reuse the setup.** Publish it once with `project.sandboxSetups.publish({ name: 'acme-web', setup })` and create computers from the published version. Add `services` to start your dev server and `commands` for scripts the agent should know about. See [sandbox setups](/build/sandbox-setups).
- **Let it fix the tests.** Once you trust it, raise the ceiling to `permissionMode: 'review'`, where edits proceed and commands still wait, or keep edits behind approval with `toolPolicy: { 'files.write': 'ask' }` in `agent.ts`. The caller picks a `permissionMode` at or below the ceiling in its harness settings.
- **Keep one computer per conversation.** Create the computer with `ownedBy: { conversation: id }` and provide it on the conversation, so follow-up questions see the same checkout. See [conversations](/client/conversations).
- **Run it on every red build.** Add a [channel](/build/channels) that receives your CI's failure webhooks and sends the failing job's name as the message.
