This agent answers developer questions about an API, the Acme Pay API in this example. Everything it knows lives in skills: one for webhooks, one for error codes, one for API versions. Reach for this pattern when you want a support or docs bot that answers from material you control, and you'd rather edit Markdown than code to improve it.

**What it shows:** [instructions](/build/instructions-and-skills), skills from a directory and inline, an agent that requires only a harness, and the harness's `reasoning` setting in [harness settings](/harnesses/settings).

`agent.ts` lists every part of the agent. It requires only a harness: no compute and no integrations, because it answers from its skills. The recommendation suggests a fast model with low reasoning, which suits short Q&A, but the caller decides.

```ts agent.ts
import { defineAgent, markdown, skill } from '@finalai/agents';

export const agent = defineAgent({
  name: 'Docs Assistant',
  description: 'Answers developer questions about the Acme Pay API.',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  skills: [
    skill('./skills/webhooks', { from: import.meta.url }),
    skill('./skills/errors', { from: import.meta.url }),
    skill({
      name: 'api-versions',
      description: 'Explain Acme Pay API versions and what changes when you upgrade.',
      instructions: markdown('./skills/api-versions.md', { from: import.meta.url }),
    }),
  ],
  require: {
    harness: {
      permissionMode: 'ask',
      recommended: { harness: 'pi', model: 'gpt-6.1-sol', reasoning: 'low' },
    },
  },
});
```

The instructions set the tone and the rules. They stay short because the details live in skills:

```markdown instructions.md
You answer developer questions about the Acme Pay API.

Answer from your skills. If no skill covers the question, say so and link to https://docs.acme.dev instead of guessing.
Show code in the language the developer is using, and default to curl.
Put the answer first, then one example, then a link to the docs page it came from.
Never ask for an API key. If someone pastes a live key (it starts with sk_live_), tell them to roll it under Developers > API keys before you answer.
```

### The webhooks skill

A skill's `description` tells the agent when to load it. The steps refer to the files beside `SKILL.md`, which the agent reads only when it needs them:

<CodeGroup>

```markdown skills/webhooks/SKILL.md
---
name: webhooks
description: Answer questions about receiving, verifying, and retrying Acme Pay webhooks.
---

1. Find the event in events.md. If the developer names an event that isn't listed, say so and suggest the closest one.
2. For signature errors, ask which language and framework they use, then walk through verify.md step by step.
3. For missed or duplicate events, explain retries: a delivery fails if the endpoint doesn't return a 2xx status within 10 seconds, and Acme Pay retries it with exponential backoff for up to 3 days. Handlers should be idempotent on the event's id.
4. Link to https://docs.acme.dev/webhooks.
```

```markdown skills/webhooks/events.md
| Event | Sent when |
| --- | --- |
| payment.succeeded | A payment is captured. |
| payment.failed | A payment attempt is declined or errors. |
| refund.created | A full or partial refund is issued. |
| payout.paid | A payout reaches the merchant's bank account. |
| dispute.opened | A cardholder disputes a payment. |
| dispute.closed | A dispute is won or lost. The outcome is in data.status. |
```

```markdown skills/webhooks/verify.md
Every webhook has an Acme-Signature header like `t=1767225600,v1=5f2b...`.

1. Read the raw request body as a string before parsing it. Parsing and re-serializing JSON changes the bytes and breaks the signature. In Express, use express.raw({ type: 'application/json' }) on the webhook route instead of express.json().
2. Build the signed payload: the t value, a period, then the raw body.
3. Compute an HMAC-SHA256 of that payload with the endpoint's signing secret (it starts with whsec_), and hex-encode it.
4. Compare it with the v1 value using a constant-time comparison.
5. Reject the event if t is more than 5 minutes old, to block replays.

The signing secret is per endpoint. Using the account's API key, or another endpoint's secret, is the most common cause of every signature failing.
```

</CodeGroup>

### The errors skill

<CodeGroup>

```markdown skills/errors/SKILL.md
---
name: errors
description: Explain an Acme Pay API error code or decline code and how to fix it.
---

1. Look up the code in error-codes.md. Codes are in the error.code field of the response, and card declines add error.decline_code.
2. Say whether the developer can fix it in code, or whether their customer has to act.
3. For 429 rate_limited, show how to retry with backoff using the Retry-After header.
4. Link to https://docs.acme.dev/errors#<code>.
```

```markdown skills/errors/error-codes.md
| Code | Status | Meaning | Who fixes it |
| --- | --- | --- | --- |
| invalid_request | 400 | A parameter is missing or malformed. error.param names it. | Developer |
| authentication_failed | 401 | The API key is missing, revoked, or from the wrong mode (test vs live). | Developer |
| card_declined | 402 | The bank declined the card. See error.decline_code. | Customer |
| insufficient_funds | 402 | A decline_code: the card doesn't have enough funds. | Customer |
| expired_card | 402 | A decline_code: the card has expired. | Customer |
| idempotency_conflict | 409 | The Idempotency-Key was reused with different parameters. | Developer |
| rate_limited | 429 | Too many requests. Wait for Retry-After seconds. | Developer |
```

</CodeGroup>

### An inline skill

A skill that fits in one file doesn't need a directory. `skill({ name, description, instructions })` takes its name and description inline and reads the steps from a file when the agent's document is made:

```markdown skills/api-versions.md
Requests pick a version with the Acme-Version header. Without it, the account's default version applies.

Upgrading from 2025-09-01 to 2026-06-01 changes three things:
- Amounts are integers in the smallest currency unit (cents) everywhere. The old amount_decimal field is gone.
- payment.failed events include the decline_code at the top level of data.
- List endpoints return at most 100 items per page, down from 250.

Tell developers to send Acme-Version: 2026-06-01 on a few requests and test them before changing the account default.
```

## Set it up

Create the project the same way as in the [quickstart](/quickstart), add the files above, and export `FINAL_API_KEY` and `FINAL_PROJECT_ID`:

```bash
mkdir docs-assistant && cd docs-assistant
npm init -y && npm pkg set type=module
npm install @finalai/agents zod
npm install --save-dev typescript tsx @types/node
```

Check that every file is found by printing the agent's document. It calls nothing:

```bash
npx final-agents print ./agent.ts
```

The output lists `webhooks`, `errors`, and `api-versions` under `skills`, with each skill's files inside it.

## Try it

`client.ts` is the same as in the [quickstart](/quickstart). `ask.ts` passes the agent itself, so nothing needs publishing first. It provides the one thing the agent requires, a harness, with the low reasoning level the agent recommends:

```ts ask.ts
import { finalCredits, serverlessPi } from '@finalai/agents/harnesses';
import { workers } from '@finalai/agents/sandboxes';
import { agent } from './agent.js';
import { client, project } from './client.js';

const runtime = await project.sandboxes.create(workers(), { idempotencyKey: 'workers' });

const { handle, response } = await project.sessions.create({
  agent,
  provide: {
    harness: serverlessPi({
      model: 'gpt-6.1-sol',
      reasoning: 'low',
      inference: finalCredits(),
      environment: runtime.id,
    }),
  },
  message: 'Every webhook fails signature verification in my Express app. What am I doing wrong?',
});

console.log(await response!.text());

await handle.close();
client.close();
```

```bash
npx tsx ask.ts
```

The agent loads the webhooks skill, reads `verify.md`, and replies with something like:

```text
Most likely, express.json() is parsing the body before you verify it. The signature
covers the raw bytes, so re-serialized JSON never matches.

Use express.raw() on the webhook route and verify the raw body:

app.post('/webhooks', express.raw({ type: 'application/json' }), (req, res) => {
  const payload = `${timestamp}.${req.body.toString('utf8')}`;
  // compute the HMAC-SHA256 with your endpoint's whsec_ secret...
});

Also check that you're using this endpoint's signing secret, not your API key.
Docs: https://docs.acme.dev/webhooks
```

## Make it yours

- **Add a skill per area of your docs.** Copy the `webhooks/` folder, change the `description`, put the reference material beside `SKILL.md`, and add it to `skills` in `agent.ts`. The agent sees every skill's description up front, so keep each one specific.
- **Let people chat with it in Final.** Publish it with `npx final-agents publish ./agent.ts --name docs-assistant`. See [publishing](/operate/publishing).
- **Put it on your docs site.** Stream its answers into a chat widget with the route from the [support chat example](/examples/support-chat).
