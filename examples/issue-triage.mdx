This agent turns a bug report into a well-filed issue. It searches for duplicates, follows your team's triage steps to pick an owner and a severity, and asks a person before it creates anything. Use it when bug reports arrive from many places and you want each one filed the same way.

**What it shows:** an [integration requirement](/build/integrations) with a tool allowlist and an approval, a [skill](/build/instructions-and-skills) with a reference file, providing the integration when you start a session, and answering the approval from a [script](/client/sessions#handle-approvals).

The agent doesn't name Linear. It requires an `issues` slot: an MCP server that the caller provides. The slot sets a ceiling on whatever fills it: only four tools are exposed, and `create_issue` always asks a person first.

```ts agent.ts
import { defineAgent, markdown, skill } from '@finalai/agents';

export const agent = defineAgent({
  name: 'Issue Triage',
  description: 'Files bug reports as issues with an owner and a severity.',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  skills: [skill('./skills/triage', { from: import.meta.url })],
  require: {
    harness: { permissionMode: 'ask' },
    integrations: {
      issues: {
        description: 'The issue tracker bug reports are filed in',
        tools: { allow: ['list_issues', 'get_issue', 'list_teams', 'create_issue'] },
        approvals: { create_issue: 'ask' },
      },
    },
  },
});
```

These are the tool names Linear's MCP server uses. If you provide a different issue tracker, or Linear renames a tool, update `allow` and `approvals` to match the server's tool list.

```markdown instructions.md
You triage bug reports for the acme-web team.
Follow the triage skill for every report. Never create an issue without searching for duplicates first.
If a report is missing steps to reproduce, ask for them before you file anything.
```

The skill holds the team's procedure, and `owners.md` maps product areas to teams:

<CodeGroup>

```markdown skills/triage/SKILL.md
---
name: triage
description: Turn a bug report into a Linear issue with an owner and a severity.
---

1. Search open issues for the same symptom with list_issues. If one matches, reply with its link and stop.
2. Pick the owning team from owners.md, based on the part of the product that's affected. Use list_teams to get the team's ID.
3. Set severity: P1 if customers are blocked, P2 if there's a workaround, P3 otherwise.
4. Create the issue with steps to reproduce, the expected and actual behavior, and the severity in the title, like "[P1] Checkout button spins forever on Safari".
5. Reply with the issue's link, team, and severity.
```

```markdown skills/triage/owners.md
- Checkout, payments, invoices: Payments team
- Sign-in, accounts, permissions: Identity team
- Everything else: Web platform team
```

</CodeGroup>

## Set it up

<Steps>
  <Step title="Create the project">
    Create the project the same way as in the [quickstart](/quickstart), add the files above, and export `FINAL_API_KEY` and `FINAL_PROJECT_ID`. `client.ts` is the same as in the quickstart.

    ```bash
    mkdir issue-triage && cd issue-triage
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    npm install --save-dev typescript tsx @types/node
    ```
  </Step>
  <Step title="Add your Linear key">
    Create a personal API key in your Linear account's security settings. In the Final dashboard, add it under **Developer** > **Secrets** in your project with the name `LINEAR_API_KEY`.
  </Step>
  <Step title="Create the integration">
    An integration is a project resource: an MCP server and how calls to it authenticate. Create it once. Final sends the secret as a bearer token, so the token never reaches the model:

    ```ts setup.ts
    import { secret } from '@finalai/agents/integrations';
    import { client, project } from './client.js';

    const linear = await project.integrations.create({
      name: 'linear',
      mcp: { url: 'https://mcp.linear.app/mcp' },
      auth: secret('LINEAR_API_KEY'),
    });
    console.log(`Created ${linear.id}`);
    client.close();
    ```

    ```bash
    npx tsx setup.ts
    ```

    To have each person file issues as themselves instead, create it with `auth: oauth()`. Final then asks each person to sign in the first time the agent calls Linear for them. See [sign-in](/build/integrations#sign-in).
  </Step>
</Steps>

## Try it

This script provides a harness and the `linear` integration for the `issues` slot, sends a bug report, streams the reply, and asks you in the terminal when the agent wants to create an issue:

```ts triage.ts
import { createInterface } from 'node:readline/promises';
import { sessionUpdateOf, textOf } from '@finalai/agents/client';
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { workers } from '@finalai/agents/sandboxes';
import { agent } from './agent.js';
import { client, project } from './client.js';

const terminal = createInterface({ input: process.stdin, output: process.stdout });
const runtime = await project.sandboxes.create(workers(), { idempotencyKey: 'workers' });
const linear = await project.integrations.get({ name: 'linear' });

const { handle, response } = await project.sessions.create({
  agent,
  provide: {
    harness: serverlessFinal({
      model: 'deepseek-v4.1-flash',
      inference: finalCredits(),
      environment: runtime.id,
    }),
    integrations: { issues: linear },
  },
  message:
    "Customers on Safari 18 can't complete checkout. The Pay button spins forever. " +
    'Steps: add any item to the cart, open checkout, click Pay. Works in Chrome.',
});

const answered = new Set<string>();
for await (const event of response!.stream()) {
  const update = sessionUpdateOf(event);
  if (update?.sessionUpdate === 'agent_message_chunk') process.stdout.write(textOf(update));

  // The agent wants to call create_issue. Show the request and send your answer.
  if (event.decisionId != null && !answered.has(event.decisionId)) {
    answered.add(event.decisionId);
    const decision = (await handle.decisions()).find((d) => d.id === event.decisionId);
    if (decision == null) continue;
    const { title, body } = decision.request;
    const reply = await terminal.question(`\n\n${title}\n${body ?? ''}\nApprove? (y/n) `);
    await handle.respond({
      decisionId: decision.id,
      outcome: { action: reply.trim() === 'y' ? 'accept' : 'decline' },
    });
  }
}

terminal.close();
await handle.close();
client.close();
```

```bash
npx tsx triage.ts
```

The agent searches for duplicates, picks the Payments team, and pauses before creating the issue. Type `y`, and it finishes with something like:

```text
No open issue matches this, so I'll file a new one for the Payments team.

Allow create_issue?
...
Approve? (y/n) y

Filed [P1] Checkout Pay button spins forever on Safari 18 for the Payments team:
https://linear.app/acme/issue/PAY-218
```

Leave `integrations` out of `provide` and `sessions.create` fails with `requirements_unmet`, naming the `issues` slot, before anything is created. See [requirements](/build/requirements).

## Make it yours

- **Take reports from where they arrive.** Install a [channel](/build/channels) that receives your support tool's webhooks, so new bug reports reach the agent without anyone forwarding them.
- **Let it update issues too.** Add `update_issue` to `allow` and to `approvals`, and add a skill step for commenting on the duplicate instead of stopping.
- **Let your team chat with it in Final.** Publish it with `npx final-agents publish ./agent.ts --name issue-triage`. See [publishing](/operate/publishing).
