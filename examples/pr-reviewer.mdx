A linked repository collaborator mentions your bot on a public pull request. The agent reads the diff with one read-only tool and posts a review as the GitHub App. It does not check out code, run tests, or change the repository.

## Create the project

Use Node.js 26 or later:

```bash
pnpm add @finalai/agents @finalai/final-agent-provider zod
mkdir -p agent/channels agent/tools
```

Create these four files:

```text
agent/
  agent.ts
  instructions.md
  channels/github.ts
  tools/read_pull_request.ts
```

```ts agent/agent.ts
import { credentials, defineAgent } from '@finalai/agents';
import { serverlessPi } from '@finalai/agents/harnesses';
export default defineAgent({
  name: 'Pull request reviewer',
  harness: serverlessPi({ credentials: credentials.chain({ payer: 'agent-owner', tryInOrder: [credentials.platform()] }) }),
});
```

```markdown agent/instructions.md
When asked to review a pull request, read its diff using read_pull_request.
Report concrete bugs and security problems with file and hunk references.
Separate confirmed observations from hypotheses. If the diff is truncated,
say the review is incomplete. Never claim you ran tests or checked out code.
Keep proposed fixes as suggestions; you have no repository write tools.
```

```ts agent/channels/github.ts
import { githubChannel } from '@finalai/final-agent-provider/channels/github';
export default githubChannel({ mention: 'final' });
```

```ts agent/tools/read_pull_request.ts
import { defineTool } from '@finalai/agents';
import { z } from 'zod';

export default defineTool({
  description: 'Read the diff of a public GitHub pull request. Does not run tests.',
  inputSchema: z.object({ owner: z.string(), repo: z.string(), number: z.number().int().positive() }),
  outputSchema: z.object({ diff: z.string(), truncated: z.boolean() }),
  annotations: { readOnlyHint: true },
  execute: async ({ owner, repo, number }, ctx) => {
    const response = await fetch(`https://api.github.com/repos/${encodeURIComponent(owner)}/${encodeURIComponent(repo)}/pulls/${number}`, {
      headers: { accept: 'application/vnd.github.diff' },
      signal: ctx.abortSignal,
    });
    if (!response.ok) throw new Error(`GitHub returned ${response.status}; this example reads public repositories only.`);
    const diff = await response.text();
    return { diff: diff.slice(0, 60_000), truncated: diff.length > 60_000 };
  },
});
```

GitHub supports the diff media type on its [pull request endpoint](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request). For private repositories, replace this tool with an appropriately authorized [GitHub connection](/build/connections); the channel's installation credentials are not handed to your authored tools.

## Configure and publish

Create a GitHub App and connect its installation in the agent's Final project. Follow [GitHub provider setup](/build/channels#provider-setup) for installation credentials, user OAuth, signing secret, events, and callbacks. Give the App access to the public repository you will test and permission to comment on pull requests.

Create the agent in Final, export your [API key](/api-keys) as `FINAL_API_KEY`, and use its slug:

```bash
pnpm exec final-agents build ./agent
pnpm exec final-agents publish ./agent --agent pull-request-reviewer
```

Copy the printed GitHub binding's `/webhook` and `/oauth/callback` URLs into the provider setup. If Final displays a forwarded webhook URL for the connected installation, use that exact URL for provider delivery instead. For one shared app serving multiple agents, [install a project-owned channel](/build/channels#use-a-provider-channel) instead of adding the per-agent factory.

## Link, connect, and try it

Link your GitHub account through user OAuth while signed in to Final, then connect the pull request to a Shared chat in **Connected**. The package verifies signatures and repository write access before accepting a mention. An unlinked or unconnected collaborator gets a public Link or Connect notice; the link still checks the Final account and permissions.

Open a pull request in your public test repository and comment:

```text
@final review this change, including authorization checks and test coverage. Read the diff for OWNER/REPO pull request NUMBER.
```

Replace `OWNER`, `REPO`, and `NUMBER`, and use your configured bot mention. The channel acknowledges the comment, then posts the completed answer once. A useful answer names a concrete hunk and explains a failure case, or says no concrete issue was found. It must not claim to have run validation. Long answers direct readers to Final.

Inline review threads inherit the connected pull request unless a more specific route overrides it. Editing or deleting your original comment updates its Final message without starting a fresh turn. Edits to the agent's Final reply update the App's GitHub comment. Permission requests show a Waiting notice; answer them in Final.

Use **Follow** when another chat should receive PR status and review events without becoming its conversation. GitHub does not provide an inbound reaction webhook; reactions from Final can still be sent outward.
