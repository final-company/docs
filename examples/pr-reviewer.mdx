Ask this agent in Final to review a public pull request. It reads the diff with one read-only tool and replies in the chat. It does not check out code, run tests, or change the repository.

## Create the project

Use Node.js 26 or later:

```bash
mkdir pr-reviewer && cd pr-reviewer
git init
pnpm init --init-type module --no-init-package-manager
printf 'node_modules/\n.final/\n.env*\n' > .gitignore
pnpm add @finalai/agents @finalai/final-agent-provider zod
mkdir -p agent/tools
```

Create these three files:

```text
agent/
  agent.ts
  instructions.md
  tools/read_pull_request.ts
```

```ts agent/agent.ts
import { credentials, defineAgent } from '@finalai/agents';
import { serverlessPi } from '@finalai/agents/harnesses';
export default defineAgent({
  name: 'Pull request reviewer',
  harness: serverlessPi({ credentials: credentials.chain({ payer: 'organization', tryInOrder: [credentials.platform()] }) }),
});
```

```markdown agent/instructions.md
When asked to review a pull request, read its diff using read_pull_request.
Report concrete bugs and security problems with file and hunk references.
Separate confirmed observations from hypotheses. If the diff is truncated,
say the review is incomplete. Never claim you ran tests or checked out code.
Keep proposed fixes as suggestions; you have no repository write tools.
```

```ts agent/tools/read_pull_request.ts
import { defineTool } from '@finalai/agents';
import { z } from 'zod';

export default defineTool({
  description: 'Read the diff of a public GitHub pull request. Does not run tests.',
  inputSchema: z.object({ owner: z.string(), repo: z.string(), number: z.number().int().positive() }),
  outputSchema: z.object({ diff: z.string(), truncated: z.boolean() }),
  annotations: { readOnlyHint: true },
  execute: async ({ owner, repo, number }, ctx) => {
    const response = await fetch(`https://api.github.com/repos/${encodeURIComponent(owner)}/${encodeURIComponent(repo)}/pulls/${number}`, {
      headers: { accept: 'application/vnd.github.diff', 'user-agent': 'Final-PR-Reviewer-Example' },
      signal: ctx.abortSignal,
    });
    if (response.status === 429 || (response.status === 403 && response.headers.get('x-ratelimit-remaining') === '0'))
      throw new Error('GitHub rate limit reached; retry after the response reset time.');
    if (response.status === 403) throw new Error('GitHub refused the request; check repository access and provider restrictions.');
    if (response.status === 404) throw new Error('Pull request not found or not publicly readable.');
    if (!response.ok) throw new Error(`GitHub returned ${response.status}.`);
    const diff = await response.text();
    return { diff: diff.slice(0, 60_000), truncated: diff.length > 60_000 };
  },
});
```

GitHub supports the diff media type on its [pull request endpoint](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request). Unauthenticated GitHub requests have a low rate limit shared by the egress IP; this example is for trying a public PR, not high-volume review. For authenticated or private repositories, replace this tool with an appropriately authorized [GitHub connection](/build/connections); channel credentials are not handed to authored tools.

## Configure and publish

Export your [API key](/api-keys) as `FINAL_API_KEY`. Register this agent once in the same project as the key. Save the following as `register.ts`, replacing `prj_your_project` with that project's ID:

```ts register.ts
import { createClient } from '@finalai/agents/client';

const client = createClient({
  host: 'https://agent-session.final.ai/api',
  auth: { apiKey: process.env.FINAL_API_KEY! },
});
try {
  const definition = await client.definitions.create({
    slug: 'pull-request-reviewer',
    name: 'Pull request reviewer',
    projectId: 'prj_your_project',
  });
  console.log(`Registered ${definition.slug} (${definition.id})`);
} finally {
  client.close();
}
```

```bash
node register.ts
```

Then build and publish with that slug:

```bash
pnpm exec final-agents build ./agent
pnpm exec final-agents publish ./agent --agent pull-request-reviewer
```

## Try it

Open a chat with the published agent in Final and send:

```text
Review OWNER/REPO pull request NUMBER, including authorization checks and test coverage.
```

Replace `OWNER`, `REPO`, and `NUMBER` with a public pull request. A useful answer names a concrete hunk and explains a failure case, or says no concrete issue was found. It must not claim to have run validation.

To receive provider events or post reviews back to an outside thread, write a [channel application](/build/channels) with its own signature verification, identity proof, and provider API calls. Those capabilities are available through the same SDK used for custom integrations.
