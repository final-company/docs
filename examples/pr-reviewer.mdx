This agent reviews a public pull request. It reads the diff with one read-only tool and replies with what it found. It doesn't check out code, run tests, or change the repository.

**What it shows:** a [serverless tool](/build/tools#in-process-or-serverless) that makes public HTTP requests, an agent with no compute or integration requirements, and starting a [published](/operate/publishing) agent by name.

## Files

<Tree>

- pr-reviewer/
  - package.json
  - agent.ts
  - instructions.md
  - client.ts
  - review.ts

</Tree>

`agent.ts` lists the agent's only tool. The tool is serverless: its code travels with the agent and runs on Final, so the agent works for any caller, including a chat in Final where none of your code is running. Everything it uses, including the size limit, is declared inside `execute`:

```ts agent.ts
import { defineAgent, defineServerlessTool, markdown } from '@finalai/agents';
import * as z from 'zod';

const readPullRequest = defineServerlessTool({
  description: 'Read the diff of a public GitHub pull request. Does not run tests.',
  inputSchema: z.object({
    owner: z.string(),
    repo: z.string(),
    number: z.number().int().positive(),
  }),
  outputSchema: z.object({ diff: z.string(), truncated: z.boolean() }),
  annotations: { readOnlyHint: true },
  execute: async ({ owner, repo, number }, ctx) => {
    const limit = 60_000;
    const url = `https://api.github.com/repos/${encodeURIComponent(owner)}/${encodeURIComponent(repo)}/pulls/${number}`;
    const response = await fetch(url, {
      headers: { accept: 'application/vnd.github.diff', 'user-agent': 'Final-PR-Reviewer-Example' },
      signal: ctx.signal,
    });
    if (response.status === 429 || response.headers.get('x-ratelimit-remaining') === '0')
      throw new Error('GitHub rate limit reached; retry after the reset time.');
    if (response.status === 404) throw new Error('Pull request not found or not publicly readable.');
    if (!response.ok) throw new Error(`GitHub returned ${response.status}.`);
    const diff = await response.text();
    return { diff: diff.slice(0, limit), truncated: diff.length > limit };
  },
});

export const agent = defineAgent({
  name: 'Pull request reviewer',
  description: 'Reviews the diff of a public GitHub pull request.',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  tools: { read_pull_request: readPullRequest },
  require: {
    harness: { permissionMode: 'ask', recommended: { harness: 'final', model: 'deepseek-v4.1-flash' } },
  },
});
```

```markdown instructions.md
When asked to review a pull request, read its diff using read_pull_request.
Report concrete bugs and security problems with file and hunk references.
Separate confirmed observations from hypotheses. If the diff is truncated,
say the review is incomplete. Never claim you ran tests or checked out code.
Keep proposed fixes as suggestions; you have no repository write tools.
```

The agent requires only a harness. It needs no files, shell, or integrations, so callers provide nothing else. See [requirements](/build/requirements).

GitHub supports the diff media type on its [pull request endpoint](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request). Unauthenticated requests share a low rate limit per outgoing IP address, so this example suits trying a public pull request, not high-volume review. For private repositories, replace the tool with an [integration slot](/build/integrations) that a caller fills with a GitHub MCP server.

## Publish it

<Steps>
  <Step title="Set up the project">
    ```bash
    mkdir pr-reviewer && cd pr-reviewer
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    ```

    Add `agent.ts` and `instructions.md` from above. Export your [API key](/api-keys) as `FINAL_API_KEY` and the project's ID as `FINAL_PROJECT_ID`.
  </Step>
  <Step title="Publish it by name">
    ```bash
    npx final-agents publish ./agent.ts --name pr-reviewer
    ```

    Publishing stores the agent's document, including the tool's source, and points the name `pr-reviewer` at it. Nothing is built or deployed. To check the document first, run `npx final-agents print ./agent.ts`.
  </Step>
</Steps>

## Try it

### From a script

Fetch the published agent by name and start a session with it. A fetched agent is data, which works here because its only tool is serverless:

```ts client.ts
import { createClient } from '@finalai/agents/client';

const apiKey = process.env.FINAL_API_KEY;
const projectId = process.env.FINAL_PROJECT_ID;
if (apiKey == null || projectId == null) throw new Error('Set FINAL_API_KEY and FINAL_PROJECT_ID');

export const client = createClient({ auth: { apiKey } });
export const project = client.project({ id: projectId });
```

```ts review.ts
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { client, project } from './client.js';

// The published agent, as data. Its only tool is serverless, so it runs without this script.
const agent = await project.agents.get({ name: 'pr-reviewer' });

const [owner, repo, number] = process.argv.slice(2);
if (owner == null || repo == null || number == null)
  throw new Error('Usage: npx tsx review.ts OWNER REPO NUMBER');

const { handle, response } = await project.sessions.create({
  agent,
  provide: {
    harness: serverlessFinal({
      model: 'deepseek-v4.1-flash',
      inference: finalCredits(),
    }),
  },
  message: `Review ${owner}/${repo} pull request ${number}, including authorization checks and test coverage.`,
});
console.log(await response!.text());

await handle.close();
client.close();
```

```bash
npx tsx review.ts OWNER REPO NUMBER
```

Replace `OWNER`, `REPO`, and `NUMBER` with a public pull request. A useful answer names a concrete hunk and explains a failure case, or says no concrete issue was found. It must not claim to have run tests. [Harness settings](/harnesses/settings) covers other models and who pays for inference.

### From a Final chat

Open a chat with `pr-reviewer` in Final and send the same request. Final provides the harness when it adds the agent to a chat, and the serverless tool runs without any of your code online.

## Extend it

- **Post reviews back to GitHub.** Write a [channel](/build/channels) that receives pull request events and posts replies with its own provider credentials.
- **Run the tests too.** Add a `shell` requirement and let the caller provide a computer with the repository checked out. See [sandboxes](/build/sandboxes).
