When someone opens a pull request, GitHub sends a webhook to this agent. The agent checks out the branch on a cloud computer, runs the linter and the tests, reads the diff, and posts a review on the pull request with its findings. Use it to give every pull request a first pass before a person looks at it, with test results attached.

**What it shows:** a [channel](/build/channels) that verifies [GitHub webhook signatures](/build/channels#verify-a-github-webhook-signature), a [sandbox](/build/sandboxes) with a repository checked out, a tool that runs Git on the sandbox with a token it never shows the model, and a tool that posts to the GitHub API.

## How it works

1. GitHub sends a `pull_request` webhook to the channel's route. The route checks the signature, skips drafts and forks, and sends the agent one message: "Review pull request #412".
2. The agent calls `checkout_pr`, which fetches the branch into the computer's checkout of `acme/web` and returns the diff.
3. The agent runs `npm ci`, `npm run lint`, and `npm test` with its built-in shell, and reads files where the diff needs context.
4. The agent calls `post_review` with a summary and line comments.

The agent runs without a person watching, so it uses `permissionMode: 'auto'` and runs commands without asking:

```ts agent/agent.ts
import { baseTools, credentials, defineAgent } from '@finalai/agents';
import { serverlessFinal } from '@finalai/agents/harnesses';
import { computer } from './sandbox.js';

export default defineAgent({
  name: 'PR Reviewer',
  description: 'Reviews new pull requests in acme/web and posts the results on GitHub.',
  secrets: ['github-token', 'github-webhook-secret'],
  tools: baseTools({ shell: computer, files: computer }),
  harness: serverlessFinal({
    credentials: credentials.chain({
      payer: 'organization',
      tryInOrder: [credentials.platform()],
    }),
    permissionMode: 'auto',
  }),
});
```

```markdown agent/instructions.md
You review pull requests in the acme/web repository. The repository is checked out in the web folder.

For each pull request:
1. Call checkout_pr with its number to check out the branch and read the diff.
2. In the web folder, run npm ci, then npm run lint and npm test. Note what fails.
3. Read changed files in full when the diff doesn't show enough context.
4. Call post_review once, with a summary and at most 10 line comments.

Start the summary with the lint and test results. Then cover bugs, missing tests, and security problems, most important first.
Skip style nits the linter would catch. If the change looks good, say so in one sentence.
Never push, merge, or change anything outside the web folder.
```

### The webhook route

GitHub signs each webhook with a secret you choose. The route verifies the signature on the raw body before it parses anything, and uses GitHub's delivery ID as the `deliveryId`, so a redelivered webhook reaches the agent once. Drafts, pull requests from forks, and other events get a `204` and never reach the agent:

```ts agent/channels/github.ts
import { defineChannel, POST } from '@finalai/agents/channels';
import { z } from 'zod';
import { isValidGitHubSignature } from '../lib/verify-github.js';

const pullRequestEvent = z.object({
  action: z.string(),
  number: z.number(),
  repository: z.object({ full_name: z.string() }),
  pull_request: z.object({
    title: z.string(),
    html_url: z.string(),
    draft: z.boolean(),
    user: z.object({ login: z.string() }),
    head: z.object({ repo: z.object({ full_name: z.string() }).nullable() }),
  }),
});

const reviewOn = new Set(['opened', 'reopened', 'ready_for_review']);

export default defineChannel({
  turnPolicy: 'queue',
  routes: [
    POST('/webhook', async ({ request, secrets, receive }) => {
      const body = await request.text();
      const secret = await secrets.get('github-webhook-secret');
      if (!(await isValidGitHubSignature(request, body, secret))) {
        return new Response('invalid signature', { status: 401 });
      }
      if (request.headers.get('x-github-event') !== 'pull_request') {
        return new Response(null, { status: 204 });
      }

      const event = pullRequestEvent.safeParse(JSON.parse(body));
      if (!event.success) return new Response('invalid payload', { status: 400 });

      const { action, number, repository, pull_request: pr } = event.data;
      const fromFork = pr.head.repo?.full_name !== repository.full_name;
      if (!reviewOn.has(action) || pr.draft || fromFork) {
        return new Response(null, { status: 204 });
      }

      await receive({
        target: { kind: 'owner-direct' },
        deliveryId: request.headers.get('x-github-delivery'),
        content: [
          {
            type: 'text',
            text: `Review pull request #${number} in ${repository.full_name}: "${pr.title}" by ${pr.user.login}. ${pr.html_url}`,
          },
        ],
      });
      return new Response(null, { status: 202 });
    }),
  ],
});
```

The signature check lives in `lib/`, so the compiler doesn't treat it as a channel:

```ts agent/lib/verify-github.ts
const encoder = new TextEncoder();

export async function isValidGitHubSignature(request: Request, body: string, secret: string | null) {
  const signature = request.headers.get('x-hub-signature-256')?.replace(/^sha256=/, '');
  if (!secret || !signature) return false;

  const key = await crypto.subtle.importKey(
    'raw',
    encoder.encode(secret),
    { name: 'HMAC', hash: 'SHA-256' },
    false,
    ['verify'],
  );
  const bytes = Uint8Array.from(signature.match(/../g) ?? [], (hex) => parseInt(hex, 16));
  return crypto.subtle.verify('HMAC', key, bytes, encoder.encode(body));
}
```

### The tools

`checkout_pr` fetches the pull request's branch with Git on the sandbox. It passes the GitHub token to Git through environment variables for that one command, so the token never appears in the agent's shell, its files, or the model's context:

```ts agent/tools/checkout_pr.ts
import { defineTool } from '@finalai/agents';
import { z } from 'zod';

export default defineTool({
  description: 'Check out a pull request in the web folder and return its diff against main.',
  inputSchema: z.object({ number: z.number().int().positive() }),
  label: { start: ({ number }) => `Checking out #${number}` },
  async execute({ number }, ctx) {
    const token = await ctx.secrets.get('github-token');
    if (!token) throw new Error('The github-token secret is not set');

    const sandbox = await ctx.getSandbox('computer');
    const git = async (...args: string[]) => {
      const result = await sandbox.run({
        command: 'git',
        args,
        cwd: 'web',
        env: {
          GIT_CONFIG_COUNT: '1',
          GIT_CONFIG_KEY_0: 'http.extraHeader',
          GIT_CONFIG_VALUE_0: `Authorization: Basic ${btoa(`x-access-token:${token}`)}`,
        },
        timeoutMs: 120_000,
        abortSignal: ctx.abortSignal,
      });
      if (result.exitCode !== 0) throw new Error(`git ${args[0]} failed: ${result.stderr}`);
      return result.stdout;
    };

    await git(
      'fetch', '--quiet', 'origin',
      '+refs/heads/main:refs/remotes/origin/main',
      `+refs/pull/${number}/head:refs/remotes/origin/pr/${number}`,
    );
    await git('checkout', '--quiet', '--detach', `origin/pr/${number}`);

    const stat = await git('diff', '--stat', 'origin/main...HEAD');
    const diff = await git('diff', 'origin/main...HEAD');
    return { stat, diff: diff.slice(0, 60_000), truncated: diff.length > 60_000 };
  },
});
```

`post_review` posts a review through GitHub's REST API. It always uses the `COMMENT` event, so the agent can't approve or block a pull request:

<CodeGroup>

```ts agent/tools/post_review.ts
import { defineTool } from '@finalai/agents';
import { z } from 'zod';
import { github } from '../lib/github-api.js';

export default defineTool({
  description: 'Post a review on a pull request in acme/web, with optional line comments.',
  inputSchema: z.object({
    number: z.number().int().positive(),
    summary: z.string().describe('The review body, in Markdown'),
    comments: z
      .array(
        z.object({
          path: z.string().describe('File path relative to the repository root'),
          line: z.number().int().positive().describe('Line number in the new version of the file'),
          body: z.string(),
        }),
      )
      .max(10)
      .optional(),
  }),
  label: { start: ({ number }) => `Posting review on #${number}` },
  async execute({ number, summary, comments = [] }, ctx) {
    const review = await github<{ html_url: string }>(ctx, `/repos/acme/web/pulls/${number}/reviews`, {
      body: summary,
      event: 'COMMENT',
      comments: comments.map((comment) => ({ ...comment, side: 'RIGHT' })),
    });
    return { url: review.html_url };
  },
});
```

```ts agent/lib/github-api.ts
import type { ToolContextIface } from '@finalai/agents';

export async function github<T>(ctx: ToolContextIface, path: string, body: unknown): Promise<T> {
  const token = await ctx.secrets.get('github-token');
  if (!token) throw new Error('The github-token secret is not set');

  const response = await fetch(`https://api.github.com${path}`, {
    method: 'POST',
    headers: {
      authorization: `Bearer ${token}`,
      accept: 'application/vnd.github+json',
      'x-github-api-version': '2022-11-28',
      'user-agent': 'acme-pr-reviewer',
    },
    body: JSON.stringify(body),
    signal: ctx.abortSignal,
  });
  if (!response.ok) throw new Error(`GitHub returned ${response.status}: ${await response.text()}`);
  return (await response.json()) as T;
}
```

</CodeGroup>

<Warning>
The agent runs the pull request's code, including its tests and install scripts, on the cloud computer. The route skips forks for that reason. Only point it at repositories where you trust everyone who can push a branch.
</Warning>

## Build and publish it

<Steps>
  <Step title="Set up the project">
    Create the project the same way as in the [quickstart](/quickstart), then add the files above:

    ```bash
    mkdir pr-reviewer && cd pr-reviewer
    git init
    npm init -y && npm pkg set type=module
    npm install @finalai/agents zod
    npm install --save-dev typescript tsx @types/node
    printf 'node_modules/\n.final/\n.env*\n' > .gitignore
    ```
  </Step>
  <Step title="Add the secrets">
    In the Final dashboard, under **Developer** > **Secrets**, add:

    - `github-token`: a fine-grained personal access token for `acme/web` with read access to **Contents** and read and write access to **Pull requests**.
    - `github-webhook-secret`: a long random string, for example from `openssl rand -hex 32`. You'll give GitHub the same value.
  </Step>
  <Step title="Test the route locally">
    Serve the route with a local secret, then sign a sample payload the way GitHub does:

    ```bash
    AGENT_LOCAL_SECRETS_JSON='{"github-webhook-secret":"local-test-secret"}' \
      npx final-agents dev ./agent
    ```

    ```bash
    BODY='{"action":"opened","number":412,"repository":{"full_name":"acme/web"},"pull_request":{"title":"Add Apple Pay to checkout","html_url":"https://github.com/acme/web/pull/412","draft":false,"user":{"login":"dana"},"head":{"repo":{"full_name":"acme/web"}}}}'
    SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac 'local-test-secret' | sed 's/^.* //')

    curl -i http://localhost:3000/github/webhook \
      -H 'X-GitHub-Event: pull_request' \
      -H 'X-GitHub-Delivery: 7f1c9e20-1b1a-11f0-8e5a-5c3f0d2a9b11' \
      -H "X-Hub-Signature-256: sha256=$SIG" \
      -H 'Content-Type: application/json' \
      -d "$BODY"
    ```

    You get `HTTP/1.1 202 Accepted`, and the dev server logs the message the agent would receive:

    ```text
    receive (github): {"target":{"kind":"owner-direct"},"deliveryId":"7f1c9e20-1b1a-11f0-8e5a-5c3f0d2a9b11","content":[{"type":"text","text":"Review pull request #412 in acme/web: \"Add Apple Pay to checkout\" by dana. https://github.com/acme/web/pull/412"}]}
    ```

    Change one character of `BODY` after computing `SIG`, and you get `401`.
  </Step>
  <Step title="Compile, register, and publish it">
    ```bash
    npx final-agents build ./agent
    ```

    ```text
    agent: PR Reviewer
    description: Reviews new pull requests in acme/web and posts the results on GitHub.
    harness: package:@finalai/final-agent-provider/harnesses/serverless-final
    mcp servers: authored (worker)
    sandboxes: computer
    base tools: shell → computer, files → computer
    channels: final, github
    ...
    secrets: github-token, github-webhook-secret
    ...
    ```

    Register the `pr-reviewer` slug once, as in the [quickstart](/quickstart#register-the-agent), then publish. The CLI prints the route's public URL:

    ```bash
    npx final-agents publish ./agent --agent pr-reviewer
    ```

    ```text
    channel github (chbind_9Qw4...):
      POST https://agents.final.ai/acme/pr-reviewer/github/webhook
    ```
  </Step>
  <Step title="Add the webhook in GitHub">
    In the `acme/web` repository, open **Settings** > **Webhooks** > **Add webhook**. Set **Payload URL** to the route's URL, **Content type** to `application/json`, and **Secret** to the value of `github-webhook-secret`. Under events, choose **Let me select individual events** and select **Pull requests**.
  </Step>
</Steps>

## Try it

Open a pull request in `acme/web`, or mark a draft as ready for review. Within a few minutes, a review from the token's account appears on the pull request:

```text
Lint passes. 2 of 418 tests fail, both in src/checkout/apple-pay.test.ts.

1. **Missing currency check.** createApplePaySession accepts any currency, but the
   merchant account only supports USD and CAD. Non-USD carts will fail at payment time.
2. **No test for a canceled payment sheet.** onCancel resets the cart state, which is
   the path that broke in #1203.

  src/checkout/apple-pay.ts:42
  > currency comes straight from the cart here. Validate it against SUPPORTED_CURRENCIES.
```

The webhook messages and the agent's replies go to the agent owner's direct conversation. Read it with `client.conversations.direct({ agent: 'pr-reviewer' })` when you want to see which commands the agent ran and why.

## Make it yours

- **Re-review on every push.** Add `'synchronize'` to `reviewOn`, and tell the agent in `instructions.md` to focus on what changed since its last review.
- **Post to a team room instead.** Change the target to `bound-conversation` and [attach the channel](/build/channels#connect-it-to-a-conversation) to your code review room, as in the [deploy watcher](/examples/deploy-watcher).
