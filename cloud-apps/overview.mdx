Final Cloud Apps runs your code from Git. You describe the app in one small file, push your code, and run one command. Final builds it, checks that it's healthy, and gives it a URL, logs, and a history of every deployment.

Here's a complete web app configuration:

```yaml final-cloud.yaml
name: acme-api
type: web
build:
  method: dockerfile
port: 3000
health:
  path: /health
```

And here's how you ship it:

```bash
git push final HEAD:main
npx final-cloud deploy acme-api
```

## How a deploy works

When you run `final-cloud deploy`, Final reads `final-cloud.yaml` from the commit you pushed, builds the app, and starts the new version next to the old one. Traffic moves over only after the new version passes its health check. If it doesn't pass, the deployment fails and the version that was already running keeps serving.

Final also asks you to confirm any deploy that opens up access, such as making the app public or giving it a secret or database for the first time. You always see what's changing before it ships.

| Term | What it means |
| --- | --- |
| App | One deployable thing with its own URL, logs, settings, and history. Each app has a type. |
| Manifest | The `final-cloud.yaml` file in your repository that describes the app. See the [manifest reference](/cloud-apps/manifest). |
| App repository | The Git repository Final creates for each app. You push code to it, and Final deploys from it. |
| Deployment | One release of one commit. Every deployment has an ID, a status, and its own build and deploy logs. |

## Before you start

You need Node.js 26 or later, Git, and a [Final API key](/api-keys) with the `apps:read` and `apps:write` permissions, exported as `FINAL_API_KEY`. The `final-cloud` CLI comes from the `@finalai/cloud` npm package, so `npx final-cloud` works in any project.

You can also see every app in the [Final dashboard](https://console.final.ai) under **Developer** > **Cloud**, with tabs for its deployments, logs, metrics, and settings.
