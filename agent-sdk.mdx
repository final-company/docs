The Agent SDK lets you define an agent as one TypeScript value: its instructions, its tools, and what it **requires** to run. Whoever starts the agent **provides** those requirements: the harness that runs the model loop, where its files and shell live, and the services it talks to. Final runs the orchestration: model calls, tool calls, approvals, and history.

Here's a complete agent and the code that starts it:

<CodeGroup>

```ts agent.ts
import { defineAgent, defineServerlessTool } from '@finalai/agents';
import * as z from 'zod';

const releaseChecklist = defineServerlessTool({
  description: 'List the checks a release must pass before it ships.',
  inputSchema: z.object({ version: z.string() }),
  execute: async ({ version }) => ({
    version,
    checks: ['CI is green on main', 'CHANGELOG.md has an entry', 'Release owner signed off'],
  }),
});

export const agent = defineAgent({
  name: 'Release Assistant',
  instructions: 'Call release_checklist for the version, then list each check as done or missing.',
  tools: { release_checklist: releaseChecklist },
  require: { harness: { permissionMode: 'ask' } },
});
```

```ts run.ts
import { createClient } from '@finalai/agents/client';
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';
import { workers } from '@finalai/agents/sandboxes';
import { agent } from './agent.js';

const client = createClient({ auth: { apiKey: process.env.FINAL_API_KEY! } });
const project = client.project({ id: process.env.FINAL_PROJECT_ID! });
const runtime = await project.sandboxes.create(workers(), { idempotencyKey: 'workers' });

const { response } = await project.sessions.create({
  agent,
  provide: {
    harness: serverlessFinal({
      model: 'deepseek-v4.1-flash',
      inference: finalCredits(),
      environment: runtime.id,
    }),
  },
  message: 'Is 1.2.0 ready to ship?',
});

console.log(await response!.text());
```

</CodeGroup>

Nothing is built or deployed first. The agent's document, including the source of its serverless tools, travels with the call that starts it. The [quickstart](/quickstart) walks through it step by step.

## How it works

1. **The agent states what it requires.** `require.harness` sets a permission ceiling, `require.compute` names the capabilities the model drives (`files`, `shell`, `computerUse`, `browserUse`), and `require.integrations` names slots for MCP servers. The agent names no machine, model, server, or credential.
2. **The caller provides it.** Every call that starts work takes a plain `provide` object: harness settings, a sandbox per capability, and an integration per slot. If anything required is missing, the call fails with `requirements_unmet` and nothing is created.
3. **Final runs it.** A **session** is one thread with the agent. Each message starts a **turn**: the harness calls the model, Final runs tools and asks for approvals, and the output streams back.

[How agents work](/concepts) explains these ideas in more depth.

You'll need a [Final API key](/api-keys) and a project ID to start agents. If you want to use Claude Code or another existing AI client with your connected accounts instead of building an agent, use the [MCP gateway](/mcp-gateway/overview).
