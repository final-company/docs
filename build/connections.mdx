title: "Connections"
description: "Give your agent tools from an MCP server, like your issue tracker or Final's connected accounts."

A connection gives your agent every tool an MCP server offers, without writing a tool for each one. Use a connection when a service already has an MCP server, like your issue tracker, or to reach the accounts your organization has connected in Final. Write your own [tool](/build/tools) when you need custom logic.

## Connect an MCP server

Add a file to `agent/connections/`. The file name becomes the connection's name. This one connects Linear's MCP server, exposes three of its tools, and asks a person before creating an issue:

```ts agent/connections/linear.ts
import { defineMcpClientConnection } from '@finalai/agents';
import { always } from '@finalai/agents/approval';

export default defineMcpClientConnection({
  url: 'https://mcp.linear.app/mcp',
  auth: { secretKey: 'linear-api-key', headerName: null },
  tools: {
    allow: ['list_issues', 'get_issue', 'create_issue'],
    approval: { create_issue: always() },
  },
});
```

`auth` names a [secret](/operate/authentication#use-secrets-in-your-code) that holds the server's token. Create it under **Developer** > **Secrets** in the dashboard. Final sends it as `Authorization: Bearer <token>` on every request, and the token never reaches the model or the harness. Set `headerName` to send it in a different header instead.

A connection that declares `secretKey` also declares that agent secret. Its publication and later source changes require an organization admin with project edit access. A project API key can upload and compile the initial draft, but cannot approve it; follow [draft upload and admin publication](/operate/publishing#publish-code-that-uses-secrets).

Connections reach MCP servers over HTTP. Servers that only run locally over stdio aren't supported.

## Choose which tools the agent gets

Without a `tools` setting, the agent gets every tool the server lists. Narrow that down to what the agent needs, so it has fewer wrong choices and can't reach tools it shouldn't use:

| Setting | What it does |
| --- | --- |
| `allow` | Only expose these tools. |
| `deny` | Hide these tools, even if `allow` matches them. |
| `approval` | Ask a person before these tools run, with the same [policies](/build/tools#ask-before-a-tool-runs) as your own tools. |
| `load` | List these tools to the agent up front. Other exposed tools stay available through search. |

Entries can be exact names or `*` patterns. When several patterns match a tool, the most specific one wins. This connection allows every read tool and every issue tool, but never deletes and always asks before updates:

```ts
tools: {
  allow: ['list_*', 'get_*', '*_issue'],
  deny: ['delete_*'],
  approval: { 'update_*': always() },
},
```

`allow` and `deny` also accept MCP annotation selectors, such as `{ readOnlyHint: true }` to allow every tool the server marks read-only. That relies on the server labeling its tools accurately, so use selectors only with servers you trust.

To ask before every tool on a connection, set the top-level `approval: always()` instead. Entries in `tools.approval` still take precedence.

## Connect to Final

`defineFinalConnection()` gives the agent Final's own MCP tools, plus the tools of every service connected under **Connectors** in Final. It's the same set of tools the [MCP gateway](/mcp-gateway/overview) gives Claude Code or Codex. No URL or token is needed:

```ts agent/connections/final.ts
import { defineFinalConnection } from '@finalai/agents';

export default defineFinalConnection();
```

Connected services can add a lot of tools, so the agent doesn't see them all up front. It searches for the ones it needs, the same way the MCP gateway works. The same `tools` settings apply, so you can keep the agent away from tools it shouldn't use:

```ts agent/connections/final.ts
import { defineFinalConnection } from '@finalai/agents';

export default defineFinalConnection({
  tools: { deny: ['create_agent_session'] },
});
```

## Connection reference

<ParamField path="url" type="string" required>
  The MCP server's HTTP endpoint.
</ParamField>

<ParamField path="auth" type="{ secretKey, headerName }">
  The secret to send with each request. `headerName: null` sends it as a bearer token.
</ParamField>

<ParamField path="headers" type="Record<string, string>">
  Extra headers to send with each request. Don't put tokens here; use `auth`.
</ParamField>

<ParamField path="tools" type="object">
  `allow`, `deny`, `approval`, and `load`, as described in [choose which tools](#choose-which-tools-the-agent-gets).
</ParamField>

<ParamField path="approval" type="never() | always()" default="never()">
  The approval policy for every tool on this connection that `tools.approval` doesn't cover.
</ParamField>

<ParamField path="description" type="string">
  A short note on what the server is for.
</ParamField>
