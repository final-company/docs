A channel connects an outside surface to a Final chat. It identifies a **person**, resolves a **place**, and translates **events** in both directions. The agent is whoever participates in that chat. A channel never chooses a Final member by email or supplies a raw member ID.

## Use a provider channel

For a bot dedicated to one agent, add the provider factory to that agent's directory:

```ts agent/channels/slack.ts
import { slackChannel } from '@finalai/final-agent-provider/channels/slack';
export default slackChannel();
```

Omit `baseUrl` to use the deployment’s public ingress; an explicit value is preserved for a custom proxy. Voice OAuth endpoint overrides follow the same rule.

The Discord, GitHub, and Linear factories live at the corresponding `channels/discord`, `channels/github`, and `channels/linear` exports. Connect your own provider application in the agent's project. Your application's credentials and provider verification run through the same package code as an official Final application.

For a shared application that serves several chats and agents, install a project-scoped channel against an existing connector installation:

```bash
npx final-agents channel install @finalai/slack-channel \
  --project proj_your_project --install cinst_your_install
```

`@finalai/slack-channel`, `@finalai/discord-channel`, `@finalai/github-channel`, and `@finalai/linear-channel` are CLI aliases for the matching factories in `@finalai/final-agent-provider/channels/*`. They do not identify separate npm packages. The existing `final-agents` executable provides this command.

## Link a person and connect a place

**Link** proves control of your provider account while you are signed in to Final. Slack uses its OpenID flow; Discord, GitHub, and Linear use user OAuth. A link belongs to the application's installation or channel binding. A different application cannot reuse it. Unlinking, leaving the workspace, or a provider revocation ends that authority.

**Connect** selects the Final chat for a provider place, such as a Slack thread or GitHub pull request. Only someone who can manage the chat can connect it. A shared place connects to a Shared chat. Linked direct messages can use your own chat with the agent. **Disconnect** ends a route; **Unlink** ends your account proof. **Follow** subscribes a chat to changes in an external resource without making it that resource's conversation.

A place has two visible policies:

| Policy | Values |
| --- | --- |
| Replies | `origin` sends replies to the place that started the turn. `all` mirrors every message in the connected chat. |
| Audience | `members` requires linked Final members. `anyone` also accepts captioned input from unlinked people. |

Shared provider bots default to `members`. Unlinked input does not impersonate a member or use personal credentials. Slack and Discord read no thread history by default. Set `history: 'linked-members'` to include only messages whose authors are currently linked members.

## Add an authenticated webhook

`webhookChannel()` accepts a standard event envelope and verifies its HMAC signature:

```ts agent/channels/deploys.ts
import { webhookChannel } from '@finalai/final-agent-provider/channels/webhook';
export default webhookChannel({ secret: 'deploy-webhook-secret' });
```

Connect a `webhook` place, such as `production-deploys`, to a chat. Then POST this envelope to the binding's `/webhook` route:

```json
{
  "place": { "kind": "webhook", "id": "production-deploys" },
  "label": "Production deployment",
  "content": [{ "type": "text", "text": "web 1.2.0 deployed successfully" }],
  "idempotencyKey": "deploy:1042"
}
```

Set `X-Final-Signature` to `sha256=` followed by the hexadecimal HMAC-SHA256 of the exact request body, using `deploy-webhook-secret`. Reuse the idempotency key when retrying the same event. Invalid signatures return `401`; malformed envelopes return `400`. The published route is `/b/<bindingId>/webhook`.

## Write a custom channel

Use `defineChannel` when you need a different provider or transport. Resolve people and places through the context, then post through the returned handles:

```ts
import { defineChannel } from '@finalai/agents/channels';

export default defineChannel({
  name: 'your-provider',
  credentials: { app: null },
  identity: { kind: 'none' },
  places: { kinds: ['topic'] },
  receive: async (_input, _ctx) => ({ ignored: true, reason: 'no-event-mapping' }),
});
```

Add a `redirect` proof or `challenge` proof before posting as members. `people.resolve` returns a member handle, a link URL, or a refusal. `places.resolve` returns a conversation handle or a connect URL. Handles are opaque and scoped to the current invocation; retain provider references in `store`, then resolve fresh handles later.

Use `conversation(handle).post` for a linked person's real message. Use `input` for a nonhuman event, or include `principal` for an unlinked person's captioned input on an `anyone` place. `attach` records content without starting a turn. `edit`, `remove`, and `react` target the original external key. `decisions.resolve` answers only options the pending decision actually offers, under the responding person's authority.

Routes receive the channel context plus `request` and `receive`. Verify the provider signature before calling `receive`. HTTP and binary WebSocket routes mount at `/b/<bindingId><path>`. A listener receives the same context plus an abort signal and can maintain an outbound provider connection. Package channels read common OAuth/signing metadata with `credentials.appInfo()` and select tenant API credentials with `credentials.app({tenant})`; metadata never includes an access token.

Semantic handlers include `message.delta`, `message.completed`, `tool.started`, `tool.completed`, `plan.updated`, `decision.created`, `decision.resolved`, and `turn.completed`. Origin-bearing edits, removals, and reactions return to their provider. `message.posted` supports `replies: 'all'`. Keep delivery receipts in `store`: completion events may be delivered more than once.

## Test it locally

Run `npx final-agents dev ./agent` to preview HTTP and WebSocket routes. Set declared local secret values with `AGENT_LOCAL_SECRETS_JSON`. Provider signature previews also accept `AGENT_LOCAL_APP_INFO_JSON`, keyed by the declared app name, with `clientId`, `clientSecret`, and optional `signingSecret`; this metadata contains no access token. The preview verifies and parses requests, then logs what `receive` would accept; it does not run an agent or grant member, chat, application, or media capabilities. Publish and connect a real place to test replies and identity proof.

## Voice

`voiceChannel()` combines live transcription, member messages, the conversation's turn stream, and streaming synthesis. It authenticates through Final OAuth with PKCE; another voice client uses the same OAuth and WebSocket protocol. `phoneChannel()` wraps that core in Twilio signed call webhooks and 8 kHz mu-law Media Streams. Link a phone number through an SMS challenge. Each linked call also requires a fresh SMS code entered on the call before it can act as that member. An explicitly configured `anyone` line accepts captioned input without member authority.

Voice posts final utterances only. New speech interrupts playback and cancels the active turn. Spoken yes/no can answer a matching once-only permission or a simple confirmation; forms remain in Final. Browser clients enable recording in the `start` frame only after displaying a recording notice. Phone calls announce recording before audio starts. Enabled recordings are attached without starting another turn, as PCM16 WAV segments of at most 10 MiB including serialization, with the last segment saved when the call ends.

The Final room file remains `channels/final.ts`, configured with `finalChannel({ onMessage, renderer, events })`. It customizes Final's own chat surface and is separate from an external channel binding.
