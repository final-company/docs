A channel application translates an outside surface into people, places, and events. Its source compiles with your agent into an ordinary bundle. The SDK provides the same capabilities for your application regardless of provider. Write the provider integration in your own application source.

## Write a custom channel

Install the authoring SDK with `pnpm add @finalai/agents zod`, then add `channels/topics.ts` to your agent directory. This complete example accepts signed topic events. Create the project secret `topic-hook-secret` first and store the same value with the event producer. [Publish through admin review](/operate/publishing#publish-code-that-uses-secrets), including the channel file in the draft.

```ts agent/channels/topics.ts
import { defineChannel, POST } from '@finalai/agents/channels';
import { z } from 'zod';

const eventSchema = z.object({ id: z.string(), topic: z.string(), text: z.string() });

export default defineChannel({
  name: 'topics',
  credentials: { app: null, secrets: ['topic-hook-secret'] },
  identity: { kind: 'none' },
  places: { kinds: ['topic'] },
  routes: [POST('/events', async (ctx) => {
    const body = await ctx.request.text();
    const secret = await ctx.credentials.secret('topic-hook-secret');
    const signature = ctx.request.headers.get('x-topic-signature') ?? '';
    if (secret == null || !/^[a-f0-9]{64}$/i.test(signature))
      return new Response('Invalid signature', { status: 401 });
    const key = await crypto.subtle.importKey('raw', new TextEncoder().encode(secret),
      { name: 'HMAC', hash: 'SHA-256' }, false, ['verify']);
    const bytes = new Uint8Array(Array.from({ length: 32 }, (_, i) =>
      Number.parseInt(signature.slice(i * 2, i * 2 + 2), 16)));
    if (!(await crypto.subtle.verify('HMAC', key, bytes, new TextEncoder().encode(body))))
      return new Response('Invalid signature', { status: 401 });
    let event: z.infer<typeof eventSchema>;
    try { event = eventSchema.parse(JSON.parse(body)); }
    catch { return new Response('Invalid event', { status: 400 }); }
    const result = await ctx.receive(event);
    return Response.json(result, { status: 'accepted' in result && !result.accepted ? 403 : 202 });
  })],
  receive: async (input, ctx) => {
    const event = eventSchema.parse(input);
    const place = { kind: 'topic', id: event.topic };
    const route = await ctx.places.resolve(place);
    if (route.kind !== 'connected')
      return { accepted: false, refusal: { refused: 'unconnected',
        message: 'Connect this topic to a chat.', connectUrl: route.connectUrl } };
    const result = await ctx.conversation(route.conversation).input({
      label: 'Topic event', content: [{ type: 'text', text: event.text }],
      origin: { place }, idempotencyKey: event.id,
    });
    return 'refused' in result ? { accepted: false, refusal: result } : { accepted: true };
  },
  events: {
    'turn.completed': async (event, ctx) => { ctx.log('Topic turn completed', { turnId: event.turnId }); },
  },
});
```

Send JSON such as `{"id":"event-1042","topic":"deployments","text":"Release deployed"}`. Set `x-topic-signature` to the hexadecimal HMAC-SHA256 of the exact body. A first event discovers the place and returns its Connect link; connect it to a chat, then retry the same event ID. This channel is inbound-only: replies stay in Final. See the complete [deployment watcher](/examples/deploy-watcher).

The example uses nonhuman `input`. To post as a member, implement a redirect or challenge identity mechanism, resolve the proven provider principal with `people.resolve`, and pass its returned member handle to `conversation(...).post({ from, ... })`. Never match members by email. Handles are invocation-scoped: store provider references and resolve fresh handles later.

## Installed application credentials

Declare `credentials: { app: 'your-application' }` when a channel needs a connected application. Publishing requires normal administrator approval for that grant. An installation selected for a running binding must match the declaration. Installed tokens and client secrets stay outside the bundle.

| Operation | Purpose |
| --- | --- |
| `credentials.client()` | Read the public OAuth client ID. |
| `credentials.verify(...)` | Verify signed bytes with installed signing material. |
| `credentials.exchange(...)` | Exchange an OAuth grant for a short-lived opaque handle. |
| `credentials.fetch(url, { credential })` | Make an authorized provider request using an app credential, OAuth handle, or no credential. |
| `credentials.connect({ url, signal })` | Open a provider socket; inject credentials only into specified JSON leaves when sending. |
| `credentials.secret(name)` | Read an explicitly declared project secret. |

`ChannelCredentialKind`, signing algorithms, signature encodings, and OAuth client authentication enums are exported by `@finalai/agents/channels`. Requests are restricted to the application's approved destinations. Opaque OAuth handles are temporary and cannot be reused across invocations. They do not provide persistent person-token storage or automatic refresh. Raw installed tokens, signing secrets, and OAuth client secrets are never returned to application code. Socket handshake-header authentication is not currently exposed; the socket API supports credential injection in JSON frames.

Use `ctx.binding.url` to construct callback URLs, such as `${ctx.binding.url}/oauth/callback`. It is supplied uniformly by the host; do not hardcode a deployment origin in application source.

## Install a published channel

For a reusable application, first [upload its source draft](/operate/publishing#publish-code-that-uses-secrets), including its `channels/<key>.ts` module. A signed-in organization admin with project Editor access chooses **Publish source only** in the agent's Code view. This approves an immutable revision without changing the source agent's current revision, routes, listeners, or schedules. It does not require an application installation or secret values in the source project, because the code is not activated there. App and secret declarations still require approval.

Copy the resulting `arev_…` revision ID. Connect your application and configure any declared project secrets in the target project. That project must be the source definition's project or a descendant of it in the same organization. When the channel declares app credentials, the selected installation must match that declaration.

```bash
npx final-agents channel install support --revision arev_your_revision \
  --project prj_your_project --install app_your_install
```

Set `FINAL_API_KEY` with `agents:write` and project Editor access. Copy the IDs from Final, and use the exact route URLs printed by the command. This creates a separate binding pinned to that source revision; later source publications do not automatically update it.

To update an active installation, publish a new source revision, then run the command with `--replace` or pass `replace: true` to the client. Without that explicit option, a different revision or configuration is rejected. Replacement keeps the binding ID and base URL. Preserve provider-facing route paths in your code to keep those endpoint URLs usable. An archived binding cannot be replaced.

For a channel running directly on its source agent, use ordinary **Publish** instead. App-credential channels must select an explicit installation: import `bundleRef` from `@finalai/agents` and add `{ channel: bundleRef('channels/support'), install: 'app_your_install' }` to `agent.ts`'s `channels` array. The export names the existing `channels/support.ts` module; the compiler derives its credentials and routes from that module. Optional `key` and `config` select the binding name and configuration.

Save the client equivalent as `configure-channel.ts`, replace the IDs, and run `node configure-channel.ts` with Node.js 26 or later:

```ts configure-channel.ts
import { createClient } from '@finalai/agents/client';

const client = createClient({
  host: 'https://agent-session.final.ai/api',
  auth: { apiKey: process.env.FINAL_API_KEY! },
});
try {
  console.log(await client.channelBindings.create({
    projectId: 'prj_your_project',
    connectorInstallId: 'app_your_install',
    revisionId: 'arev_your_revision',
    channelKey: 'support',
    config: {},
  }));
} finally {
  client.close();
}
```

## Link a person and connect a place

**Link** proves a provider account while the person is signed in to Final. Each application owns its OAuth or challenge protocol. **Connect** maps a provider place to a chat the person can manage. **Disconnect** removes that route. **Unlink** revokes account proof.

Shared provider places connect to group chats. Direct messages may connect to the linked person's chat. `places.defaults` declares whether the application permits captioned unlinked input (`audience: 'anyone'`) and automatic group creation. Such input never receives member authority or personal credentials.

The `origin` reply policy sends replies to the place that started a turn. An explicit `all` policy shares future chat messages with that place. Applications decide which provider APIs can represent edits, removals, reactions, and streamed replies. Do not promise a mutation when the provider cannot perform it.

**Follow** creates a resource observation without making that resource the chat's conversation. Implement both `resources.resolve({ url, principal }, ctx)` and `resources.authorize({ place, principal }, ctx)`. The first parses a resource into a canonical place; the second checks current provider access using an appropriate provider API. Choose an authorization mechanism your application can revalidate; account linking does not automatically supply a provider user token. The host rechecks authorization for later observation access, including cached handles. Use `places.follow(place, { by, conversation })` and `places.unfollow(...)` with a currently linked person.

## Create a Shared chat in Final

Do this while signed in to the Final web app as a person with edit access to the agent's project:

1. Open the project where you published the agent.
2. Open the project's **+** menu and choose **New Chat**.
3. Select **your own name and the published agent**, then choose **Start chat**. Selecting just one agent opens your direct chat instead, so include yourself to create a Shared group chat in this project.
4. Keep this as the only agent for the examples below. The first selected agent uses `default` routing, so outside events reach it without a separate mention.

You own the new chat and can select it on the Connect page. Create it before following a provider's Connect notice. The project API key used to publish an agent cannot create a person-owned Shared chat; use your signed-in Final session for this step.

## Routes, listeners, and events

HTTP and binary `WS` routes receive `ctx.request` or `ctx.socket`. A `listeners: [{ key, run }]` entry maintains an outside connection for the binding. Close provider work and return when `ctx.signal` aborts. Pass the signal to credential and media operations.

Use `events` for messages, tools, plans, decisions, and turn completion. `message.posted` supports outward mirroring; edit, removal, and reaction events allow an application to update existing provider copies. Save delivery receipts in `ctx.store`, scope them to the actual provider destination, and preserve deletion tombstones to prevent retry resurrection. Acknowledge provider interactions promptly and perform slower work asynchronously when the provider protocol permits it.

`conversation(...).attach` saves content without starting a turn. `edit`, `remove`, and `react` target an external key. `decisions.resolve` checks the responding person's authority. Never select between concurrent approvals using an ambiguous yes/no.

`ctx.media.transcribe` and `ctx.media.synthesize` are streaming primitives for authored audio applications. Such an application owns its OAuth proof, transport protocol, cancellation, recording notice, and playback lifecycle.

## Test it locally

```bash
AGENT_LOCAL_SECRETS_JSON='{"topic-hook-secret":"local-test-value"}' \
  pnpm exec final-agents dev ./agent
```

The local preview verifies routes and prints what would be received without running the agent. For the example above, post to `http://localhost:3000/topics/events`. Installed application operations require a host-provided opaque credential facade; the CLI does not accept raw installed credential JSON.

Final's own room renderer is configured separately in `channels/final.ts` with `finalChannel({ onMessage, renderer, events })` from `@finalai/agents/channels/final`.
