---
title: "Instructions and skills"
description: "Tell your agent how to behave, and give it procedures to follow when a task calls for one."
---

Instructions are the standing guidance the agent reads on every turn: its role, its tone, and the rules it follows. Skills are procedures it loads only when a task needs one, like "how we triage a failed release." Keep instructions short and general, and move anything long or task-specific into a skill.

## Write instructions

Put the agent's instructions in `agent/instructions.md`:

```markdown agent/instructions.md
You help maintainers prepare releases for the acme-web repository.

Before you assess a release, call release_checklist for its version.
Separate what you've confirmed from what you're assuming.
Never mark a release ready without the release owner's sign-off.
End with the version, the open checks, and the next action.
```

Good instructions say what the agent is for, which tools to use when, and what a finished answer looks like. Instructions guide the model but don't enforce anything, so if an action must never happen without a person's OK, also add an [approval policy](/build/tools#ask-before-a-tool-runs).

### Split long instructions

As instructions grow, split them into files in `agent/instructions/`. The compiler loads `instructions.md` first, then each file in `instructions/` in filename order. Number the files if order matters:

<Tree>

- agent/
  - instructions.md
  - instructions/
    - 10-release-policy.md
    - 20-writing-style.md

</Tree>

### Compute instructions when a session starts

Sometimes the right instructions depend on who's asking or where. Export `defineDynamic(...)` from a `.ts` file in `instructions/`, and return `defineInstructions(...)` from its `session.started` handler:

```ts agent/instructions/context.ts
import { defineDynamic, defineInstructions } from '@finalai/agents';

export default defineDynamic({
  description: 'Tells the agent whether it is in a shared conversation.',
  preview: 'You are working in conversation conv_...',
  events: {
    'session.started': async (_event, ctx) =>
      defineInstructions({
        content: ctx.session.conversation
          ? `You are working in the conversation "${ctx.session.conversation.title ?? 'Untitled'}".`
          : 'You are working on a standalone task.',
      }),
  },
});
```

The handler runs once when a session starts, and its result stays fixed for the rest of that session. `description` and `preview` show what the fragment contains before any session runs. Handlers can read [secrets](/operate/authentication#use-secrets-in-your-code) and call APIs with `fetch`. Use a `turn.started` handler instead to recompute the value on every turn.

## Package a skill

A skill is a folder in `agent/skills/` with a `SKILL.md` file. Its frontmatter `description` tells the agent when the skill applies, and the body holds the steps:

```markdown agent/skills/triage/SKILL.md
---
name: triage
description: Triage a failed release check into an issue with an owner and severity.
---

1. Read checklist.md to find which team owns the failing check.
2. Search for an existing issue before you create one.
3. Create the issue with the release version, the failing check, and the owner.
4. Reply with a link to the issue and the next step.
```

Any other file in the folder, like `checklist.md` here, ships with the skill, and the agent can read it while following the steps. A skill that fits in one file can be `agent/skills/triage.md` instead.

The agent sees each skill's name and description up front, and loads the full steps only when it decides the skill applies. That keeps long procedures out of every turn.

## Instructions, skills, or something else

| You want the agent to... | Use |
| --- | --- |
| Always follow a rule or keep a persona | [Instructions](#write-instructions) |
| Follow a multi-step procedure for some tasks | [A skill](#package-a-skill) |
| Look up current data, like release status | [A tool](/build/tools) |
| Keep notes or files while it works | [Sandbox files](/build/sandboxes) |
| Remember facts across sessions | Not supported yet. Put stable facts in instructions or skills. |
