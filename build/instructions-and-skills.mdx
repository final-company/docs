---
title: "Instructions and skills"
description: "Tell your agent how to behave, and give it procedures to follow when a task calls for one."
---

Instructions are the standing guidance the agent reads on every turn: its role, its tone, and the rules it follows. Skills are procedures it loads only when a task needs one, like "how we triage a failed release." Keep instructions short and general, and move anything long or task-specific into a skill.

## Write instructions

Keep the instructions in a Markdown file beside the agent module and pass it with `markdown`:

```markdown instructions.md
You help maintainers prepare releases for the acme-web repository.

Before you assess a release, call release_checklist for its version.
Separate what you've confirmed from what you're assuming.
Never mark a release ready without the release owner's sign-off.
End with the version, the open checks, and the next action.
```

```ts agent.ts
import { defineAgent, markdown } from '@finalai/agents';

export const agent = defineAgent({
  name: 'Release Assistant',
  instructions: markdown('./instructions.md', { from: import.meta.url }),
  require: { harness: { permissionMode: 'ask' } },
});
```

`from: import.meta.url` makes the path relative to the module. The file is read when the agent's document is made, and its text becomes part of the document. Pass a string instead for short instructions.

Good instructions say what the agent is for, which tools to use when, and what a finished answer looks like. Instructions guide the model but don't enforce anything, so if an action must never happen without a person's OK, also add an [approval](/build/tools#ask-before-a-tool-runs).

### Split long instructions

Pass an array, and the parts are joined in order with a blank line between them:

```ts
instructions: [
  markdown('./instructions.md', { from: import.meta.url }),
  markdown('./release-policy.md', { from: import.meta.url }),
  markdown('./writing-style.md', { from: import.meta.url }),
],
```

Instructions are part of the agent's document, so they're the same in every session. Context that depends on who's asking or where belongs in the message, or in a conversation participant's per-chat `instructions` (see [conversations](/client/conversations#change-an-agents-settings)).

## Package a skill

A skill is a directory with a `SKILL.md` file. Its front matter `description` tells the agent when the skill applies, and the body holds the steps:

```markdown skills/triage/SKILL.md
---
name: triage
description: Triage a failed release check into an issue with an owner and severity.
---

1. Read checklist.md to find which team owns the failing check.
2. Search for an existing issue before you create one.
3. Create the issue with the release version, the failing check, and the owner.
4. Reply with a link to the issue and the next step.
```

Pass the directory to the agent with `skill`:

```ts
import { skill } from '@finalai/agents';

skills: [skill('./skills/triage', { from: import.meta.url })],
```

Every other file in the directory, like `checklist.md` here, ships with the skill, and the agent can read it while following the steps. For a skill that fits in a few lines, define it inline:

```ts
skill({
  name: 'changelog',
  description: 'Write a changelog entry for a release.',
  instructions: 'List user-facing changes first, then fixes, each with its pull request.',
}),
```

The agent sees each skill's name and description up front, and loads the full steps only when it decides the skill applies. That keeps long procedures out of every turn.

Some harnesses don't load skills. If the agent can work without them, add `skills` to `require.harness.optionalFeatures`; otherwise those harnesses are refused as [unsuitable](/build/requirements#nothing-starts-with-something-missing).

## Instructions, skills, or something else

| You want the agent to... | Use |
| --- | --- |
| Always follow a rule or keep a persona | [Instructions](#write-instructions) |
| Follow a multi-step procedure for some tasks | [A skill](#package-a-skill) |
| Look up current data, like release status | [A tool](/build/tools) |
| Start with files in its workspace | [`workspace`](/build/configuration#what-the-agent-knows) seed files |
| Keep notes or files while it works | [Sandbox files](/build/sandboxes) |
