An integration gives the agent every tool an MCP server offers, without writing a tool for each one: your issue tracker, your code host, or Final's own gateway. The agent declares named **slots** with what each is for and the most it may expose. The caller fills each slot with an **integration**, a project resource that holds the server's URL and how calls to it authenticate. Each person's own sign-in happens at runtime, the first time a call needs it.

An integration can also hold a credential for a sandbox's outbound traffic instead of, or as well as, an MCP server. See [credentials for a sandbox's traffic](#credentials-for-a-sandboxs-traffic).

## Require a slot

```ts agent.ts
import { defineAgent } from '@finalai/agents';

export const agent = defineAgent({
  name: 'Triage Assistant',
  instructions: 'You file bug reports with an owner and severity, after checking for duplicates.',
  require: {
    harness: { permissionMode: 'ask' },
    integrations: {
      issues: {
        description: 'Issue tracker where bugs are filed',
        tools: { allow: ['list_issues', 'get_issue', 'create_issue'] },
        approvals: { create_issue: 'ask' },
      },
    },
  },
});
```

The slot name, `issues`, is how the agent refers to it; it says nothing about which server fills it. Final never fills a slot by matching names. Mark a slot `optional: true` if the agent can work without it; when it isn't provided, its tools are absent.

## Choose which tools the agent gets

A slot's policy is a ceiling over whatever integration fills it. Without `tools`, the agent gets every tool the server lists. Narrow that to what the agent needs, so it has fewer wrong choices and can't reach tools it shouldn't use:

| Setting | What it does |
| --- | --- |
| `tools.allow` | Only expose these tools. |
| `tools.deny` | Hide these tools, even if `allow` matches them. |
| `tools.load` | List these tools to the agent up front. Other exposed tools stay reachable through search. |
| `tools.allowAnnotations`, `tools.denyAnnotations` | Select tools by their MCP annotations, such as `{ readOnlyHint: true }`. |
| `approvals` | `'ask'` or `'allow'` per tool, so a person confirms calls first. |

Entries can be exact names or `*` patterns. `deny` wins over `allow`, and when several patterns match a tool, the most specific one governs. This slot allows every read tool and every issue tool, never deletes, and asks before updates:

```ts
issues: {
  description: 'Issue tracker',
  tools: { allow: ['list_*', 'get_*', '*_issue'], deny: ['delete_*'] },
  approvals: { 'update_*': 'ask' },
},
```

Annotation selectors rely on the server labeling its tools accurately, so use them only with servers you trust.

## Create an integration

Integrations belong to a project and are created once. Names are unique in a project, so later calls fetch the same one with `get({ name })`:

```ts setup.ts
import { createClient } from '@finalai/agents/client';
import { finalGateway, oauth, secret } from '@finalai/agents/integrations';

const client = createClient({ auth: { apiKey: process.env.FINAL_API_KEY! } });
const project = client.project({ id: process.env.FINAL_PROJECT_ID! });

// Each person signs in with their own Linear account.
const linear = await project.integrations.create({
  name: 'linear',
  mcp: { url: 'https://mcp.linear.app/mcp' },
  auth: oauth(),
});

// One token from a project secret, for everyone.
const github = await project.integrations.create({
  name: 'github',
  mcp: { url: 'https://api.githubcopilot.com/mcp/' },
  auth: secret('GITHUB_TOKEN'),
});

// Final's own tools and the services connected to the project.
const final = await project.integrations.create(
  finalGateway({ url: 'https://api.final.ai/v1/connectors/mcp' }),
);

console.log(linear.id, github.id, final.id);
```

Then provide it for the slot when you start work:

```ts
const issues = await project.integrations.get({ name: 'linear' });

await project.sessions.create({
  agent,
  provide: { harness, integrations: { issues } },
  message: 'File a bug: the export button does nothing on Safari.',
});
```

<ParamField path="name" type="string" required>
  Lowercase letters, digits, `.`, `_`, and `-`. Unique in the project.
</ParamField>

<ParamField path="mcp.url" type="string">
  The MCP server's HTTP endpoint. An integration needs at least one of `mcp`, `egress`, and `exit`. To serve tools from your own Final Cloud Function instead, see [custom integrations](/build/custom-integrations).
</ParamField>

<ParamField path="mcp.headers" type="Record<string, string>">
  Static, non-secret headers sent with each request. Put tokens in `auth`.
</ParamField>

<ParamField path="auth" type="IntegrationAuthInput" required>
  How calls authenticate. Build it with a helper from `@finalai/agents/integrations`:

  | Helper | Calls authenticate with |
  | --- | --- |
  | `oauth()` | Each person's own sign-in with the server's OAuth provider. Add `{ scopes }` to request specific scopes. |
  | `oauth({ credential: 'shared' })` | One sign-in that serves everyone in the project. |
  | `oauth({ server, client? })` | OAuth against a named authorization server (`{ issuer }`, or `{ authorizationEndpoint, tokenEndpoint }`), for a credential that is no MCP server; `client` is your project's own OAuth client. |
  | `browserSession({ signInUrl })` | A website session: the person signs in to the site in a browser Final runs, and requests to the integration's egress hosts carry its cookies. Use with `egress: { hosts, inject: { kind: 'header', header: 'cookie', format: 'raw' } }`. |
  | `secret('NAME', { header? })` | A [project secret](/operate/authentication#use-secrets-in-your-code), sent as `Authorization: Bearer <secret>` or in `header`. |
  | `platformIdentity(scopes)` | A short-lived signed assertion of the calling session, which your server [verifies](#verify-calls-from-final) against Final's published keys. |
  | `noAuth()` | Nothing. |

  An integration can also name a credential broker you run, `{ kind: 'broker', url, scopes }`: Final asks it for a credential with a platform identity assertion each time the integration is used.
</ParamField>

Secrets and tokens never reach the model or the harness. Integrations reach MCP servers over HTTP; servers that only run locally over stdio aren't supported.

`project.integrations.update({ id, ... })` changes an integration in place. Its ID stays the same, so every `provide` that names it picks up the change.

## Sign-in

A personal sign-in isn't a requirement, and the agent never handles it. The first time a call needs a person's sign-in, Final holds the call and raises a `sign_in` decision for that person. When they finish signing in, the held call continues. Each person signs in once per integration in a project, and Final refreshes their token after that.

In Final's web and mobile apps, the person sees a sign-in card in the chat. For a `browserSession` integration, the card opens a live view of a browser Final runs; the person signs in to the site there, then confirms on the card. To ask ahead of the first call, use `project.integrations.requestSignIn({ id, conversationId })`. In your own app, list the session's open decisions, start the person's sign-in, and send them to the authorization URL:

```ts
import { DecisionKind } from '@finalai/agents/client';

const session = client.sessions.attach(sessionId);
for (const decision of await session.decisions()) {
  if (decision.kind !== DecisionKind.SignIn || decision.request.signIn == null) continue;
  const { authorizationUrl } = await project.integrations.signIn({
    id: decision.request.signIn.integrationId,
    decisionId: decision.id,
    returnUrl: 'https://app.example.com/final/sign-in',
  });
  // Send the person to authorizationUrl.
}
```

The provider redirects back to `returnUrl` with `state` and `code`. Complete the sign-in as the same person, and the decision resolves (a browser sign-in, whose `signIn` response has `method: 'browser'`, completes with only its `state`):

```ts
await project.integrations.completeSignIn({ state, code });
```

For a browser sign-in (`method: 'browser'` on the `signIn` response), `authorizationUrl` is your own `returnUrl` with `state`. That page gets the live view for the person who is signed in, sends them to it, and completes the sign-in with only `state` once they've signed in to the site:

```ts
const { url } = await project.integrations.browserSignInView({ state });
// Send the person to url. It expires in minutes, and anyone holding it controls the sign-in browser: don't store or forward it.
await project.integrations.completeSignIn({ state });
```

`signIn`, `browserSignInView`, and `completeSignIn` act for the person the client is authenticated as. `project.integrations.signOut({ id })` forgets their sign-in.

A shared integration (`oauth({ credential: 'shared' })`) is signed in once for everyone. Use shared integrations for work no person is present for, such as [schedules](/build/schedules) and [channels](/build/channels).

## Call tools without a session

Your own code can use a project's integrations directly, without starting an agent: a nightly job that files issues, or a backend step that posts to Slack. The call goes through the same tool policy, approvals, sign-ins, and call records as an agent's. An API key calls as the project and acts for nobody. An app calls with a person's token and acts for that person, so their own sign-ins apply.

`project.integrations.listTools(integrationId)` lists the integration's tools and needs the `integrations:read` permission. `callTool` calls one and needs `integrations:call`:

```ts
import { IntegrationToolCallStatus } from '@finalai/agents/client';

const outcome = await project.integrations.callTool(integrationId, {
  name: 'create_issue',
  arguments: { title: 'Checkout fails on Safari' },
  callKey: 'triage-2026-11-13/create_issue',
  requirement: {
    description: 'Issue tracker',
    tools: { allow: ['create_issue'] },
    approvals: { create_issue: 'ask' },
  },
});

switch (outcome.status) {
  case IntegrationToolCallStatus.Completed:
    console.log(outcome.result); // The MCP tool result
    break;
  case IntegrationToolCallStatus.DecisionRequired:
    // Save outcome.decision.id; call again once it resolves.
    break;
  case IntegrationToolCallStatus.Failed:
    console.error(outcome.error.code, outcome.error.message);
    break;
}
```

| Field | What it does |
| --- | --- |
| `name`, `arguments` | The tool and its input. |
| `callKey` | Your key for this one logical call. A key that completed returns its recorded outcome and never runs the tool again; reusing it for a different call fails with `call_key_reused`. Keys are per caller, and per person for an app. |
| `requirement` | A [slot policy](#choose-which-tools-the-agent-gets) for this call: which tools it may use and which need approval. Without it, the integration's own policy applies. |
| `conversationId` | Where a person is asked, when the call needs an answer. |
| `decisionId` | The resolved decision a repeated call relies on. |
| `dryRun` | Check the call (exposure, approvals, credentials) without running the tool. |

### When a call needs a person

A call that needs an approval, a person's sign-in, or an answer to a question the tool asks returns `decision_required` with the decision's `id` and `kind` (`approval`, `sign_in`, or `input`). Nothing runs until it resolves. Then call again with the same `callKey` and the decision's ID:

```ts
const retried = await project.integrations.callTool(integrationId, {
  name: 'create_issue',
  arguments: { title: 'Checkout fails on Safari' },
  callKey: 'triage-2026-11-13/create_issue',
  decisionId,
});
```

Where the person is asked depends on the call:

- With `conversationId`, the decision is asked in that conversation, like an agent's.
- Without one, it's a [decision in the project](/client/decisions) for the person the caller acts for. They see it in Final's apps and answer it there or in your app.
- An API key with no `conversationId` acts for nobody, so a call that needs a person fails with `conversation_required`.

Watch for the answer with the `decision.resolved` [event](/operate/events), which names the decision's ID.

A call whose outcome is unknown, such as a timeout after the server received it, fails with `outcome_unknown`, and its key never runs the tool again. Check with the service whether the call went through before you use a new key.

## Final's gateway

`finalGateway({ url })` is an ordinary integration for Final's MCP gateway: the project's tasks, chats, agents, and search, plus the tools of every service connected under **Connectors**. It's the same set of tools the [MCP gateway](/mcp-gateway/overview) gives Claude Code or Codex. Pass the gateway's **Final MCP URL**, `https://api.final.ai/v1/connectors/mcp`. It authenticates with a platform identity assertion for the calling session, so it needs no token, and that assertion confines it to the session's own conversation and the chats linked from it.

```ts
require: {
  harness: { permissionMode: 'ask' },
  integrations: {
    final: { description: "Final's tools and the project's connected services", tools: { deny: ['create_agent_session'] } },
  },
},
```

Connected services can add many tools, so the agent searches for the ones it needs instead of seeing them all up front. An agent provided the gateway can also ask for an [optional requirement](/build/requirements#optional-requirements) it was started without.

## Verify calls from Final

An integration with `platformIdentity()` auth, or a credential broker, receives a short-lived signed assertion with every call: which organization, project, session, conversation, and person it's for. Verify it with `verifyPlatformIdentity` from `@finalai/agents/verify`, which runs on WebCrypto alone, in Node, Workers, Deno, or a browser:

```ts
import { PlatformIdentityVariant, verifyPlatformIdentity } from '@finalai/agents/verify';

const token = request.headers.get('authorization')?.replace(/^Bearer /, '') ?? '';
const result = await verifyPlatformIdentity({
  token,
  audience: 'https://mcp.example.com/mcp',
  variant: PlatformIdentityVariant.Integration,
  issuer: 'https://agent-session.final.ai',
  jwksUrl: 'https://agent-session.final.ai/.well-known/jwks.json',
});
if (!result.ok) return new Response(null, { status: 401 });
const { projectId, sessionId, userId, scopes } = result.claims;
```

`audience` is your server's own URL, the one the integration names, and the assertion must be for it. Read the IDs from the claims; don't parse `sub`. The scopes are the ones the integration was created with.

## Credentials for a sandbox's traffic

Some credentials belong to the machine rather than to an MCP server: a token for cloning private repositories, or for a package registry. An integration with `egress` holds one for a sandbox's outbound traffic. Final adds it to requests to the hosts you name, so the token is never on the machine and no other host ever sees it:

```ts
import { EgressHeaderFormat, EgressInjectKind, EgressPolicy } from '@finalai/agents/client';
import { secret } from '@finalai/agents/integrations';

// GITHUB_GIT_CREDENTIAL holds `x-access-token:<token>`, sent as HTTP Basic.
const git = await project.integrations.create({
  name: 'github-git',
  egress: {
    hosts: ['github.com'],
    inject: { kind: EgressInjectKind.Header, format: EgressHeaderFormat.Basic },
    policy: EgressPolicy.GitHub,
  },
  auth: secret('GITHUB_GIT_CREDENTIAL'),
});
```

| Field | What it does |
| --- | --- |
| `egress.hosts` | Hosts, or `*.` patterns, whose requests get the credential. |
| `egress.inject` | `{ kind: 'header', header?, format? }` sets a header, `authorization` by default, as `bearer` (the default), `basic` (a `user:password` credential), or `raw`. `{ kind: 'placeholder', env }` gives the machine placeholder values in the named environment variables, replaced with the real credential as requests leave. |
| `egress.policy` | A protocol-aware policy for the traffic: `git-smart-http` refuses tag pushes and lets a sandbox delete only branches it created; `github` adds GitHub's REST and GraphQL rules for refs. |

A [sandbox setup](/build/sandbox-setups) names an egress integration on each repository it clones, and that sandbox's traffic may use it from the first boot.
