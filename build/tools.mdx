A tool is a TypeScript function the agent can call, like "read the release status" or "publish the release." The model decides when to call it based on its description, Final calls your code, and the result goes back to the model. Write a tool when the agent needs live data or needs to act in your systems; for a service that already has an MCP server, use an [integration](/build/integrations) instead.

## In-process or serverless

Where a tool runs is decided by how you define it:

| | `defineServerlessTool` | `defineInProcessTool` |
| --- | --- | --- |
| Runs | On Final's runtime | In the process that created the session |
| Works when your process isn't running | Yes | No: it reports itself unavailable until the process is back |
| Can use | Its input, `ctx`, and runtime globals (`fetch`, `crypto`, `URL`, ...) | Anything that process holds: imports, a database connection, in-memory state |
| Its code | Part of the agent's document | Never leaves your process |
| Works for callers that only fetch the agent | Yes | No |

Use a serverless tool unless the tool needs something only your process has. An agent started by callers that don't hold your code, like Final's own chats or a teammate who fetched it by name, must use serverless tools. See [where code and compute run](/build/where-code-runs).

## Write a serverless tool

```ts tools.ts
import { defineServerlessTool } from '@finalai/agents';
import * as z from 'zod';

export const releaseStatus = defineServerlessTool({
  description: 'Get the CI, changelog, and sign-off status of a release.',
  inputSchema: z.object({ version: z.string().describe('Semantic version, like 1.2.0') }),
  outputSchema: z.object({
    version: z.string(),
    ciPassing: z.boolean(),
    changelogUpdated: z.boolean(),
    signedOff: z.boolean(),
  }),
  annotations: { readOnlyHint: true },
  execute: async ({ version }, ctx) => {
    const token = await ctx.secrets.get('RELEASE_SERVICE_TOKEN');
    if (token == null) throw new Error('The RELEASE_SERVICE_TOKEN secret is not set');
    const response = await fetch(`https://releases.example.com/api/releases/${version}`, {
      headers: { authorization: `Bearer ${token}` },
      signal: ctx.signal,
    });
    if (!response.ok) throw new Error(`Release service returned ${response.status}`);
    return await response.json();
  },
});
```

Then add it to the agent under the name the model sees, and list the secret it reads:

```ts
tools: { release_status: releaseStatus },
secrets: ['RELEASE_SERVICE_TOKEN'],
```

- **`description` and `inputSchema`** are what the model reads to decide when to call the tool and what to pass. Write them for the model: say what the tool returns, and describe each argument.
- **`outputSchema`** describes the result, so your own code can read it typed with [`toolResultFrom`](/build/hooks#react-to-a-specific-tools-result).
- **`ctx.secrets.get()`** reads a project secret listed in `secrets`, so the token never appears in your source. See [secrets](/operate/authentication#use-secrets-in-your-code).
- **`ctx.signal`** fires when the call is cancelled. Pass it to `fetch` so the request stops too.
- **Throwing an error** tells the agent the call failed, with your message. It can retry, try something else, or explain the problem.

### Keep it self-contained

The SDK captures the `execute` function's own source and puts it in the agent's document. It can use only its parameters, what it declares inside itself, and the runtime's globals. Move constants and helpers inside the function. If it uses something defined outside, making the document fails and names it:

```text
serverless tool release_status uses BASE_URL, which is defined outside it. Serverless code may use only its parameters, what it declares and the runtime's globals (fetch, crypto, URL, ...); move BASE_URL inside it, bundle the code and pass { source }, or define it in-process
```

The input arrives as the model sent it, checked against the input's JSON Schema. Schema transforms and defaults don't run, so validate inside the function if you rely on them.

### Use a library

A serverless tool can't import packages. To use one, bundle the tool into a single module that imports nothing, and pass its text as `source`:

```bash
npx esbuild release-tools.ts --bundle --format=esm --platform=browser --outfile=dist/release-tools.js
```

```ts
import { readFileSync } from 'node:fs';

export const releaseNotes = defineServerlessTool({
  description: 'Render the notes for a release as HTML.',
  inputSchema: z.object({ version: z.string() }),
  source: readFileSync(new URL('./dist/release-tools.js', import.meta.url), 'utf8'),
  export: 'releaseNotes',
});
```

`export` names the function in the module, `default` when you leave it out. It gets the same `(input, ctx)` arguments.

## Write an in-process tool

An in-process tool runs in the process that started the session, over that process's connection to Final, so it can use your app directly:

```ts
import { defineInProcessTool } from '@finalai/agents';
import * as z from 'zod';
import { db } from './db.js';

export const findOrder = defineInProcessTool({
  description: 'Look up an order by id.',
  inputSchema: z.object({ id: z.string() }),
  execute: async ({ id }) => db.orders.find(id),
  toModelOutput: (order) => (order == null ? 'No such order' : `${order.id}: ${order.status}`),
});
```

Its input is parsed with `inputSchema` before `execute` runs, so transforms and defaults apply. `toModelOutput` sends the model a shorter version of the result; your app and [hooks](/build/hooks) still see the full one.

When the process exits, the session carries on and the tool reports itself unavailable until a process holding the agent reconnects. A process that only fetched the agent by name doesn't hold the code, so starting the agent there fails with `code_unavailable`.

## Ask before a tool runs

Tools run without asking by default. For a tool that changes something, like publishing a release or sending an email, set `approval` so a person confirms each call first:

```ts
import { defineServerlessTool } from '@finalai/agents';
import { always } from '@finalai/agents/approval';
import * as z from 'zod';

export const publishRelease = defineServerlessTool({
  description: 'Publish a release to production.',
  inputSchema: z.object({ version: z.string() }),
  approval: always(),
  execute: async ({ version }, ctx) => {
    const token = await ctx.secrets.get('RELEASE_SERVICE_TOKEN');
    if (token == null) throw new Error('The RELEASE_SERVICE_TOKEN secret is not set');
    const response = await fetch(`https://releases.example.com/api/releases/${version}/publish`, {
      method: 'POST',
      headers: { authorization: `Bearer ${token}` },
      signal: ctx.signal,
    });
    if (!response.ok) throw new Error(`Publish failed with ${response.status}`);
    return { published: version };
  },
});
```

When the agent calls this tool, the turn pauses and Final creates a **decision** asking whether to allow it. The tool runs only after someone approves. Your app shows the request and sends the answer; see [handle approvals](/client/sessions#handle-approvals).

| Policy | When it asks |
| --- | --- |
| `never()`, or no `approval` | Never. The tool runs right away. |
| `always()` | Before every call. |
| `whenInput(predicate)` | When `predicate` returns `true` for the call's input. |

`whenInput` is useful when only some calls are risky. This one asks only for production deploys:

```ts
import { whenInput } from '@finalai/agents/approval';

const approval = whenInput<{ environment: 'staging' | 'production' }>(
  (input) => input.environment === 'production',
);
```

The predicate runs where its tool runs, so a serverless tool's predicate is self-contained too.

## Use the agent's sandbox from a tool

`ctx.sandbox(capability)` opens the sandbox the session was provided for a capability, from wherever the tool runs. This tool runs the test suite on the machine provided for `shell` and returns a short summary instead of the full log:

```ts
export const runTests = defineServerlessTool({
  description: 'Run the test suite and report whether it passed.',
  inputSchema: z.object({ filter: z.string().optional().describe('Only run matching tests') }),
  execute: async ({ filter }, ctx) => {
    const shell = await ctx.sandbox('shell');
    const result = await shell.run({
      command: 'npm',
      args: filter == null ? ['test'] : ['test', '--', filter],
      timeoutMs: 10 * 60_000,
      abortSignal: ctx.signal,
    });
    return {
      passed: result.exitCode === 0,
      output: result.stdout.slice(-4000) + result.stderr.slice(-2000),
    };
  },
});
```

The sandbox also has `readTextFile`, `writeTextFile`, `readDir`, `stat`, `removePath`, and `spawn` for long-running processes. `ctx.sandbox` throws if the session has no sandbox for that capability, so the agent should [require](/build/requirements#compute) it.

## Tool reference

<ParamField path="description" type="string" required>
  What the tool does and returns, written for the model.
</ParamField>

<ParamField path="inputSchema" type="Zod schema | JSON Schema" required>
  The arguments. Any Standard Schema library works, such as Zod, Valibot, or ArkType.
</ParamField>

<ParamField path="execute" type="(input, ctx) => result" required>
  Runs the tool and returns a value or a promise. For a serverless tool, pass `source` (and optionally `export`) instead.
</ParamField>

<ParamField path="outputSchema" type="Zod schema | JSON Schema">
  The shape of the result, so the agent and [`toolResultFrom`](/build/hooks#react-to-a-specific-tools-result) can rely on it.
</ParamField>

<ParamField path="approval" type="never() | always() | whenInput(fn)" default="never()">
  When to ask a person before the tool runs.
</ParamField>

<ParamField path="annotations" type="object">
  MCP hints about the tool: `title`, `readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint`.
</ParamField>

<ParamField path="toModelOutput" type="(output) => JSON value">
  In-process tools only. Replaces what the model sees with a shorter version of the result.
</ParamField>

The `ctx` argument is the same wherever the tool runs:

| Field | What it is |
| --- | --- |
| `ctx.secrets.get(name)` | Reads a project secret the agent lists in `secrets`. Returns `null` if it isn't set. |
| `ctx.signal` | Fires when the call is cancelled. |
| `ctx.progress(data, label?)` | Reports progress while the tool runs. |
| `ctx.sandbox(capability)` | Opens the sandbox provided for `files`, `shell`, `computerUse`, or `browserUse`. |
| `ctx.sessionId`, `ctx.callId`, `ctx.actingUserId` | The session, this call (matching the `toolCallId` in the session's events), and the person the turn acts for. |
