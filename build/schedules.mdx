---
title: "Schedules"
description: "Prompt an agent in a conversation on a timer: a weekday digest, an hourly check, or a one-time reminder."
---

A schedule is a timer in a [conversation](/client/conversations). Each time it fires, it hands one agent participant its prompt, and the agent's reply is posted in the conversation. Use schedules for recurring work nobody asks for each time: a morning summary of yesterday's releases, a weekly report, an hourly check.

A schedule isn't part of the agent's definition. It belongs to a conversation and one agent participant in it, and each firing runs with what that participant is provided there, so there's nothing separate to set up for runs. People and your app create schedules through the API, and an agent provided [Final's gateway](/build/integrations#finals-gateway) can create its own: asking it "every weekday at 9, summarize yesterday's releases" is enough.

## Create a schedule

Create the conversation with the agent and what it's provided, then add the schedule to it:

```ts schedule.ts
import { createClient, ScheduleDelivery, ScheduleTriggerType } from '@finalai/agents/client';
import { finalCredits, serverlessFinal } from '@finalai/agents/harnesses';

const client = createClient({ auth: { apiKey: process.env.FINAL_API_KEY! }, localCompute: false });
const project = client.project({ id: process.env.FINAL_PROJECT_ID! });

const agent = await project.agents.get({ name: 'release-digest' });
const releases = await project.integrations.get({ name: 'github' });

const chat = await project.conversations.create({
  kind: 'group',
  title: 'Release digest',
  actor: { externalId: 'release-team', displayName: 'Release team' },
  participants: [
    { user: 'usr_your_user_id' },
    {
      agent,
      provide: {
        harness: serverlessFinal({ model: 'deepseek-v4.1-flash', inference: finalCredits() }),
        integrations: { releases },
      },
    },
  ],
});

const digest = await chat.createSchedule({
  name: 'Weekday digest',
  prompt: 'Summarize the releases that shipped in the last 24 hours. List anything blocking the next release, with an owner for each item.',
  trigger: { type: ScheduleTriggerType.Cron, expression: '0 9 * * 1-5', timezone: 'America/Los_Angeles' },
  delivery: ScheduleDelivery.Always,
});
console.log(chat.id, digest.nextRunAt);
```

This runs at 9:00 a.m. Los Angeles time, Monday through Friday, in the conversation the script created, and the person you added reads each digest there in Final. `client.people.all()` lists your organization's members and their IDs. A conversation created with an API key belongs to one of your app's own users, the `actor`; a client signed in as a person creates it as that person.

Each firing acts for whoever created the schedule, and nobody is there to answer. Keep that in mind when you choose what the agent is provided:

- **Integrations** should use a project secret or a shared sign-in (`oauth({ credential: 'shared' })`), since there's no one to show a sign-in card to.
- **Compute** must be a specific sandbox, provided in the conversation. There's no calling process to lend its machine, and every firing uses that sandbox's disk.
- **Inference** should end with a source that doesn't need a person, like a project key or `finalCredits()`.

## Schedule options

<ParamField path="name" type="string" required>
  What the schedule is, as people see it in the conversation.
</ParamField>

<ParamField path="prompt" type="string" required>
  What the agent is asked each time the schedule fires.
</ParamField>

<ParamField path="trigger" type="{ type: 'cron', expression, timezone } | { type: 'once', at }" required>
  When it fires. A `cron` trigger takes a five-field expression (minute, hour, day of month, month, day of week) and an IANA time zone such as `Europe/Berlin`. A `once` trigger takes a future timestamp with `Z` or a UTC offset, and turns the schedule off after it fires.
</ParamField>

<ParamField path="delivery" type="'always' | 'if_needed'" required>
  `always` posts a reply on every firing, as a reminder should. `if_needed` lets the agent stay silent when it has nothing to report, which suits checks like "tell me if the build is red".
</ParamField>

<ParamField path="agentParticipantId" type="string">
  The agent participant the schedule belongs to. You can leave it out when the conversation has one agent.
</ParamField>

<ParamField path="enabled" type="boolean" default="true">
  Whether the schedule fires.
</ParamField>

## Run a schedule now

`runSchedule` fires a schedule immediately, which is handy for testing a new prompt. It returns as soon as the firing is handed to the agent:

```ts
const run = await chat.runSchedule({ scheduleId: digest.id });
console.log(run.conversationId, run.inputId);
```

The reply arrives in the conversation as the agent's message, captioned with the schedule.

## Pause, change, or delete a schedule

```ts
await chat.updateSchedule({ scheduleId: digest.id, enabled: false });
await chat.deleteSchedule({ scheduleId: digest.id });
```

`updateSchedule` also accepts `name`, `prompt`, `trigger`, and `delivery`. The schedule's agent, and the conversation's owners and admins, can change it. To change what runs get, change what the participant is provided with [`participants.provide`](/client/conversations#change-an-agents-settings).

`chat.schedules()` lists a conversation's schedules, and `project.schedules.list()` lists every schedule in a project's conversations, each with its `nextRunAt` and `lastRunAt`.
