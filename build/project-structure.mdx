An agent is one value made with `defineAgent`, exported from a module you choose. It lists every part explicitly: there's no folder convention to follow and nothing is discovered from file names. Import tools, hooks, and skills like any other code, and pass them in.

<Tree>

- release-assistant/
  - package.json
  - agent.ts
  - instructions.md
  - release-policy.md
  - skills/
    - triage/
      - SKILL.md
      - checklist.md
  - tools.ts
  - hooks.ts
  - run.ts

</Tree>

```ts agent.ts
import { defineAgent, markdown, skill } from '@finalai/agents';
import { audit } from './hooks.js';
import { releaseStatus, publishRelease } from './tools.js';

export const agent = defineAgent({
  name: 'Release Assistant',
  description: 'Checks whether a release is ready to ship and publishes it.',
  instructions: [
    markdown('./instructions.md', { from: import.meta.url }),
    markdown('./release-policy.md', { from: import.meta.url }),
  ],
  skills: [skill('./skills/triage', { from: import.meta.url })],
  tools: { release_status: releaseStatus, publish_release: publishRelease },
  hooks: { audit },
  secrets: ['RELEASE_SERVICE_TOKEN'],
  require: { harness: { permissionMode: 'ask' } },
});
```

Only `name`, `instructions`, and `require` are required. Lay out the other files however you like: one file per tool, or all of them in `agent.ts`.

## Text files beside the module

`markdown(path, { from: import.meta.url })` and `skill(path, { from: import.meta.url })` name text files relative to the module. Nothing is read when you call them; the files are read when the agent's document is made, which is when you start a session, publish, or print. Pass inline strings instead when that's simpler:

```ts
instructions: 'You help maintainers decide whether a release is ready to ship.',
```

`files(path, { from: import.meta.url })` names a directory, for the agent's `workspace` seed files. See [agent definition](/build/configuration).

## The agent's document

`final-agents print` writes the document Final stores for an agent, without calling anything:

```bash
npx final-agents print ./agent.ts
```

The module may export the agent under any name; pass `--export <name>` if it exports more than one. The document holds the instructions and skills as text, the requirements, each tool's name and input schema, and the source of each serverless tool and hook. It's stored by its content hash, so any change to these makes a new hash, while an in-process tool's body never leaves your process and never affects the hash.

In code, `documentOf(agent)` from `@finalai/agents` returns the same document.

## Code that runs on Final

[Serverless tools and hooks](/build/tools#in-process-or-serverless) run on Final's runtime from their own source, which the SDK captures. They can't import modules or use variables defined outside them: everything they use must be inside the function, a parameter, or a runtime global such as `fetch`, `crypto`, or `URL`. `print` fails and names anything a serverless function reaches outside itself.

In-process tools and hooks run in the process that created the session and can import anything. See [where code and compute run](/build/where-code-runs).

## Run your scripts

The examples run TypeScript with `tsx`, which also resolves the `.js` import specifiers TypeScript uses for local files:

```bash
npm install --save-dev tsx
npx tsx run.ts
```

`final-agents print` and `publish` import your agent module with Node. If the module imports other local TypeScript files, load it through tsx:

```bash
NODE_OPTIONS='--import tsx' npx final-agents print ./agent.ts
```

## Several agents in one repository

Export each agent from its own module, or several from one module, and pass the one you mean:

```bash
npx final-agents publish ./agents/release.ts --name release-assistant
npx final-agents publish ./agents/triage.ts --name triage-bot
```
